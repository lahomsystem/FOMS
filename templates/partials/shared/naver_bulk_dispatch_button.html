{# 네이버 일괄 발송처리 실행 버튼 + 확인 + **결과 추적** (NAVER-BULKDISPATCH-02). **두 화면(워크벤치·실측 대시보드)이 이 파셜 하나를 include 한다.** 되돌릴 수 없는 조작의 확인 문구와 요청 코드를 두 벌로 두면 한쪽만 고쳐지는 날이 온다. 1회차 운영(2026-08-31)에서 이 자리는 `window.alert` 로 "요청했습니다"만 말하고 사람이 직접 새로고침했다. 그런데 새로고침하면 대상이 0집이 되어 띠가 통째로 사라졌고, 발송이 됐는지 안 됐는지 화면으로 알 수 없었다. 그래서 지금은 **띠 안에서** 진행을 말하고, 결과 조회(`/bulk-dispatch/state`)를 몇 초 간격으로 읽어 "N집 발송 완료"까지 바꾼다. 배선 규율 3개: * **document 위임 + 싱글톤.** 이 화면들은 셸 프래그먼트로 갈아끼워진다 — `DOMContentLoaded` 에 매달면 스왑 진입에서 죽고, 매번 다시 바인딩하면 클릭이 여러 번 나간다(불가역 조작에서 치명적). * **버튼은 렌더 쪽이 판단한다.** 이 파셜은 버튼이 이미 그려져 있을 때만 동작한다 — v3 풀페이지처럼 스크립트가 통째로 빠지는 셸에서는 버튼 자체가 렌더되지 않는다. * **폴링은 스스로 끝난다.** 남은 대상이 0이 되거나 두 번 연속 같은 값이면 멈추고, 그래도 안 끝나면 최대 횟수에서 멈추면서 **끝나지 않았다고 말한다** — 조용히 멈춰 "완료"로 보이면 그게 1회차 결함의 재생산이다. 변수: `bulk_dispatch` (문구의 집 수 재진술용). #}
