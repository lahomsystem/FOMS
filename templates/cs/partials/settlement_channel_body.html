{# 채널(네이버) 정산 탭 body (NAVER-SETTLE-01 §6). 정산 대시보드 셸(`settlement_dashboard_body.html`)의 4번째 pane 안쪽만 채운다 — pane 자체와 `role`/`aria-*`/`hidden` 배선은 셸 소유라 여기서 건드리지 않는다. 셸은 이 include 를 `{% if can_view_channel_settlement %}` 로 감싼다(ADMIN·회계팀 전용, 판정 SSOT 는 `foms/services/settlement_channel_access.py`). 서버에서 마크업째 빼는 이유는 이 저장소의 클라 숨김 금지 원칙이다 — 감추기만 하면 개발자 도구로 그대로 보인다. **이 파일은 빈 컨테이너 + 상태 노드만 낸다.** 값은 전부 `data-settlement-ch-api` 의 조회 API 를 fetch 로 읽어 채운다(초기 페이로드를 마크업에 심는 방식은 금지). 앵커가 서버 렌더 시점부터 있어야 fetch 가 실패해도 "빈 카드"가 아니라 "무엇이 비었는지"가 보인다 — 요약·실무 탭과 같은 규율이다. **이름 접두어(§0)**: 상태/훅 속성 `data-settlement-ch-*`, CSS 클래스 `.s-ch-*`, id `foms-settle-ch-*`. 세 탭이 **한 루트(`#foms-settlement-root`) 안**에 살고 요약 탭 JS 의 `collectEls()` 가 루트 전체를 `querySelector` 로 훑기 때문에, 접두어가 겹치면 서로의 노드를 잡는다(특히 상태 노드 — 숨은 pane 안에서 로딩/실패가 켜져 아무것도 안 보인다). **"예정" 이라는 낱말에 대하여**: 여기 쓰인 "정산 예정일" 은 네이버 정산 API 의 `settleExpectDate` 축을 가리키는 도메인 용어다. 요약/실무 탭이 금지하는 목업 잔재 "예정"(근거 데이터 없는 미구현 배지)과는 다른 것이라, 채널 표면만 별도 계약으로 본다 (`tests/domains/test_settlement_channel_render.py`). #}
{# ── S0 · 동기화 헤더 ──────────────────────────────────────────────────────── 네이버 API 는 워커 프로세스에서만 부를 수 있다. 이 줄은 "언제 받아온 값인가"와 [지금 동기화](enqueue)만 담당한다 — 버튼이 곧바로 수집하지 않는다는 사실은 JS 가 결과 문구로 말한다. #}
{# ── 기간·기준일 바 ────────────────────────────────────────────────────────── 요약/분석 탭의 `.s-filterbar` 는 이 탭에서 CSS 로 감춘다(기간 축이 다르다). 여기 셀렉트가 그대로 조회 API 파라미터(basis/from/to/granularity)가 된다. #}
