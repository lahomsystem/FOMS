# 생산·시공 단계 도면 — 도면팀 바로 고치기 · 사본 지우기 · 생산팀 알림 — SPEC (2026-10-27, 승인·구현)

## 배경
운영 주문 5690(생산 단계)의 도면 칸에 같은 도면이 두 장 있다. 하나는 "최종"(도면팀 전달 → 영업 수령 확정), 하나는 "직접 업로드"(같은 파일 `유진영1 (1).png` 을 첨부 칸에 따로 올린 사본)다. 영업이 지우려 했는데 지워지지 않았고, 도면팀은 지울 권한이 없다.

사용자 요구(2026-10-27): "도면도 생산단계 주문건에 대해 수정할 수 있어야 돼." 이어서 "생산단계에서 도면팀 또는 영업요청에 의한 도면팀 수정 건 발생 시 생산팀 전원이 알 수 있어야 돼."

## 지금 코드 (탐침 시험으로 확인, 생산 단계 + 도면 확정 주문)
- "최종" 도면: 첨부 삭제 API 가 모두에게 409 `DRAWING_IN_USE` 를 준다(관리자 포함, `foms/api/files/order_routes.py:710`). 하지만 목록의 `can_delete` 는 이 사실을 모르고 참을 줄 수 있어(`order_attachment_permissions.py:138`) 휴지통 버튼이 보인다. 실패 문구는 첨부 올리기 칸 밑(`erp_order_tab.html:572`)에 떠서 아래쪽 도면 카드에서 누르면 보이지 않는다.
- "직접 업로드" 사본: 지정 도면 담당·다른 도면팀 모두 삭제 403. 영업 담당은 200.
- 도면팀은 ERP 주문 화면(`/edit/<id>`)을 열 수 없다(`can_edit_erp` — 관리자·CS·영업만, `foms/web/orders/edit.py:253`). 도면 작업실의 [첨부 파일 열기] 링크도 그 화면으로 보내서 도면팀은 튕긴다. 작업실에는 사본 목록이 없다.
- 지정 도면 담당은 생산 단계에서도 작업실 [도면 전달]이 된다(200). 결과는 도면 상태 `TRANSFERRED` → 영업이 다시 수령 확정할 때까지 생산 [제작 시작]·[수정 제작]이 막힌다(`foms/api/production/orders.py:805`, `:1053`).
- 확정된 주문에 다시 보낼 때 기본 방식이 "추가"라, 고친 도면이 옛 도면을 바꾸지 않고 한 장 더 붙는다(탐침: 현재본 `final.png` + `s1.png` 두 장). 같은 마법사 시트면 제자리 교체되지만 그 밖은 쌓인다.
- 생산 단계 도면 재전달·수정 요청 알림(`foms/services/notifications/production_change.py`)은 CS·영업 팀에만 간다(`TARGET_TEAMS = ("CS", "SALES")`). 생산팀은 받지 않는다. 2026-08-05 에 생산팀 계정이 0명이라 일부러 뺐고, 시험(`tests/domains/test_production_change_notification.py:91`)이 "PRODUCTION 을 넣지 마라"를 지키고 있다.
- 생산 보드(PC·태블릿) 카드에는 생산 진입 뒤 도면 `TRANSFER` 가 "도면 재전달"로 빨갛게 뜨고, 사람마다 [확인]을 눌러야 꺼진다(`foms/services/production_change_alerts.py`).

## 운영 실측 (2026-10-27, 운영 DB 읽기 전용)
- 활성 계정: 시공 10 · 영업 11 · CS 3 · 도면 3 · 회계 2 · 관리자 1 · 협력사 2 · **생산팀 0**.
- 폰 알림(푸시) 구독: 영업 8 · 회계 1 뿐이다. 시공·도면·CS 는 0.
- 지금 생산 단계 주문 56건, 시공 단계 3건. 최근 180일 생산 동작 기록은 영업 관리자 한 사람이 [제작 시작]을 4번 누른 것이 전부다(생산 보드 [확인] 0번).
- 계정 만들기 화면의 팀 목록에 "생산팀"이 이미 있다(`foms/web/auth/routes.py:80`). 관리자가 생산팀 계정을 만들 수 있다.
- 결론: 코드만 바꾸면 생산팀에 보내도 받는 사람이 없다. **생산팀 사람마다 계정(팀 = 생산팀)을 만들고 폰 알림을 켜야** 실제로 닿는다.

1. 사본 지우기 = **도면팀 전원**.
2. 생산·시공 단계에서 도면팀이 고친 도면 = **영업 확인 없이 바로 최종**("핫픽스 해야 되는 경우도 있으니").

5. 생산 단계에서 도면팀이 고친 도면이 반영되면(도면팀이 스스로 고친 것, 영업 수정 요청에 답한 것 둘 다) = **생산팀 전원이 알아야 한다**.

## 변경

### A. 도면팀 사본 지우기
1. `can_delete_order_attachment`: 협력사 원본 규칙(관리자만) 다음에 "팀이 `DRAWING` 이고 첨부 분류가 `drawing` 이면 참"을 넣는다. 단계는 보지 않는다(도면 단계에서도 같은 일이 생긴다). 실측·시공·AS 사진은 그대로다.
   - 이 규칙은 삭제·되살리기에만 쓴다. `can_modify_order_attachment`(제품 연결 바꾸기)는 지금 규칙을 그대로 둔다 — 지금은 삭제 함수를 그대로 부르므로 옛 규칙을 따로 떼어 둔다.
2. "최종" 도면(`drawing_current_files` 에 든 key)은 `serialize_attachment` 가 `can_delete=False` 를 싣는다. 휴지통 버튼이 모두에게서 사라진다. 서버 409 는 그대로 둔다.
3. 도면 작업실 상세(PC)에 **"도면 칸에 따로 올라온 파일"** 카드를 넣는다.
   - 대상: 이 주문의 살아 있는 `category='drawing'` 첨부 중 최종 도면도, 교체된 옛 도면도 아닌 행(주문 화면의 "직접 업로드" 배지와 같은 집합).
   - 보여 줄 것: 썸네일, 파일 이름, 올린 사람, 올린 날짜, [보기], [지우기](`can_delete` 일 때만).
   - [지우기]는 기존 `DELETE /api/orders/<id>/attachments/<att_id>` 를 부른다. 확인 창 문구: "이 파일을 도면 칸에서 지웁니다. 최종 도면은 그대로 남습니다. 잘못 지웠으면 영업이나 관리자가 7일 안에 되살릴 수 있습니다." 성공·실패 문구는 카드 안에 띄운다.
   - 대상이 없으면 카드를 그리지 않는다.
4. 작업실 [첨부 파일 열기] 링크는 ERP 주문 화면을 열 수 있는 사람(`can_edit_erp`)에게만 보인다.

### B. 생산·시공 단계 = 도면팀이 보내면 바로 최종
1. `perform_drawing_transfer`(작업실 전달 창·태블릿 시트 전달·대시보드 전달 창이 함께 쓰는 처리)에서 주문 단계가 `PRODUCTION`·`CONSTRUCTION`(한글 `생산`·`시공` 포함)이면 **바로 반영**으로 처리한다.
   - 전달 이력에 `TRANSFER`(`hotfix: true` 표시)와 `CONFIRM_RECEIPT`(보낸 사람 이름, 메모 "생산·시공 단계 — 도면팀 바로 반영(영업 확인 생략)", `auto_confirm: "DRAWING_HOTFIX"`, 확정 파일 목록)를 차례로 남긴다.
   - 도면 상태 `CONFIRMED`, `drawing_confirmed_at`·`drawing_confirmed_by` 는 보낸 사람으로 채운다. 단계는 바꾸지 않는다.
   - `OrderEvent(DRAWING_STATUS_CHANGED)` 를 남긴다(이전 상태 → `CONFIRMED`, 사유 "도면팀 바로 반영"). 수령 확정 라우트와 같은 감사 흔적이다.
   - 영업 수정 요청(`RETURNED`)에 답한 수정본도 같다. 단, 미반영 요청이 있으면 보내지 못하는 지금 규칙은 그대로 둔다.
2. 알림: 영업 쪽 알림 제목 "도면 바로 반영됨", 본문 "주문 #N (고객) 도면팀이 고친 도면을 바로 반영했습니다. 확인할 필요 없습니다." 생산 변경 알림은 D 절을 따른다. 발주 PUSH "다시 보내야 함" 표시는 지금처럼 붙는다.
3. 응답 문구: "도면이 바로 반영되었습니다. 생산·시공 단계라 영업 확인 없이 최종 도면이 됩니다."
4. 바로 반영된 전달은 `TRANSFERRED` 를 거치지 않으므로 [전달 취소]로 되돌릴 수 없다. 잘못 보냈으면 다시 고쳐 보낸다(교체). 영업은 지금처럼 [수정 요청]을 낼 수 있다.
5. 도면·고객컨펌 단계, 시공 뒤 단계는 지금 흐름(영업 수령 확정 필요) 그대로다.

### C. 확정된 주문에 다시 보낼 때 기본 = 교체
1. 작업실 전달 창: 도면 상태가 `CONFIRMED` 이고 현재 도면이 있으면 기본 방식을 "교체"로 고르고, 도면이 한 장뿐이면 그 장을 미리 고른다. 생산·시공 단계면 창 위에 안내를 띄운다: "생산·시공 단계입니다. 보내면 영업 확인 없이 바로 최종 도면이 됩니다. 전달 취소로 되돌릴 수 없습니다."
2. 서버: 바로 반영 조건이고 방식이 비어 있으며(`mode` 없음·교체 대상 없음) 마법사 시트 교체도 없고 현재 도면이 한 장이면, 그 장을 교체한다. 두 장 이상이면 지금처럼 추가한다(태블릿 시트 전달은 방식을 고르지 않으므로 400 으로 막지 않는다). "추가"를 고르면 지금처럼 더한다.

### D. 생산팀 전원 알림
1. 생산 변경 알림 수신 팀에 생산팀을 넣는다: `TARGET_TEAMS = ("CS", "SALES", "PRODUCTION")`. 생산팀 활성 계정 전원이 벨 알림을 받고, 폰 알림을 켠 사람은 폰으로도 받는다(팀당 알림 한 줄 → `fan_out_new_notification` 이 그 팀 활성 계정마다 받은 표시를 만든다. 지금 쓰는 길 그대로).
   - 이 목록은 같은 모듈의 다른 생산 변경 알림(시공일 변경, 도면 수정 요청, 주문 취소)도 함께 쓴다. 그래서 생산팀은 그것들도 받게 된다. 영업이 생산 단계에서 [수정 요청]을 내면 생산팀이 "곧 도면이 바뀐다"를 먼저 알게 된다.
   - 대상 단계는 지금 규칙(`PROD_STAGES` = 고객컨펌·생산·시공)을 그대로 쓴다.
   - `test_target_teams_are_teams_that_actually_have_users` 의 "PRODUCTION 넣지 마라" 단언을 바꾼다: CS·영업이 계속 받으므로 생산팀이 0명이어도 무음 알림이 아니다. 새 단언 = "CS·SALES 가 늘 들어 있다" + "PRODUCTION 이 들어 있다".
2. 바로 반영(B) 때 생산 변경 알림은 종류를 새로 둔다(`kind="drawing_hotfix"`, 이름 "도면 바뀜").
   - 제목: "[생산] 도면 바뀜 — 고객명".
   - 본문, 도면팀이 스스로 고친 경우: "주문 #N — 도면 바뀜 (도면팀 OOO 이 고쳐 바로 최종 도면이 됐습니다. 새 도면으로 만들어 주세요)".
   - 본문, 영업 수정 요청에 답한 경우(직전 상태가 `RETURNED`): "주문 #N — 도면 바뀜 (영업 수정 요청을 도면팀 OOO 이 반영해 바로 최종 도면이 됐습니다. 새 도면으로 만들어 주세요)".
   - 이 알림은 60초 합치기를 하지 않는다. 같은 주문에 바로 앞서 온 알림(예: 영업 수정 요청)과 합쳐지면 폰 알림이 안 나가기 때문이다. 늘 새 알림이고 늘 폰 알림을 보낸다.
   - 바로 반영이 아닌 전달(도면·고객컨펌 단계)은 지금처럼 "도면 재전달"이다.
3. 생산 보드 카드의 변경 표시: 바로 반영 전달(`TRANSFER` 에 `hotfix: true`)은 "도면 재전달" 대신 **"도면 바뀜(바로 반영)"** 으로 보인다. 빨간 표시가 사람마다 [확인]을 눌러야 꺼지는 지금 방식 그대로다.
4. 받는 사람이 실제로 생기려면(운영 실측 참고) 관리자가 생산팀 사람마다 계정을 만들고(팀 = 생산팀), 각자 폰에서 알림을 켜야 한다. 이건 코드 밖 일이다. 계정이 생기기 전까지 생산팀 알림은 아무에게도 가지 않는다(CS·영업은 계속 받는다).

## 건드리지 않는 것
- 최종 도면 첨부 삭제 409(관리자 포함).
- 전달 권한 술어 `can_transfer_drawing`(결정 4).
- 모바일 v2 셸 작업실 화면(`workbench_mobile_handoff.html`) — 사본 카드는 PC 상세만. 필요하면 다음 차례.
- 작업실 목록에서 확정된 주문이 기본으로 빠지는 규칙(검색·"컨펌 포함"으로 찾는다).
- 운영 5690 데이터 — 코드 반영 뒤 도면팀·영업이 화면에서 사본을 지운다.

## 테스트 (새 파일 `tests/domains/test_drawing_production_hotfix.py`)
- 생산 단계 + 확정 주문, 지정 도면 담당이 전달 → 200, 도면 상태 `CONFIRMED`, 단계 `PRODUCTION` 그대로, 이력 끝 두 줄 `TRANSFER(hotfix)`·`CONFIRM_RECEIPT(auto)`, 현재 도면 한 장(교체), 생산 [제작 시작] 도면 게이트 통과.
- 시공 단계 같은 결과. 음성 대조: 도면·고객컨펌 단계는 지금처럼 `TRANSFERRED`.
- 현재 도면 두 장 + 방식 없음 → 지금처럼 추가(태블릿 회귀 방지). `mode=APPEND` 명시 → 추가.
- 생산 단계 `RETURNED` + 미반영 요청 → 400 그대로.
- 도면팀(담당 아님 포함)이 `drawing` 사본 삭제 → 200, 되살리기 → 200. 같은 사람이 실측 사진 삭제 → 403(음성 대조). 협력사 원본 → 403. 최종 도면 → 409.
- 목록 API: 최종 도면 `can_delete=False`, 사본은 도면팀에게 `True`.
- 작업실 상세: 사본 카드에 사본만 보이고 최종 도면은 안 보임, 도면팀에게 [첨부 파일 열기] 없음.
