## 2. 한 줄

표시 줄(`production_part_marks`, 도면 한 장 × 파트 하나에 한 줄)은 그대로 두고, 그 줄 안에 **맡은 사람 목록(JSON)** 을 더한다. 줄의 상태 칸은 "도면 한 장 · 그 파트가 완료됐나"의 요약으로 계속 쓴다 — 맡은 사람이 모두 [끝]이면 완료(DONE), 한 명이라도 아직이면 작업 필요(NEED). 그래서 제작 완료 · 검수 순서 · 공정 칸 동기화 · 공장 완료 판정(모두 상태 칸만 읽는다)은 한 줄도 안 바뀌고, 이름을 그리는 자리만 "여러 이름"을 배운다. 맡은 사람이 한 명이면 모든 화면 글이 지금 그대로다.

### 4-2. 추천 ⓒ — 까닭과 모양

**추천 ⓒ.** 생산 쿼리 가드 숫자를 하나도 안 늘리는 길이 이것뿐이고(ⓐ 는 상한 셋에 꽉 차거나 넘음), 표시 쓰기는 이미 주문 행 잠금으로 줄을 서서(표를 따로 뺀 까닭인 '여럿이 동시에 주문 JSON 을 다시 씀'과 다름) 줄 안 목록을 읽고-고치고-쓰는 것이 안전하다. 상태 칸을 요약으로 남기면 완료 판정 쪽 열두 자리(§3-7)가 그대로다. 목록은 사람 몇 명 × 80바이트라 PG TOAST 문턱(2KB)보다 훨씬 작다(주문 `structured_data` 의 TOAST 함정과 다름).

```json
"holders": [
  {"uid": 31, "name": "이시영", "at": "2026-11-24T23:10:00+00:00", "done_at": "2026-11-25T02:30:00+00:00", "done_uid": 31, "done_name": "이시영"},
  {"uid": 44, "name": "김재단", "at": "2026-11-25T00:02:00+00:00", "done_at": null, "done_uid": null, "done_name": null}
]
```

- `uid` · `name` = 맡은 사람(이름 스냅샷 — 지금 `*_by_name` 처럼 사용자가 지워져도 남음), `at` = 그 사람이 맡은 때(밤 넘김 · 아침 칩 — Q21), `done_*` = 그 사람 몫의 끝(대신 완료면 `done_uid` · `done_name` = 반장, Q15). 목록 차례 = 맡은 차례.
- **요약 칸 규칙(한 함수 `summarize(holders, state_hint)`)**: 목록이 비면 NONE(기본 · 직접 완료는 아래), 한 명이라도 끝이 아니면 NEED, 모두 끝이면 DONE. `picked_by_*` · `picked_at` = 목록 첫 사람, `done_by_*` · `done_at` = 가장 늦게 끝난 사람(NEED 면 비움 — 지금 "NEED 줄은 끝낸 사람 없음"과 같음). `handed_from_name` · `handed_at` = 마지막 담당 바꾸기 한 번(지금 뜻 그대로).
- **사람 없는 끝**: BASIC(재단 기본)과 풀어 쓰기 · 옛 줄의 DONE 은 목록이 빈 채 `done_by_*` 만 있다 — 지금과 같다.
- 쓰는 곳은 지금처럼 한 곳(`next_mark_values` → `flush_writes` / `_upsert_marks`) — `MARK_COLUMNS` 에 `holders` 가 들어가면 두 길이 저절로 같이 쓴다.

### 4-3. 읽기 정규화 · 되돌린 사이의 줄 (`crew_of(row)` 한 함수)

- `holders` 가 NULL(마이그레이션 전 줄 · 코드를 되돌린 사이 옛 코드가 쓴 줄)이면 요약 칸에서 푼다: NEED → `[담당]`, DONE + 담당 있음 → `[담당(끝 = done_by)]`, 그 밖 → `[]`.
- 목록이 있는데 `summarize(목록)` 의 (상태, 첫 사람 id, 끝낸 사람 id)가 줄의 요약 칸과 다르면 = 옛 코드가 마지막으로 쓴 줄 → **요약 칸이 이긴다**(위처럼 요약 칸에서 다시 풂). 그래서 되돌렸다 다시 올려도 상태가 거꾸로 가지 않는다.
- 모든 읽기(판 · 30초 · 날짜 줄 · PC · 경고 · 쓰기 판정)가 이 함수 하나만 쓴다.

## 5. 규칙 (C) — 사장님 답 그대로 + §6 추천값으로 채운 표

사장님 답에서 그대로 옮긴 것(바꾸지 않음):
- R1 같이 맡기 = 각자 [나도 자름]. 맡은 사람이 도면에 모두 보인다.
- R2 빠지기 = 자기만 [맡기 취소].
- R3 완료 = 맡은 사람 **모두** [끝]. 한 명이면 "재단 1/2 끝".

|---|---|---|---|---|

**풀이(답에서 바로 따름 — 틀리면 고침)**
- 같이 맡기는 "맡기"라 막힘 규칙이 take 와 같다: 보류 · 도면 고치는 중 · 남의 공장 · 손 체크 칸이면 막힘. 빼기 · 맡기 취소 · 되돌리기는 막힌 중에도 된다(지금 `ALLOWED_WHILE_BLOCKED` 와 같은 뜻).
- 검수 순서 · [제작 완료] · 공정 칸 · 공장 완료는 줄 상태로만 본다 → "1/2 끝" = 미완료(R3 이 그대로 퍼짐).
- 마지막 검수 장 "제작 완료할까요?"는 검수 줄이 DONE 이 되는 누름에서만(검수 1/2 끝이면 안 물음).
- 첫 맡기 = 제작 시작(11-23 B6)은 join 에도(회차 없는 옛 판 줄에 같이 맡을 때).
- 같이 맡기는 `[나도 {verb}]` — 재단 "나도 자름", 그 밖 "나도 엣지" · "나도 조립" · "나도 검수"(지금 `[내가 {verb}]` 꼴, `home_parts.html:19`).
- 통째 작업(공정 칸 손 작업) · 풀어 쓰기는 카드 0장 파트만이라 여러 명과 만나지 않는다(지금 그대로).

1. **"빠지고 싶으면 자기만 [맡기 취소]"** ↔ 지금 반장 · 관리자가 남의 장을 맡기 취소하는 길(`part_mark_rules.py:267-272` 관리자 덮어쓰기 · `parts-modal.js:70-71` 반장 고르기 [맡기 취소])과 승인된 [담당 바꾸기](11-23 B2 — 남을 빼고 내가 들어감). 답을 "동료끼리는 못 뺀다"로 읽고 반장 · 관리자 길은 남겼다(Q5 · Q8).

3. **"재단 1/2 끝"(사람 수)** ↔ 날짜 줄 · 작업 시트의 "재단 3/5"(도면 수, 11-23 §4-2). 같은 꼴이 다른 단위라 주문 단위 자리에는 안 쓴다(Q11).
