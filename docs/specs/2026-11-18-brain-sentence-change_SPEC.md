# 문장으로 고치기 — 바뀐 내용을 한 문장으로 넣으면 회사 지식 · 온톨로지를 고치고 따로 보고 (설계 판 1, 2026-11-18 · 결정 D246 ~ D249 승인)

사장님 말(11-17): "내가 문장으로 변경된 내용을 넣으면 자동으로 분석해서 온톨로지, 지식 변경 등 모든 관련 내용을 자동으로 할 수
있어야 될 것 같은데. 변경된 내용은 별도 보고하고."

계기: 같은 날 사장님이 승인 대기 화면을 보고 "도면 담당은 도면팀에서 자율적으로 해. 협력사 시공일도 출고 담당이 출고 스케줄 보고
조율해"라고 했다. 이 한 문장을 반영하려고 사람이 한 일은 (1) 밤 훑기 규칙 둘을 끄고 (2) 열린 제안 43개를 거두고 (3) 문서에 적은
것이다(원장 D245). 회사 지식에는 아직 이 사실이 없다. 문장 하나가 지식 항목 · 온톨로지 연결 · AI 직원 설정 세 곳에 걸려 있었다.

## 0. 한 줄

**입력 칸 하나 + 분석기 하나 + 묶음 보고 하나.** 고치는 길(제안 → 반영 → 판 → 되돌리기)은 이미 있는 것을 그대로 쓴다. 새로 만드는
것은 문장을 '고침 묶음'으로 바꾸는 앞단과, 그 묶음을 한 화면에서 보여 주고 한 번에 되돌리는 뒷단이다.

## 1. 지금 있는 것 · 없는 것 (11-18 코드 확인)

있는 것(그대로 쓴다):

- 고침 제안: `foms/services/brain/proposals.py` — `propose_create` · `propose_update` · `propose_retire` · `propose_link`
  (더하기 · 빼기) · `propose_rollback`. 제안한 이는 `Proposer`(사람 · 에이전트 · 옮기기).
- 반영 · 거절 · 한꺼번에: `apply.py` `apply_change` · `decide.py` `apply_decision` · `bulk_apply`. 판은 `BrainRelease`,
  판 화면은 `release_view.py`, 판 되돌리기는 `rollback.py` `rollback_release`.
- 계획을 한꺼번에 넣는 길: `plan_proposals.py` `file_plan`(모의 실행 = 저장점에서 되돌림 — 꼴 · 관문 · 겹침 검사가 넣을 때와
  같다) · `plan_labels.py`(다른 이름 · 규칙 → 제품 잇기).
- AI 부르기: `chat_model.py` `build_params`(JSON 틀 답) · `call_model`(하루 돈 상한 · 돈 줄 `brain_chat_spend`).
  가림: `foms/services/cs_agent/masking.py` `mask` · `require_masked`.
- 찾기: `read.py` `search` · `around.py` `search_around`(이웃) · 의미 찾기(Voyage — 운영에서 켜져 있음).
- 회사 지식 밖 설정 저장(감사 줄 포함): AI 직원 수준 표 `foms/services/ai_staff/levels.py` `save_levels`, 상담 AI 관리 칸
  `foms/services/cs_agent/settings.py` `save_settings`.

없는 것(이 설계가 만든다):

1. 문장을 받는 입력 칸과, 문장 → 고침 묶음(어느 항목을 어떻게) 분석기.
2. 문장 하나에서 나온 고침을 한데 묶는 번호. 지금 `BrainChange` 에는 묶음 칸이 없다(판 번호는 하루 단위).
3. 묶음 보고 화면 · 알림과 묶음 단위 되돌리기. 지금 '판 되돌리기'는 같은 날 다른 승인까지 같이 되돌린다(11-13 에 겪음).
4. 회사 지식 밖(수준 표 · 관리 칸)을 같은 묶음 안에서 고치는 길. 밤 훑기 규칙처럼 코드에 박힌 것은 설정으로 못 바꾼다.

## 2. 흐름

```
사장님 문장
  → ① 가림(손님 이름 · 전화 · 주소)
  → ② 관련 재료 모으기: 글자 찾기 + 의미 찾기 + 온톨로지 이웃 → 항목 20 ~ 30개(키 · 유형 · 글 · 걸린 연결)
                       + 바꿀 수 있는 설정 칸 목록(이름 · 지금 값 · 뜻)
  → ③ AI 한 번(JSON 틀): '고침 묶음' = 고칠 항목 · 새 항목 · 은퇴 · 연결 더하기/빼기 · 설정 고침
                                   · 코드를 고쳐야 하는 것 · 되물을 것
  → ④ 검사(코드): 있는 키인가 · 꼴 · 허용 짝 · 이미 같은 값 · 서로 맞섬 · 금액이 든 글 — 모의 실행으로
  → ⑤ 묶음 저장 + 제안 줄 만들기(묶음 번호를 단다)
  → ⑥ 반영(결정 1 에 따라: 미리 보기 뒤 한 번 누르기 / 바로)
  → ⑦ 보고: 묶음 화면(문장 · 고친 것 전 → 후 · 못 고친 것 · 코드가 필요한 것) + 알림 한 줄
  → ⑧ 되돌리기: 묶음 화면의 단추 하나 — 이 묶음이 고친 것만 되돌린다
```

- ③ 에서 AI 는 **고르기만** 한다. 반영은 코드가 ④ 검사를 통과한 것만, 이미 있는 반영 함수로 한다. AI 가 모르는 키 · 없는 유형 ·
  허용되지 않는 연결을 내면 그 줄은 빼고 보고에 '못 고친 것'으로 적는다.
- 문장이 모자라 정할 수 없으면(예: "가격 올렸어" — 무엇을 얼마로?) 고치지 않고 **되묻는다**(보고 화면에 물음 한 줄, 답을 적으면 같은
  묶음으로 다시 분석).
- 같은 뜻의 항목이 이미 여럿이면 가장 맞는 하나를 고치고 나머지는 '같이 볼 것'으로 보고에 적는다(자동으로 지우지 않는다).

## 3. 고침 묶음 꼴 (AI 답 · 저장)

```json
{
  "summary": "한 줄 요약(가린 글)",
  "updates":  [{"key": "<항목 키>", "after": {"<칸>": "<새 값>"}, "why": "…"}],
  "creates":  [{"type": "<유형>", "brand": "<브랜드|common>", "values": {…}, "why": "…"}],
  "retires":  [{"key": "<항목 키>", "why": "…"}],
  "links":    [{"op": "add|remove", "kind": "<연결 종류>", "from": "<키>", "to": "<키>", "why": "…"}],
  "settings": [{"area": "ai_staff_levels|cs_agent", "name": "<칸>", "value": <값>, "why": "…"}],
  "needs_code": ["코드를 고쳐야 반영되는 것 — 한 줄씩"],
  "questions":  ["정하려면 더 알아야 하는 것 — 한 줄씩"],
  "also_look":  ["<항목 키> — 같이 볼 것"]
}
```

- `settings` 는 **허용 목록에 있는 칸만**(코드가 정한 이름 · 값 범위). 처음 목록: AI 직원 수준 표(직원 · 할 일 · 0 ~ 2). 상담 AI
  관리 칸은 2판에서 칸마다 넣는다.
- 저장: 새 표 `brain_change_requests` 한 줄 — 번호 · 넣은 사람 · 가린 문장 · 묶음(JSON) · 상태(분석됨 · 반영됨 · 일부 반영 ·
  되돌림 · 버림) · 돈 · 걸린 시간 · 만든 때. `brain_changes` 에 `request_id` 칸 하나(없으면 빈 값 — 지금 줄은 그대로).
  설정 고침은 표에 전 → 후 값을 같이 적어 되돌릴 수 있게 한다.
- 원문은 저장하지 않는다. 가린 문장만(가림이 새면 저장 전에 멈춘다 — `require_masked`).

## 4. 화면 — 새 화면 하나, 입력 칸 하나

- **입력 칸**: 회사 지식 화면(`templates/brain/ds/inbox.html` — 승인 대기) 맨 위에 한 줄 칸 "바뀐 내용을 적어 주세요" + [분석]
  단추. 볼 수 있는 사람만(결정 2). 새 그림 · 요약 상자는 만들지 않는다.
- **묶음 화면**(`/brain/requests/<번호>`): 위에 넣은 문장, 아래에 고침 줄 목록 — 지금 승인 카드의 '전 → 후' 줄 그대로. 줄마다
  빼기 표시(미리 보기 때), 맨 아래 [이대로 고치기] · [버리기]. 반영 뒤에는 같은 화면이 **보고**가 된다: 고친 것 · 못 고친 것(까닭) ·
  코드를 고쳐야 하는 것 · 같이 볼 것, 그리고 [이 묶음 되돌리기].
- **목록**: 승인 대기 화면의 거르기에 '문장으로 고친 것' 하나(묶음 번호 · 날짜 · 한 줄 요약 · 상태).
- **알림**: 반영이 끝나면 넣은 사람에게 FOMS 안 알림 한 줄("문장으로 고치기 — N곳을 고쳤어요", 누르면 묶음 화면). 폰 알림은
  보내지 않는다(본인이 방금 한 일).
- 폰: 입력 칸과 묶음 화면 모두 폰 폭에서 한 줄씩 쌓인다(전 → 후는 위아래로).

## 5. 단계

| 판 | 무엇 | 코드 | 끝난 것으로 보는 기준 |
|---|---|---|---|
| 1 | 회사 지식 항목 · 연결 고침(고치기 · 만들기 · 은퇴 · 연결) + 묶음 화면 · 보고 · 묶음 되돌리기 | 새 표 1 · 칸 1(마이그레이션) · 분석기 · API 넷 · 화면 하나 · 입력 칸 | 문장 10개 시험 묶음(아래 7절)에서 사람이 본 정답과 같은 항목을 고름 8 이상 · 틀린 반영 0 |
| 2 | 설정 고침 — AI 직원 수준 표, 이어서 상담 AI 관리 칸 · '코드를 고쳐야 하는 것' 보고 | 허용 목록 · 저장 함수 잇기 · 되돌리기 | 11-17 문장("도면 담당은 도면팀에서 …")을 넣으면 수준 표 두 칸 0 + 지식 항목 고침이 한 묶음으로 나옴 |
| 3 | 모자란 재료 채우기와 잇기 — 능력 질문 화면의 '모자람' 줄에서 이 입력 칸으로(그 질문에 필요한 유형을 미리 알려 줌) | 화면 잇기 | 온톨로지 빈 재료 설계(2026-11-13) 2판 · 3판의 자료 넣기를 이 길로 할 수 있음 |

밤 훑기 규칙 같은 코드 상수는 어느 판에서도 자동으로 고치지 않는다 — 보고의 '코드를 고쳐야 하는 것'에 적고 사람이(Claude Code 가)
고친다.

## 6. 돈 · 시간

- 문장 하나에 AI 한 번(되물으면 한 번 더). Sonnet 기준 넣는 글 약 1만 ~ 2만 토큰 · 답 1천 ~ 2천 토큰 — 한 번에 몇십 원 ~ 백몇십 원
  어림. 돈 줄은 물어보기와 따로(`brain_change_spend`) 두고 하루 상한을 관리 칸으로(처음 값 2달러 · 비우면 꺼짐).
- 걸리는 시간 10 ~ 30초 어림 → 화면은 '분석 중'을 보이고 끝나면 묶음 화면으로 간다(WORKER 줄 일로 돌릴지 web 에서 바로 돌릴지는
  만들 때 실측으로 정한다 — 30초를 넘기면 줄 일).

## 7. 시험

- 코드 시험: 가림이 새면 멈춤 · 모르는 키 · 허용 밖 연결 · 허용 밖 설정 칸은 빼고 보고에 적음 · 같은 값이면 고침 0 · 묶음 되돌리기가
  그 묶음만 되돌림(같은 날 다른 승인은 그대로) · 볼 수 없는 사람은 404 · AI 답이 틀 밖이면 반영 0.
- 내용 시험(저장소 밖 학습 폴더 — 문장 10개와 사람이 고른 정답): 가격 · 정책 · 일 나눔 · 일정 규칙 · 제품 구성 · 금지 조합 ·
  용어 · AS · 배송 · 설정. 문장마다 '고른 항목이 맞나 · 빠뜨린 것 · 잘못 고친 것'을 표로 남긴다. 운영 글은 저장소에 넣지 않는다.
- 스테이징: 실제 화면에서 문장 넣기 → 미리 보기 → 반영 → 보고 → 되돌리기를 사람이 한 번씩.

## 8. 위험 · 막는 법

| 위험 | 막는 법 |
|---|---|
| AI 가 문장을 잘못 알아듣고 엉뚱한 항목을 고침 → 상담 AI 가 틀린 답 | 미리 보기(결정 1) · 줄마다 빼기 · 묶음 되돌리기 한 번 · 반영은 검사를 통과한 줄만 |
| 한 문장이 여러 곳을 한꺼번에 바꿔 무엇이 바뀌었는지 모름 | 묶음 번호 · 보고 화면 · 알림 · 감사 줄(지금 반영 함수의 감사 줄에 묶음 번호) |
| 손님 이름 · 전화가 문장에 섞여 바깥(AI 회사)으로 나감 | 가림 뒤에만 보냄 · 새면 멈춤 · 원문 저장 안 함 |
| '같이 못 함'(excludes) 같은 연결을 잘못 이으면 "안 돼요" 오답(D203 은 한 장씩 승인) | 이 길에서도 `requires` · `excludes` 줄은 미리 보기에서 따로 표시하고, 바로 반영(결정 1 의 다른 안)을 골라도 이 둘은 늘 한 번 누르게 |
| 금액이 든 글 | 금액 칸은 지금 관문(가격 규칙은 계산기 가리키기 — D179)을 그대로 지난다. 금액 숫자를 글에 넣는 고침은 '못 고친 것'으로 |
| 하루에 많이 넣어 돈이 샘 | 따로 돈 줄 · 하루 상한 |

## 9. 사장님 결정 (11-18 질문 창 — 원장 `docs/plans/2026-10-27-cs-ai-agent-ledger.md` D246 ~ D249)

- **D246 반영 방식**: 미리 보기 뒤 [이대로 고치기] 한 번. (다른 안: 바로 반영하고 보고 · 쉬운 것만 바로)

  그대로(`apply.check_permission`) — 넣은 사람이 반영할 수 없는 줄은 승인 대기에 남는다. 설정 고침은 관리자만.
  (다른 안: 사장님 · 관리자만)
- **D248 첫 판 범위**: AI 직원 설정(수준 표)까지 한 번에. 5절 표의 1판 · 2판 가운데 수준 표를 1판으로 당긴다(상담 AI 관리 칸은
  2판 그대로). (다른 안: 회사 지식 · 온톨로지부터)
- **D249 입력 칸 자리**: 둘 다 — 승인 대기 화면 맨 위 한 줄 칸 + 물어보기 화면. 물어보기에서는 묻는 말과 고치는 말이 섞이지
  않게 **따로 누르는 단추**([바뀐 내용으로 넣기])로만 넘어간다(말투로 알아서 고치기로 넘기지 않는다). (다른 안: 승인 대기 화면만 ·
  물어보기만)

## 10. 하지 않는 것

- 주문 · 손님 · 일정 같은 ERP 자료를 문장으로 고치기(이 길은 회사 지식 · 온톨로지 · AI 설정만).
- 코드 상수(밤 훑기 규칙 · 계산식)를 자동으로 고치기.
- 승인 없이 손님에게 나가는 글(알림톡 서식 · 매크로)을 고치기 — 지식 항목만 고치고, 바깥 사본은 '같이 볼 것'으로 알린다.
- 원문 문장 저장.

## 11. 만들 것의 약속 (1판 — 일꾼이 서로 맞추는 기준)

저장(마이그레이션 하나 — 머리 `graft_00` 뒤):

- 표 `brain_change_requests`: `id` · `created_by`(사람 번호) · `layer_scope`(넣은 사람이 고칠 수 있는 층 — `all` 또는 층 이름) ·
  `masked_text`(가린 문장, 1,000자) · `bundle`(JSON — 3절 꼴 + 줄마다 검사 결과) · `status`
  (`analyzing` · `ready` · `asked` · `applied` · `partial` · `reverted` · `discarded` · `failed`) · `error_code` ·
  `cost_usd` · `latency_ms` · `created_at` · `decided_at`.
- `brain_changes.request_id`(빈 값 허용 · 색인) — 이 묶음이 만든 제안 줄. 설정 고침은 `bundle.settings[]` 에 전 → 후 값과
  반영 여부를 적는다(제안 줄을 만들지 않는다).

서비스(`foms/services/brain/` 새 파일들 — 파일마다 500줄 아래):

- `change_request.py` — `start(session, actor, text)`(가림 → 묶음 줄 `analyzing` → 분석 → `ready` 또는 `asked` · `failed`) ·
  `answer(session, actor, request_id, text)`(되물음에 답 — 같은 묶음 다시 분석) · `apply(session, actor, request_id, skip=[줄 번호])`
  (제안 줄 만들기 + 넣은 사람이 반영할 수 있는 줄 반영 + 설정 저장) · `discard` · `revert`(이 묶음이 반영한 것만 되돌림) ·
  `view(session, viewer, request_id)` · `list_page(session, viewer, page)`.
- `change_request_model.py` — 재료 모으기 · AI 부르기(JSON 틀 · 돈 줄 `brain_change_spend`) · 답 읽기. 시험은 가짜 AI 로.
- `change_request_check.py` — 줄마다 검사(있는 키 · 층 · 꼴 · 허용 짝 · 같은 값 · 맞섬 · 금액 글 · 허용 설정 칸).
- 누가 쓸 수 있나: `change_request.can_use(viewer)` — 새 회사 지식 화면이 켜진 사람 가운데 관리자 또는 층 승인자.

API(`/api/brain/change-requests` — 답 꼴 `{'success','data','error'}`):

| 길 | 무엇 |
|---|---|
| `POST /api/brain/change-requests` `{text}` | 분석 시작 → `{id, status}`(끝났으면 묶음 화면 값까지) |
| `GET /api/brain/change-requests/<id>` | 묶음 화면 값: 문장 · 상태 · 줄 목록(`kind` · `label` · `before` · `after` · `why` · `check` · `state` · `caution`) · 못 고친 것 · 코드가 필요한 것 · 같이 볼 것 · 물음 · 할 수 있는 일(`can_apply` · `can_revert`) |
| `POST …/<id>/answer` `{text}` | 되물음에 답 |
| `POST …/<id>/apply` `{skip: [줄 번호]}` | 이대로 고치기 |
| `POST …/<id>/discard` | 버리기 |
| `POST …/<id>/revert` | 이 묶음 되돌리기 |
| `GET /api/brain/change-requests?page=` | 목록 |

화면: `GET /brain/requests/<id>`(묶음 화면) · 승인 대기 화면 맨 위 입력 칸 · 물어보기 화면의 [바뀐 내용으로 넣기] 단추(입력한 글을
`POST /api/brain/change-requests` 로 보내고 묶음 화면으로 간다).

스위치: `FOMS_GRAFT_BRAIN_CHANGE_REQUEST`(사람별 — `graft_flags`, 새 회사 지식 화면 `brain_ui` 가 켜져 있어야 한다). 꺼져 있으면
입력 칸 · 단추 · API · 화면이 없다(404).

## 12. 만든 것 · 알아 둘 것 (11-18 — 스테이징 `6e9b3dbb`, 운영 전)

- **분석은 WORKER 줄 일이다**(6절의 '만들 때 실측으로 정한다'의 답): AI 열쇠(`ANTHROPIC_API_KEY`)는 운영 WORKER 에만 있고 web 에는
  없다(결정 C3-0). web 은 묶음 줄을 `analyzing` 으로 만들고 RQ `default` 줄에 일을 넣은 뒤 바로 돌아온다(스테이징 실측 172ms).
  줄 일(`run_brain_change_request_task` → `change_request_job.run_change_request`)이 분석해 `ready` · `asked` · `failed` 로 닫는다.
  같은 분석은 한 번만(잡은 표시), 다시 하기 0, 일 시간 상한 5분 · AI 한 번 60초, 10분 넘게 `analyzing` 이면 읽을 때 `stuck` 으로 닫는다.
  묶음 화면은 `analyzing` 동안 5초마다 다시 읽는다.
- **새로 만들 수 있는 유형**: 사실 · 정책 · 제작 조건(문서 id `cr<묶음>-<차례>`, 승인 칸은 반영한 사람 · 날). 제작 조건은 같은 묶음에
  걸 곳(`applies_to`)이 있어야 한다(외톨이 금지). 가격 규칙 · 사장님 결정 · 기준 답 문구는 이 길로 만들지 않는다.
- **고칠 수 있는 칸**: 이름 · 글 · 유효 시작 · 끝. 세부 칸(정책 갈래 · 조건 꼴 등)은 다음 판.
- **재료 상한**: 항목 24개 · 글 앞 400자 · 전체 1만 8천 자. 모델 · 생각 깊이는 물어보기 설정을 따르고 최대 출력 8,000.
- **권한**: 보기는 넣은 사람과 관리자, 이대로 고치기 · 답 · 버리기는 넣은 사람만, 되돌리기는 넣은 사람과 관리자. 되물음 답은 3번까지.
- **알림**: 반영 뒤 넣은 사람에게 FOMS 안 알림 한 줄(`BRAIN_CHANGE_REQUEST` — 수만, 폰 알림 없음), 누르면 묶음 화면.
- **스테이징 확인(11-18)**: 스위치를 QA 계정 둘에 켜고 실제 서버에서 입력 칸 · 목록 링크 · 물어보기 단추가 보임, 시작 → 줄 →
  WORKER → 5초 안에 `failed`(`not_ready:no_api_key` — 스테이징에는 열쇠가 없다) → 묶음 화면 · 목록 · 버리기까지. **진짜 AI 로는 아직
  한 번도 돌리지 않았다** — 고르는 정확도 · 돈 · 시간은 운영 WORKER 에서만 잴 수 있다(7절 '내용 시험'은 그때).
- **화면에 남은 흠**: 못 고친 연결 줄의 끝이 없는 지식이면 지식 주소(`common/…`)가 그대로 보인다.
- **이 일을 하다 찾은 것(따로 정할 것)**: 운영 물어보기(`/brain/ask`)도 web 에서 바로 AI 를 부르는데 web 에 열쇠가 없다 — 운영
  `brain_questions` 0줄. 열쇠가 없으면 `not_ready`(503)이고 질문 줄을 남기지 않는다.
