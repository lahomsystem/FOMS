## 1. 왜 바꾸나

사용자(운영 실장)가 아침에 폰으로 홈을 열어 묻는 것은 세 가지다.

1. 이번 달 어느 날에 일이 몰렸나 (시공 팀 배치, 실측 추가 여부)
2. 그날 돈이 얼마 나가나 (그날 시공 건 출고가 합)
3. 그날 막힌 것은 무엇인가 (오늘·내일 시공인데 출고 전)

지금 홈은 7일 띠 + "오늘의 현장" 한 줄 목록이다. 2026-10-14 운영 화면에서 확인한 문제:

- 목록 40건이 한 줄로 쭉 나오고 "시간미정"이 맨 위였다 — 시간 문자열 비교 버그.
  **이미 수정**: `_field_ops_sort_key` 가 `measurement_glance_time_key` 를 쓴다(이 SPEC 의 0단계).
- 실측 25건 전부 "준비완료" 칩 — 담당 배정 여부만 보는 칩이라 정보가 없다.
- 시공 11건 중 10건 "출고 미확인" — 미래 날짜에도 같은 빨간 칩이 붙어 경고가 소음이 됐다.
- "시공"이 한 카드에 두 번(왼쪽 글자 + 배지). 품목·금액·전화가 없다.
- 한 주만 보여 달 단위 쏠림이 안 보이고, 금액이 없다.

## 2. 사용자 결정 (2026-10-14)

- 출고가 합 = **그날 시공 건의 출고가 합**. 실측·AS 는 넣지 않는다.
- 그날 목록 순서 = **시공 먼저**, 그다음 실측, AS.

## 3. 화면

### 3.1 홈 상단: 월간 달력 (7일 띠 대체)

- 머리: `‹ 2026년 10월 ›` (지난달·다음달 이동).
- 요약 한 줄: 이번 달 출고가 합계(큰 글씨) + 실측 N · 시공 N · AS N.
- 요일 줄(일요일 시작, 일 빨강·토 파랑) + 날짜 칸 5~6주.
- 날짜 칸: 날짜 숫자(오늘은 채운 원) / ▲실측 수 / ■시공 수 / ●AS 수 / 출고가 합(예 `3,470만`).
  0 인 줄은 비운다. 지난 날은 흐리게. 공휴일 날짜는 빨강.
- 빨간 점: **오늘·내일** 시공 중 출고 전 단계가 있을 때만. 먼 날짜의 출고 전은 정상 상태라 표시하지 않는다.
- 범례 한 줄: 빨간 점 뜻 + "금액 = 그날 시공 출고가 합".
- 달 밖 날짜(앞뒤 달)는 숫자만 흐리게, 누를 수 없다.

### 3.2 오늘 요약 카드 (달력 아래)

`오늘 10월 14일 (수)` / `실측 25 · 시공 11 · AS 4` / `출고가 3,470만` + `출고 전 10` 칩 / [오늘 목록] 버튼.

### 3.3 날짜를 누르면: 그날 목록 시트

- 아래에서 올라오는 시트(`role="dialog"`). 닫기 = 위쪽 어두운 곳 누르기 / 닫기 버튼 / Esc.
- 머리: `‹ 10월 14일 (수) [오늘] ›` + `출고가 합계 3,470만 · 시공 11건`.
- 탭: 전체 · 시공 · 실측 · AS (건수 표시). 기존 `/erp/dashboard/field-ops` 를 그대로 쓴다.
- 목록: 종류 묶음(시공 → 실측 → AS) 안에서 시간 묶음(오전 → 오후 → 종일 → 시간 미정) 머리줄.
  - 시공 묶음 머리: `시공 11건` + `출고가 3,470만`. 오늘·내일이면 빨간 띠
    `출고 전 10건 — 오늘 시공인데 아직 출고 처리가 안 됐어요`.
- 카드: 시간 / 고객명 / 주소 / 품목 요약(시공·AS) · 담당 / 출고가(시공만) / 상태 칩 / 전화 버튼.
- 상태 칩은 **할 일이 있을 때만** 붙인다:
  - 시공: 오늘·내일이고 출고 전 단계 → `출고 전`(빨강). 잔금이 남았으면 `잔금 48만`(주황). 지난 날·그 밖은 칩 없음.
  - 실측: 담당 없음 → `담당 미배정`(주황). 그 밖은 칩 없음("준비완료" 삭제).
  - AS: 칩 없음(종류는 묶음 머리가 말한다).
- 카드 본문 누르기 = 모바일 주문 상세(기존 링크). 전화 버튼 = `tel:` 고객 번호(번호 없으면 버튼 숨김).

### 3.4 그대로 두는 것

위험 레이더, 처리 대기, 전체 파이프라인, + 버튼. "내 할 일" 토글은 기존 머리 토글을 그대로 쓰고,
바뀌면 달력과 열린 시트를 다시 읽는다(목업의 "전체/내 담당" 버튼은 이 기존 토글로 대신한다).

## 4. 데이터 규칙

- 모집단: 기존 타워와 같다 — `_tower_base_query`(최근 60일 활성 ERP 주문, 시공팀은 본인 담당).
  완료 후 60일이 지난 주문은 빠지므로 **지난달 이전**의 지난 날 숫자는 실제보다 적을 수 있다.
  이번 달 안의 지난 날은 31일 이내라 빠지지 않는다. 달 이동은 앞뒤 12개월로 제한한다.
- 날짜별 실측·시공·AS 수: 기존 `_week_strip` 의 4개 집계 쿼리를 날짜 목록만 넓혀 그대로 쓴다
  (`order_schedule_dates` 복수 일정 정본, 자가실측 4체크 완료 제외, AS = AS 상태 + `as_visit`).
- 출고가: `erp_shipping_price_from_structured`(정산 "예상 매출"·모바일 상세와 같은 식).
  산출 불가(None)는 금액에서 빠지고 건수에는 남는다.
  - 날짜 칸 금액: 그 날짜에 시공 일정이 걸린 주문들의 출고가 합.
  - 이달 합계: 이달 안에 시공 일정이 있는 주문을 **한 번씩만** 더한다(복수 시공일 주문이 이중으로 들어가지 않게).
    그래서 날짜 칸 합을 더한 값과 다를 수 있다(복수 시공일 주문이 있을 때만).
- 금액 표기: 만 원 단위 반올림, `3,470만` / `1억 2,300만`. 0 원이면 칸에 금액 줄을 비운다.
- 빨간 점·출고 전: 기존 술어(`erp_stage_code` 가 `_INSTALL_READY_CODES` 밖)를 오늘·내일에만 적용.
  이 술어 자체(단계 코드로 출고 여부를 보는 것)는 이번에 바꾸지 않는다 — 별도 확인 과제.
