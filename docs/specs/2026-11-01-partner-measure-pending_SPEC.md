# 협력사 주문 '실측 예정' · '도면 요청' 나누기 — 영발은 도면 요청 때만 (설계, 승인 대기)

작성 2026-11-01. 요청(사용자): "영발 PUSH 는 실측이 끝나고 도면팀이 작업할 데이터가 다 들어왔을 때 보내야 하는데(이후 고치더라도),
지금은 주문 입력 수준인데도 나간다." 앞선 결정을 바꾼다 — 2026-10-28(협력사 주문은 저장하면 바로 도면 단계,
`docs/specs/2026-10-19-partner-foms-mode_SPEC.md`) · 2026-10-29 결정 A(첫 저장 때 영발을 묻기,
`docs/specs/2026-10-29-partner-channel-push_SPEC.md` §4).

## 1. 운영에서 본 것 (2026-11-01, 읽기 전용)

- 협력사 주문 24건(전부 라운즈, 22건 정명근). **13건이 실측 전에 등록**됐다 — `partner_intake.measured_on` 이 등록일보다 뒤
  (#5889 · #5912~#5922 · #5931). 10-31 에는 40분 동안 11건을 한꺼번에 올렸다. 협력사는 상담 직후 고객 · 시공일 자리를
  잡으려고 미리 올린다 — 10-28 설계의 가정("협력사는 실측까지 하고 넘긴다")과 다르다.
- 영발을 보낸 22건 중 **14건은 빈 주문**(가로 치수 0칸, 속성 다섯 칸 모두 '상담', 사진 0장). 거의 다 저장한 그 분에 나갔다 —
  첫 저장 뒤 `window.confirm('…본사 영발방에도 지금 보낼까요?')`(`static/js/partner/partner-channel-push.js:119`)에서 확인.
- 24건 모두 저장 즉시 DRAWING · `measurement_completed=True`(`foms/services/partners/orders.py:191,211,216`) → 작업 큐 '도면'에
  섞이고 도면팀에 "도면 작업을 시작해 주세요" 알림이 간다(같은 파일 232행). 13건 모두 도면 담당 없음 · 보낸 도면 없음.
- 본사 주문 대조군: 10-01 뒤 영발 324건 중 302건이 실측 당일이나 그 뒤(실측 전 3건 · 실측일 없음 19건). 지금 치수 · 속성이 다 빈
  본사 주문은 0건.
- 속성 칸은 새 주문에서 '상담'으로 미리 채워진다(`templates/partner/partials/item_card.html:48`) → 빈 주문도 영발 글은 꽉 차 보인다.

## 2. 사람별로 필요한 것

- **협력사 담당자**: 고객을 일찍 등록하고 시공일 자리를 잡고 싶다. '영발'이라는 말을 모른다. 휴대폰에서 빨리 누른다.
  → 화면은 '영발'이 아니라 "실측을 했나요?"를 묻고, 실측 뒤에는 "도면 요청" 한 번이면 끝나야 한다.
- **도면팀**: 그릴 수 있는 주문(치수가 들어온 주문)만 큐 · 알림으로 받아야 한다.
- **영발방을 보는 영업 · 일정 담당**: 영발 = "그릴 준비가 끝났다"는 뜻이어야 한다.
- **출고 담당**: 희망 시공일은 실측 전이라도 일찍 알아야 한다 — 지금 희망 시공일 알림 · 달력 숫자는 단계와 상관없이 들어가므로
  (`foms/services/partners/schedule_request.py`, 시공 전 단계면 센다) 그대로 둔다.
- **CS**: 협력사 창구. 막힌 주문을 풀거나 직접 넘긴다.

## 3. 결정 (사용자 2026-11-01)

- A. **'실측 예정'은 둘 다로 가른다**: 협력사가 저장할 때 "실측을 마쳤나요?"(마침/아직)를 고르고, '마침'이어도 조건(B)이 모자라면
  서버가 '실측 예정'으로 저장하고 무엇이 빠졌는지 알린다.
- B. **도면 요청 조건 = 실측일(오늘이거나 그 전) + 제품마다 가로 치수 1칸 이상.** 사진 · 초안 도면은 조건이 아니다(사진이 필요 없는
  경우도 있다 — 사용자). 속성 '상담'은 그대로 받는다(본사도 미정이면 '상담').
- C. **이미 들어온 13건은 '실측 예정'으로 되돌린다.** 이미 나간 빈 영발 기록은 지우지 않는다.

## 4. 만들 것

1. **등록** (`create_partner_order`): 페이로드 `measured_done`(마침/아직). 마침 + 조건 충족이면 지금처럼 DRAWING ·
   `measurement_completed=True` · 도면팀 + CS 알림. 아니면 **MEASURE · 주관 CS · `measurement_completed=False`**(10-28 이전과 같은
   모양, 새 단계 코드 없음) · CS 알림 1건("실측 예정 등록 — 실측 11-13")만, 도면팀 알림 없음. 응답에 `stage` · `missing`(빠진 것).
2. **도면 요청** — 새 API `POST /api/partner/orders/<id>/request-drawing`(자기 회사 주문만, 협력사 문지기 · 쓰기 정책 · 쓰기 가드 목록에 올림).
   서버가 조건(B)을 다시 본다 → 모자라면 400 + `missing`. 맞으면 기존 전이 `COMPLETE_MEASUREMENT`(MEASURE→DRAWING,
   `foms/services/orders/order_transition_service.py:204`)로 옮기고, 주관 DRAWING · `measurement_completed=True` ·
   MEASURE quest 완료 + DRAWING quest(본사 "도면 단계로 넘기기"와 같은 quest 처리) · 도면팀 + CS 알림 · **영발 자동 1번**.
   영발 실패는 전이를 되돌리지 않고 "영발방 전송은 실패 — 주문 화면에서 다시 보내 주세요"(발주 자동 전송과 같은 방식).
   본사 CS 는 기존 "도면 단계로 넘기기"로 같은 일을 할 수 있다(협력사가 전화로 부탁할 때).
3. **영발 버튼 잠금** (`push_state`): 영발은 DRAWING 이후(= 도면 요청 뒤)에만 열린다. 그 전엔 회색 + "실측 끝 · 도면 요청을 누르면
   영발방으로 같이 갑니다". 서버도 409. **첫 저장 뒤 묻는 창은 없앤다**(`partner-channel-push.js:116-125`, `partner-portal.js:132`).
4. **앞서 빈 영발이 나간 주문**: 도면 요청 때 영발은 재전송이 된다 — 변경 메모 자동 "[실측 완료] 치수와 내용을 넣었습니다",
   글 첫 줄에 "[실측 완료]"를 붙여 영발방에서 앞의 빈 글과 구분한다.
5. **협력사 화면**: 새 주문에 "실측을 마쳤나요?" 두 단추(기본 없음 — 꼭 고른다). 주문 화면 아래 "실측 끝 · 도면 요청" 단추(MEASURE 일
   때만). 단계 이름 MEASURE = **"실측 예정"**(지금은 '접수 확인 중', `orders.py:42`), 목록 파이프라인(`order_list.py:26`)에 같은 칸.
   실측일이 지났는데 아직 실측 예정이면 목록 카드에 "실측 끝나면 도면 요청을 눌러 주세요" 한 줄.
6. **본사 작업 큐**: 실측 예정 협력사 주문 카드에 하늘색 칸 "협력사 실측 11-13"(희망 시공일 칸과 같은 줄,
   `templates/partials/shared/channel_mark.html`). 우리 실측 일정표 · 실측팀 화면에는 넣지 않는다(지금처럼 `schedule.measurement` 비움) —
   구현 때 실측 대시보드 · 하단 '실측' 배지에 섞이지 않는지 확인한다.
7. **13건 되돌리기**: 일회용 스크립트 `tools/ops/partner_premeasure_revert.py`(기본 미리 보기, `--apply` 때만 씀). 주문마다 조건을 다시 본다 —
   협력사 주문 · DRAWING · 보낸 도면 0 · 도면 담당 없음 · 가로 치수 0칸 · 실측일이 오늘 뒤. 맞으면 단계 강제 변경 경로
   (`apply_stage_override`, regress, 사유 "실측 전 등록 — 실측 예정으로")로 MEASURE, 주관 CS, `measurement_completed=False`,
   열린 DRAWING quest → MEASURE quest(OPEN). 운영 실행은 배포 뒤 `railway ssh -s web` 안에서, 미리 보기 목록을 대화에 보이고 실행한다.
   #5897(김서현 · 실측일 없음 · 빈 주문)은 다음 날 #5908(같은 고객, 내용 있음)과 겹쳐 보여 13건에서 빼고 CS 확인으로 남긴다.

## 5. 시험

- 등록: 마침 + 조건 충족 → DRAWING · 도면팀 알림 / 아직 → MEASURE · CS 알림만 / 마침인데 치수 없음 · 실측일 미래 → MEASURE + `missing`.
- 도면 요청: 조건 모자람 400 · 다른 회사 404 · 본사 직원 거부 · 맞으면 DRAWING + quest + 알림 + 영발 1번(채널톡은 가짜) ·
  앞서 영발 보낸 주문은 재전송 + "[실측 완료]" · 영발 실패해도 단계 유지.
- 영발 버튼: MEASURE 에서 409, DRAWING 에서 열림. 첫 저장 묻기 창 없음(정적 검사).
- 작업 큐 칩: 실측 예정 협력사 주문만 "협력사 실측" 칩, 본사 주문 · 도면 단계 협력사 주문엔 없음.
- 되돌리기 스크립트: 조건 하나라도 어긋나면 건너뜀(대조군: 도면 보낸 주문 · 치수 있는 주문), 미리 보기는 쓰지 않음.
- 스테이징: `CLAUDE-TEST-` 협력사 주문으로 등록(아직) → 도면 요청 → 영발방 1건, 작업 큐 휴대폰 · PC 화면.
