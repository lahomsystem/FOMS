## 1. 요청과 결정 (사용자, 2026-10-14)

- 금액에 따른 노랑·분홍은 **출고가 알약에만** 칠한다. 날짜 칸 바탕에는 **그날 날씨**(수도권)를 그린다.
- 1~12월 계절이 보이게 한다. 달마다 실제 사진을 머리띠로 쓴다.
- 날씨가 칸을 꽉 채우고 날짜끼리 **이음새 없이** 이어진다.
- 애플 최신 디자인 느낌으로 입체적으로 만든다.
- 날씨 그림은 5종이다: 맑음, 구름, **부슬비**, **장대비**, 눈.
  - 장대비: 빗방울이 많고 빠르다.
  - 부슬비: 속도는 느린 그대로, 빗방울은 적다.
  - 눈: 전보다 빨리 내린다.
- 움직임은 휴대폰 성능에 영향이 없을 때만 넣는다. 그래서 **오늘부터 7일만** 움직인다.
- 맑은 날 해는 기온 받침에 가리지 않게 조금 아래로 둔다.
- 옆 날짜 구름이 겹쳐 보이면 안 된다.

## 2. 화면 (목업 M3v2 그대로)

### 2.1 구조
- **머리띠**
  - 달마다 실제 사진 1장을 깔고, 글자가 읽히게 어두운 막을 한 겹 덮는다.
  - 머리띠에 들어가는 것: 월 이름, ‹ › 달 이동, 이 달 출고가 합계, 실측·시공·AS 합계 알약.
  - 사진 출처 한 줄을 반드시 작게 표시한다(CC BY-SA 조건).
- **달력 판**: 흰 유리 판(반투명·흐림)이고, 머리띠 아래에 살짝 겹친다.
- **주마다 날씨 띠 1개**: 모서리 24px, 그림자, 위쪽 옅은 광택.
  - 띠 바탕은 날짜마다 날씨 색을 가로 그라데이션으로 이어 붙인다(칸 가운데가 그 날 색).
  - 그 위에 칸마다 **날씨 그림 판**을 얹는다(§2.3).
- **날짜 칸** (현재 버튼 `data-foms-day-tile` 을 그대로 쓴다. 누르면 그날 목록 시트)
  - 왼쪽 위: 날짜. 일요일·공휴일은 빨강, 토요일은 파랑.
  - 오른쪽 위: 기온 작은 반투명 흰 받침(`25°`, 낮 최고기온).
  - 그 아래: 실측·시공·AS 건수. 글자에 옅은 흰 테두리를 둘러 어두운 장대비 띠에서도 읽히게 한다.
  - 맨 아래: 출고가 알약. 노랑·분홍 기준(회사 공통 설정)은 **알약 색**으로만 보인다.
  - 오늘: 띠 위에 뜬 유리 렌즈를 두고, 날짜를 빨간 원으로 표시한다.
  - 지난 날: 글자와 그림을 흐리게 한다.
- **범례**: 맑음·구름·부슬비·장대비·눈 칩 5개, 그리고 `2,500만+` `3,000만+` 알약.
- 빨간 점(오늘·내일 출고 전 시공), 시트, 달 이동, 내 담당 필터는 지금 동작을 그대로 둔다.

### 2.2 날씨가 없는 날
- 예보 범위(오늘~10일 뒤) 밖의 미래 날짜는 **그림 없이 옅은 회백색 띠**로 둔다. 평년값을 지어 넣지 않는다.
- 수집이 실패했거나 아직 자료가 없을 때도 같은 모습이다. 달력의 나머지는 그대로 동작한다(fail-open).

### 2.3 날씨 그림 규칙 (이음새 없애기)
- 그림 판은 **칸 폭의 2배**다. 제 칸을 가운데에 두고 양옆으로 반 칸씩 넘친다.
- 판의 양끝은 마스크로 서서히 투명해진다. 이렇게 해서 경계에 잘린 선이 생기지 않게 한다.
- 단단한 물체(해 원반, 구름, 빗방울, 눈 결정)는 **제 칸 안에만** 그린다. 옆으로 번지는 것은 빛(해 빛번짐, 햇살 줄기)뿐이다.
- 칸마다 제 그림이 옆 날짜의 번짐보다 위에 오게, 오른쪽 날짜부터 깐다.
- 물체는 오른쪽 위에 둔다. 해는 기온 받침 바로 아래에 둔다.
- 그림 모양과 색 값은 목업 생성기 `scratchpad/gen/wv_anim.py` 의 `DEFS`·`scene()`·`svg_band()` 를 정본으로 옮긴다. 옮길 때 저장소 안 파이썬 모듈 또는 Jinja 매크로로 둔다.

| 종류 | 띠 바탕(RGB) | 그림 |
|---|---|---|
| 맑음 | 255,236,176 | 해 원반(가운데 흰빛→주황) + 빛번짐 + 햇살 줄기 12개 + 빛 반사 2점 |
| 구름 | 214,221,232 | 앞 구름(그늘 포함) + 뒤 옅은 구름 |
| 부슬비 | 212,224,238 | 밝은 구름 + 작은 물방울 7개 |
| 장대비 | 176,190,212 | 먹구름 두 겹 + 길쭉한 빗줄기 27개(세 묶음) |
| 눈 | 198,216,246 | 흰 구름 + 6갈래 결정 3개 + 눈송이 7개 |

### 2.4 움직임
- 움직임은 위치·크기·투명도(`transform`·`opacity`)만 바꾼다. 색·흐림·배경 위치는 움직이지 않는다.

| 종류 | 움직임 |
|---|---|
| 맑음 | 햇살 48초에 한 바퀴 + 빛 5초 숨쉬기 + 반사 반짝 |
| 구름 | 앞·뒤 구름이 다른 속도로 몇 px씩 흐름 (9초·13초) |
| 부슬비 | 물방울 하나하나가 2.5~3초에 살랑이며 낙하 |
| 장대비 | 세 묶음이 번갈아 0.5초에 비스듬히 낙하 (묶음째 움직여 가볍게) |
| 눈 | 결정이 돌며 3.4초, 눈송이 2.4초에 낙하 |

- **오늘부터 6일 뒤까지 7칸만** 움직인다. 이 판정은 서버가 칸마다 `wx_live` 로 내려준다. 나머지 칸은 멈춘 그림이다.
- 휴대폰 '동작 줄이기'(`prefers-reduced-motion`)가 켜져 있으면 전부 멈춘다.
- 다크 모드는 그림을 그대로 두고, 띠 바탕만 어두운 색과 섞어 낮춘다(검은색과 55% 섞기). 범례 칩도 같이 맞춘다.

### 3.2 날씨 종류 판정 (서버 한 곳)
- **단기**: 그날 하루 시간별 값을 모아서 판정한다. 위 줄부터 먼저 맞는 것을 쓴다.
  1. `PTY` 에 눈(3) 또는 비/눈(2)이 있으면 → 눈
  2. 비(1)·소나기(4)가 있고, 하루 `PCP` 합 ≥ 20mm 이거나 한 시간 ≥ 7mm 이면 → 장대비
  3. 비(1)·소나기(4)가 있고 그보다 적으면 → 부슬비
  4. 비·눈이 없고 낮 시간(09~18시) `SKY` 가 4(흐림) 또는 3(구름많음)인 시간이 절반 이상이면 → 구름
  5. 나머지 → 맑음
- **중기**: 오전·오후 글 중 더 궂은 쪽을 쓴다.
  - "눈"이 들어가면 → 눈
  - "비"·"소나기"가 들어가면 → 부슬비. 중기예보에는 비의 양이 없어서 강도를 모르기 때문이다.
  - "흐림"·"구름많음" → 구름
  - 그 밖 → 맑음
- 판정 기준 숫자(20mm, 7mm, 절반)는 상수로 서비스 모듈 옆에 둔다.

### 3.4 언제 받아 오나 — 요청 경로에서는 절대 받지 않는다
- 추천: **SIDEFX 상시 루프에 주기 작업 하나 추가.**
  - 대상: `tools/ops/run_domain_side_effect_outbox.py` 의 `_run_loop`. 이미 `--expiry-scan-interval`·`--retention-scan-interval` 같은 주기 스캔이 있다.
  - 새 인자: `--weather-interval` (기본 3600 = 1시간마다, 0 = 끔). 기본값이 켜짐이라 `railway-domain-sidefx.toml` 은 고치지 않는다.
    키가 없으면 호출 없이 건너뛴다.
  - 단기예보 새 발표(02·05·08…시 + 10분)나 중기 새 발표(06·18시 + 30분) 뒤 처음 도는 회차에만 실제로 호출한다.
  - 호출은 타임아웃 5초, 재시도 없이 다음 회차를 기다린다. 실패는 경고 로그만 남기고 루프를 죽이지 않는다.
  - 감독자 없는 백그라운드 루프가 죽은 전례가 있다(정산 루프 함정). 그래서 try 범위 밖에 형 변환을 두지 않는다.
- 다른 길(비추천):
  - 매일 02시 cron(`tools/cron/nightly.py`)만 쓰면 하루 한 번이라 예보가 낡는다.
  - 요청할 때 받으면 홈 화면이 기상청 응답 속도에 묶인다.
- Railway SIDEFX 서비스에 `KMA_APIHUB_KEY` 를 넣는다. 스테이징 먼저, 운영은 사용자 명시 요청 때만 넣는다.

### 3.5 달력에 싣기

- 칸마다 다음 값을 싣는다.
  - `wx`: `"sun"|"cloud"|"drizzle"|"heavy"|"snow"|""`
  - `t_max`
  - `wx_live`: 오늘 ≤ 날짜 ≤ 오늘+6 이고 `wx` 가 있을 때만 참

- 이번 일에는 JS 가 필요 없다. 움직임은 CSS 만으로 한다. `mobile-tower.js` 는 287줄이라 300줄 래칫에 여유가 거의 없으니 건드리지 않는다.
- 페이지 크기:
  - 움직이는 7칸만 그림을 통째로 그린다(칸당 약 3KB).
  - 멈춘 칸은 `<symbol>` + `<use>` 로 재사용한다. `<use>` 안에서는 CSS 움직임이 사파리에서 불안정하므로 멈춘 칸에만 쓴다.

## 7. 결정이 필요한 것

1. **기상청 인증키**
   - 공공데이터포털(data.go.kr)에서 단기예보·중기예보(·지상관측) 활용 신청이 필요하다. 보통 바로 승인된다.
   - 발급은 사용자 계정으로 해야 한다.
2. **지난 날 날씨** — 셋 중 하나를 고른다.
   - (가) 실제 관측: 추가 API, 가장 정직하다.
   - (나) 그날 마지막 예보를 그대로 둔다: 추가 호출이 없다.
   - (다) 비운다.
   - 추천: (나)로 시작하고, 필요하면 (가)로 바꾼다.
3. **머리띠 사진 12장을 이번에 같이 넣을지**
   - 목업 사진은 Wikimedia Commons (CC BY-SA·CC0·PD)이다. 출처 줄 표시 조건이 있다.
   - 넣지 않으면 달마다 단색 머리띠로 둔다.
4. **나눠 내기**
   - 1차 = 화면(띠·그림·움직임, 날씨 자료 없으면 회백색) + 금액색 알약 이동
   - 2차 = 날씨 수집
   - 추천: 한 번에 하되 커밋을 둘로 나누기
