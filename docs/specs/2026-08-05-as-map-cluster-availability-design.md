# AS 지도 v2 — 겹침 클러스터 + 방문 가능시간 필터 설계 (2026-08-05, 승인 대기)

## 요청 원문
1. 원거리(줌아웃)에서 핀이 겹쳐 보일 때 → 첨부 이미지(`최승호 x2` 스타일)처럼 별도 표시
2. AS 건들에 평일/주말·가능 시간 표기 → 지도에서 필터링
   ("AS도면 탭"은 코드상 부재 — AS 대시보드의 AS도면은 **컬럼(체크박스)**뿐. 해석 확인 필요)

## 실사용자 페르소나 (계획 기준)
- **김실장 (CS·AS 배차 담당, PC)**: 미완료 55건에서 방문 동선을 짠다. 고객 제약("주말만", "평일 오전만")이
  지금은 as_log 자유 텍스트·연락처 특이사항에 묻혀 지도에서 안 보인다. 수도권 줌아웃하면 핀이 겹쳐
  이름이 잘려 못 읽는다(첨부 이미지 1). 원하는 것: "이번 주말 서쪽 갈 일 있는데 근처 주말 가능 건 뭐 있지?"를 10초 안에.
- **박팀장 (시공팀, 태블릿·모바일)**: 주말 시공 빈 슬롯에 AS 방문을 끼워 넣는다. 카드에서 가능시간이 한눈에 보여야 한다.

## 기능 1: 스크린 겹침 클러스터 (지도 JS 전용, 백엔드 무변경)

### 현상 (조사 확정)
현재 접기(`x2`)는 **같은 주소/좌표 그룹만** 동작(`duplicateKey` — meta/주소/좌표 6자리). 주소가 다른
인접 건(수도권 밀집)은 줌아웃 시 pill이 서로 겹쳐 잘린다(이미지 1).

### 설계 — 화면공간(px) 클러스터링
- `map-view-kakao.js` 단독 수정. 매 `zoom_changed`/`idle`에서:
  1. 마커를 `map.getProjection()`으로 컨테이너 px 좌표로 투영
  2. pill AABB(이름 8자 컷 폭 추정 + 여백 4px) 겹침을 그리드 버킷으로 판정, 겹치면 같은 클러스터로 union
  3. 클러스터 ≥2건: 대표 1개만 표시 + **기존 `xN` 배지·핑크 스타일 그대로 재사용**(학습비용 0, 이미지 2와 동일 룩)
  4. 클릭 → 기존 `openGroupPopup` 재사용: 건 목록(+상태 배지 추가)·행별 [상세]·[펼쳐 보기]=클러스터 bounds로 줌인
  5. 줌인으로 겹침 해소되면 자동 해체(기존 임계 로직과 같은 이벤트 훅)
- 기존 동일주소 그룹은 클러스터의 하위 단위로 흡수(대표끼리 다시 스크린 판정, 배지 수 = 총 건수 합).
- **route(동선) 모드는 클러스터 비활성** — 순번 핀·폴리라인과 충돌.
- 적용 범위: `/map_view` 공용 엔진이므로 실측·AS·generic 모두 혜택(동작 플래그로 켬, folium 폴백은 현행 유지).

### UX 디테일 (페르소나 검증)
- 대표 pill 이름 + `xN` — 김실장은 "저 동네 4건"만 알면 클릭한다. 이름 대신 숫자만 쓰는 원형 클러스터는
  기존 pill 문법과 이질적이라 배제.
- 팝업 목록 행에 상태색 점(접수/처리중) 추가 — 클러스터 안에서 우선순위 판단.
- 성능: 55~500 마커 × 그리드 버킷 O(n) — 프레임 저하 없음.

## 기능 2: 방문 가능시간 (평일/주말·시간대) 표기 + 지도 필터

### 데이터 (조사 확정: 스키마 전무, 신설 필요)
- 신설 canonical: `structured_data.schedule.as_visit.availability`
  ```json
  {"days": "any|weekday|weekend", "time": "any|am|pm|evening", "note": "짧은 메모(선택)"}
  ```
- 쓰기 경로: 실사용 경로인 `/api/update_order_field`에 `as_visit_availability` 필드 추가
  (structured_data 패턴 준수: deepcopy + flag_modified). 저장 시 as_log system 로그 1줄
  ("가능시간: 주말·오후") — 타임라인 이력 보존. cycle transition payload에도 미러(append-only 계보 유지).
- 조회 SQL: `schedule->as_visit->availability->>'days'` **등호 비교**(ILIKE 금지 규칙 준수).
  모집단이 status 3종 선행 축소라 인덱스 불요.

### 입력 UI (김실장 동선 = AS 탭에서 접수·통화 직후 기록)
- **PC 행**: AS방문일 셀 안에 date input 아래 미니 칩 줄. 칩 클릭 → 팝오버:
  - 요일 3버튼(무관/평일/주말) + 시간 4버튼(무관/오전/오후/저녁) + 메모 1줄 — 탭 2번이면 끝.
  - erp-pro.css 체계(인라인 스타일 금지), 기존 as_billing 팝오버 패턴 재사용.
- **모바일 v2 카드**: 방문 블록에 동일 칩(카드 상세 시트에서 편집).
- 실측 오전/오후 프리셋 선례(`erp_order_tab.html:299-318`)와 동일 문법.

### 표기
- AS 탭 PC 행·모바일 카드: `주말·오후` 형태 칩. 주말=강조색, 평일=중립, 무관=회색 (색 대비 AA 준수).
- 지도 마커 pill: 주말 가능 건에 작은 도트 표식(pill 우측) — 필터 안 켜도 훑어보며 인지.
- 지도 팝업 테이블에 "가능시간" 행 추가.

### 지도 필터 (as 모드 헤더)
- 기존 "분류(버킷)" 옆에 "가능시간" select 2개: 요일(전체/평일 가능/주말 가능) · 시간(전체/오전/오후/저녁).
- "평일 가능" = `days ∈ {any, weekday}` — **'무관' 건 포함**(제외하면 미기입 다수 초기엔 빈 지도가 되는 함정).
- **미기입 처리(핵심 페르소나 디테일)**: 기존 55건 전부 미기입에서 시작. 필터 결과 배지 옆에
  "미기입 N건 제외" 고지 — 조용한 누락 금지. 미기입만 모아보는 옵션(입력 독려 동선) 포함.
- 서버: `build_as_incomplete_map_query`에 availability 파라미터 추가(버킷과 동일 패턴), 탭 SSOT 원칙 유지.

### 비범위 (v2에서 안 함)
- as_log 자유 텍스트 소급 파싱(자동 추출) — 오탐 위험, 수동 입력이 정본.
- AS 외 도메인(실측/시공) 가능시간 확장.

## 구현 순서 제안 (T 목록, 승인 후 ledger화)
1. **F1 클러스터**: map-view-kakao.js 스크린 클러스터 + 그룹 팝업 확장 + ?v 범프 + 계약 테스트(JS 로직 함수 분리로 node 테스트 가능하면 추가, 아니면 스테이징 QA 절차) 
2. **F2-a 데이터·API**: availability 스키마 + field_update 확장 + as_log 로그 + 테스트
3. **F2-b AS 탭 UI**: PC 팝오버 + 모바일 카드 칩 + 표기
4. **F2-c 지도 필터**: 쿼리 파라미터 + 헤더 select + 마커 도트 + 팝업 행 + 미기입 고지
5. 스테이징 QA(두 페르소나 시나리오 재연) → 승인 → production 승격
