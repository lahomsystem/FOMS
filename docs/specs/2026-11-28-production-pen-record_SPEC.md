## 1. 한눈에

- **쓰는 사람**(계정 칸 '펜 기록 쓰기'를 켠 사람): 생산 첫 화면에서 도면 그림을 눌러 도면 보기를 열고 `[기록 쓰기]` → 펜으로 쓰고 `[저장]`.
- **저장하면**: 기록 원본(선 · 글 · 화살표)은 새 표에, 도면 + 기록을 합친 그림은 주문 첨부 '생산' 분류에 들어간다. 도면팀 원본은 그대로다.
- **보는 사람**: 기록이 있는 도면은 머리 줄에 `[생산 기록 | 원본]`이 생긴다. '생산 기록 먼저 보기'를 켠 사람은 생산 기록이, 나머지는 원본이 먼저 보인다. 누구나 눌러서 바꿔 볼 수 있다.
- **도면 카드**: 그림 위 작은 딱지 "생산 기록" 하나. 카드 높이는 그대로다.
- **스위치**: `FOMS_PRODUCTION_PEN_RECORD`(기본 꺼짐). 꺼져 있으면 화면 · 쿼리가 지금과 같고 API 는 404 다.

### 3-2. 기록 한 개의 꼴 (`objects` 배열의 항목)

위자드가 저장하는 꼴(조사 값: `static/js/drawing/wizard.js` `serializeObjCore`)과 칸 이름을 맞춘다 — 나중에 위자드 쪽에서 읽을 일이 생겨도 옮길 것이 없다.

| 종류 | 칸 |

| `pen` | `points`(x, y 번갈아) · `stroke` · `strokeWidth` · 형광펜이면 `opacity` 0.4 |

| `text` | `x` · `y` · `text`(40자) · `fill` · `fontSize` |

- 좌표는 **가로 1478 기준**(위자드의 논리 크기 1478×1040 — 조사 값)이고 세로는 그림 비율대로다. 그림이 어떤 크기로 보이든 같은 자리에 선다.
- 서버가 받는 값: 종류 셋만, 색은 `#e11d1d` · `#1c62d6` · `#000000` · 형광펜 `#ffd400` 만, 굵기는 3 · 5 · 9 · 형광펜 24 만. 개수 300개 · 한 선 2,000점 · 전체 400KB 를 넘으면 413 `NOTE_TOO_LARGE`.

### 3-3. 합친 그림 — 태블릿은 펜 기록만 보내고 서버가 얹는다

1. 태블릿: 펜 기록만 그린 **투명 PNG**(긴 변 = 원본 긴 변, 최대 2,956px)를 화면 밖 캔버스에서 만든다. 이 캔버스에는 도면 그림을 안 그리므로 잠기지 않는다. 글자도 태블릿이 그려 보내서 서버에 한글 글꼴이 필요 없다.
2. 서버: 저장소에서 원본 바이트를 읽고(작은 그림 길이 이미 하는 일 — `part_thumb.py:99-121`), **흰 바탕에 얹은 뒤**(투명 칸이 검정이 되는 함정 — `part_thumb.py:9-10`) 펜 기록 PNG 를 원본 크기로 맞춰 겹친다.
3. 결과를 `orders/<주문>/production/` 아래에 PNG 로 저장하고 `order_attachments` 한 줄을 만든다: `category='production'` · `file_type='image'` · `filename='도면2_생산기록.png'` · `user_id`=쓴 사람.
4. 같은 도면의 앞 그림은 지운 표시(`deleted_at`)로 돌린다.

### 3-4. 도면이 바뀌면 — "옛 기록은 따로 남김"

- 지금 확정 도면 목록은 `resolve_final_drawing_files(sd)`(`drawing_confirm_cleanup.py:93-110`)가 준다. 기록 줄의 `drawing_key` 가 이 목록에 없으면 **바뀌기 전 기록**이다. 도면을 바꾸는 길(재전달 · 바로 반영)에는 손대지 않는다.
- 새 도면: 기록 없음으로 시작한다. 같은 `sheet_id`(없으면 같은 번호)의 바뀌기 전 기록이 있으면 도면 보기 머리 줄에 알림 한 줄을 띄운다 — "도면이 바뀌었어요 · 앞 기록은 주문 첨부 '생산'에 있어요"(캔버스 '머리 줄 상태 넷'의 넷째).
- 바뀌기 전 그림은 주문 첨부 '생산' 분류에 그대로 있고, 목록에서 "생산 · 바뀌기 전"으로 보인다(§5-3).

## 8. API

새 파일 `foms/api/production/drawing_notes.py`(등록: `foms/api/production/__init__.py` · `foms/platform/blueprints.py`). 응답은 `{'success', 'data', 'error'}` 꼴, 글은 `message`.

| 길 | 하는 일 |
|---|---|
| `GET /api/production/drawing-notes?order_id=&drawing_key=` | 쓰기 화면을 열 때 한 번. `{note: {objects, base_w, base_h, version, by, at} 또는 null}`. 읽기 문 = 생산 첫 화면을 볼 수 있음(`can_view_production_home` — `home_access.py:63`) + 그 주문 읽기 범위 + key 가 지금 확정 도면 |
| `PUT /api/production/drawing-notes` | 저장. `multipart/form-data`: `payload`(JSON — `order_id` · `drawing_key` · `objects` · `base_w` · `base_h` · `seen_version`) + `ink`(투명 PNG). 한 tx: 문 → 주문 줄 잠금 → 버전 견줌 → 값 검사 → 합친 그림 저장 → 첨부 줄 → 기록 줄(+1) → 이벤트 → 커밋. `{note: {version, view_url, by, at}}` |
| `DELETE /api/production/drawing-notes` | 기록 지우기(`order_id` · `drawing_key` · `seen_version`). 기록 줄 삭제 + 첨부는 지운 표시. 화면에서는 "다 지우고 `[저장]`"이 이 길을 부른다 |

- **둘이 같이 고칠 때**: `seen_version`(연 순간의 버전, 새 기록이면 0)이 지금 값과 다르면 409 `NOTE_CHANGED`. 유일 제약에 걸린 동시 첫 저장도 같은 답으로 바꾼다.
- **감사 기록**: `order_events` — `PRODUCTION_DRAWING_NOTE_SAVED` · `PRODUCTION_DRAWING_NOTE_DELETED`(payload: `drawing_key` · `drawing_no` · `version` · 기록 개수 · `attachment_id`). 기록 원본은 이벤트에 안 싣는다.
- **쿼리**: 생산 첫 화면 +1(그 화면 주문들의 기록 줄을 `order_id IN (…)` 한 번 — 원본 `objects` 는 안 읽고 버전 · 쓴 사람 · 시각 · 첨부 key 만), 작업 시트 +1. 스위치가 꺼져 있으면 +0. 저장은 태블릿 한 번 누름에 원본 한 번 읽기 + 그림 한 번 쓰기다.
- **읽는 모듈**: `foms/services/production/drawing_notes_read.py`(새 파일). `part_board.py`(487줄) · `home.py`(496줄)는 꽉 찼으므로 부르는 줄만 넣는다.
- 새 쓰기 길이므로 인벤토리(감사 범위 · 쓰기 목록)를 다시 만든다(`python tools/harness/refresh_inventories.py` + 줄 번호만 밀리면 `*_scan.py` 직접).

### 9-1. 스위치

`FOMS_PRODUCTION_PEN_RECORD`(기본 꺼짐). 읽는 곳은 `foms/services/production/pen_record.py` 의 `enabled()` 하나(현장 알람의 `floor_alarm.enabled()` 와 같은 꼴). 꺼짐 = 도면 보기 · 카드 · 작업 시트 · 쿼리가 지금과 한 글자도 같고 API 셋은 404. 마이그레이션 · 계정 칸 · 첨부 분류는 스위치와 상관없이 올라간다(값이 없으면 보이는 것이 없다).

### 9-2. 이번에 안 만드는 것

자동 저장 · 임시 저장, 기록 여러 판 되돌려 보기, 도면 카드 작은 그림에 펜 기록 얹기, 작업 시트에서 쓰기, 시공 기사 화면에 보이기, 저장 알림(현장 알람), 압력, 치수선 도구, 손가락으로 쓰기.

### 9-3. 시험

- 서버: 문 넷(스위치 꺼짐 404 · 칸 꺼진 반장 403 · 다른 팀 403 · 켠 사람 200), 버전 견줌 409, 동시 첫 저장, 바뀐 도면 409, 그림 아닌 도면 400, 큰 기록 413, 저장 뒤 첨부 한 줄 + 앞 그림 지운 표시, 지우기, 바뀌기 전 판정, 이벤트 payload, 쿼리 수(꺼짐 +0 · 켬 +1).
- 합친 그림: 투명 PNG 를 얹은 결과가 원본 크기 · 흰 바탕인지, 빈 칸이 검정이 아닌지.
- 계정 칸: 추가 · 고치기 · 생산팀이 아니면 비움 · 바뀐 기록 글.
- 첨부 분류: 정규화 · 다른 팀이 '생산'으로 올리면 403 · 화면 글 지도.
- PG: 마이그레이션 왕복 + 유일 제약(`tests/postgres/`).
- 화면(Node): 펜 · 손가락 구분, 지우개, 되돌리기, 저장 잠김 · 풀림, 받아 오기 중 쓰기 화면 유지, 스위치 꺼짐일 때 머리 줄 · 아래 줄 그대로.
- 실화면: 1280×720 터치에서 도면이 화면의 몇 %인지, 카드 높이(기록 있음 = 없음), 글자 100 · 150%.

## 10. 사장님께 여쭐 것

1. **도면 보기의 파트 단추 자리.** 지금 아래 줄에 `[재단 시작]` 같은 큰 단추가 있습니다. (가) 보는 상태에서는 아래 줄을 그대로 두고 쓰는 상태에서만 숨긴다(권함 — 쓰기 화면은 캔버스 그대로 도면이 가장 큽니다) · (나) 머리 줄로 올려 작은 단추로 바꾼다(보는 상태도 도면이 커지지만 파트 단추가 작아집니다).
2. **작업 시트.** 1차는 보기만(딱지 + 먼저 보기)으로 하고 쓰기는 첫 화면 도면 보기에서만 해도 됩니까?(권함)
3. **관리자 계정.** 관리자도 칸을 켜야 쓸 수 있게 할지(권함 — "따로 정한 사람만" 그대로), 관리자는 칸 없이도 쓰게 할지.
4. **'생산' 분류에 손으로 올리기.** 주문 화면에서 '생산' 분류를 골라 사진을 직접 올리는 것을 생산팀 · 관리자에게만 허용해도 됩니까?(권함) 아예 막고 태블릿 저장으로만 들어오게 할 수도 있습니다.
5. **카드 작은 그림.** 1차는 원본 작은 그림 + 딱지입니다. 작은 그림에도 펜 기록이 보여야 합니까?
6. **손가락으로 쓰기.** 펜이 없거나 고장 났을 때를 위해 손가락으로도 쓰는 길을 둘지. 1차는 없습니다(손바닥이 닿아 선이 튀는 것을 막으려는 것).
7. **기록을 지웠을 때.** 주문 기록에 "생산 기록 지움" 한 줄만 남기고 그림은 지웁니다. 지운 그림도 첨부에 남겨야 합니까?
