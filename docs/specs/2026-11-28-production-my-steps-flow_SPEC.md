### 3-2. 날짜 탭 도면 보기 — 파트 직원
- 내가 담았거나 같이 작업하는 카드(지금 `c.mine_row` 가 참인 카드)는 판에서 **뺀다**. 칩 숫자 `전체 도면` 도 뺀 수다.
- 칩은 `전체 도면` · `완료` 둘(`내 작업` 칩만 없앰 — 10번 답). 내가 끝낸 카드는 `완료` 칩에 지금처럼 보인다.
- 남이 담은 카드는 그대로 보이고 [재단 같이 작업]이 있다(5번 답). 같이 작업을 누르면 그 카드도 빠져 '내 공정'으로 간다(19번 답).
- **빼는 자리 = 서버(권고)**. 까닭: ① 숫자(`counts`) · 200장 캡 · 빈 화면 글이 서버에서 한 번에 맞는다 ② 화면에서만 숨기면 숨은 카드가 200장 캡 자리를 먹는다 ③ 거르는 재료(`mine_row`)는 이미 만든다 — 쿼리 0.
- 화면 쪽 할 일: [재단 시작] · [같이 작업]이 성공하면 그 카드를 판에서 빼고 탭 숫자 +1, 알림 한 줄. 30초 받아 오기가 "내 것이 됐다 / 내 것이 아니게 됐다"(반장이 담당을 나에게 줌 · 내 것을 남에게 넘김)를 보면 그 날 장을 다시 받는다(지금 날 조각 `?view=day` 길 그대로 — 새 길 없음).
- 아침 칩 "어제부터 내 작업 N장 ›"(`home_parts.html:84-87`)의 [보기]는 '내 공정' 탭으로 간다(지금은 그 날 장의 `#pp-mine`).

### 3-3. 날짜 탭 도면 보기 — 반장 · 관리자
- 아무 카드도 안 빠진다(19번 답). 칩 `전체 도면` · `작업 중` · `완료` 는 지금 그대로.
- 미정 카드 단추: 재단 · 조립 `[기본][재단 시작]` 한 줄, 엣지 · 검수 `[엣지 시작]` 하나. `[<파트> 완료]` 는 카드에서 뺀다 → 카드 키를 두 줄에 맞추던 `pp-finrow` 가 없어져 **반장 카드 키 = 파트 직원 카드 키**.
- 남이 작업 중인 카드의 `[이름 작업 중 ›]` + `[재단 완료]`(대신 완료)는 지금 그대로다 — "시작해야 완료가 나온다"와 어긋나지 않는다(이미 시작된 카드다).

### 3-4. '내 공정' 탭 (`tab=mine`)
- 담는 것: ① 내 몫이 작업 중인 카드 전부(시공일과 무관, 같이 작업 포함) ② **오늘 내가 끝낸** 카드.
- 묶음: 시공일 날짜(가까운 날 먼저, 지난 날이 맨 위) → 그 안에 주문. 묶음 머리 글 "12/1 (월) 시공 · 2장" / "정하늘 #2101 · 2장". 날짜 글은 날짜 탭 장 제목과 같은 함수로 만든다(지방 상차 주문의 '상차' 표도 같은 꼴).
- 카드는 날짜 탭 카드와 **같은 조각 · 같은 키**(매크로 `pp_act` 그대로 → `[재단 시작 취소][재단 완료]`). 확인 창 · 알림 · 크게 보기 · 펜 기록 딱지 · 받아 오기도 같은 스크립트가 그대로 돈다(판 설정 `data-foms-parts-config` 를 같이 싣는다).
- [재단 완료] → 확인 → 카드가 아래 '오늘 끝낸 것'으로. [재단 시작 취소] → 지금처럼 확인 창("재단 시작을 취소할까요?") → 카드가 사라지고 날짜 탭 도면 보기로 돌아간다. **시안은 확인 창 없이 바로였다 — 지금 화면대로 확인 창을 둔다**(6번 답 "지금처럼").
- '오늘 끝낸 것': 맨 아래에 늘 펼침. 파트 직원에게 완료 취소 단추는 없다(지금 규칙 — 운영에 있는 "반장만 되돌리기"). '오늘' = KST(`get_today_kst`), 표시 줄의 완료 시각(UTC)을 KST 날짜로 바꿔 견준다. 자정이 지나면 비워진다.
- 여러 파트 계정(재단 · 엣지 둘 다): 파트를 섞어 한 화면에 보이고 카드 단추 글이 파트를 말한다([엣지 완료]). → §7 물을 것 6.
- 읽기: 날짜 탭이 이미 하는 표시 줄 읽기 한 번(`read_screen_marks` 와 같은 범위)을 그대로 쓰고 파이썬에서 "내 것"을 고른다. **새 색인 · 마이그레이션 없음**(사용자 id 로 표를 뒤지지 않는다 — 읽는 주문이 이미 화면의 생산 주문으로 좁혀져 있다). 쿼리 수 = 날짜 탭과 같다.
- 카드 수 캡: 200장(지금 판과 같은 값). 넘치면 넘친 수를 글로 알린다.

### 3-5. 도면 없는 주문 — '도면 없음' 카드 (가장 위험한 대목)
지금은 표시 표가 도면 key 없이는 한 줄도 못 담고(§2-4), 파트 계정은 주문 공정 API 가 잠겨 있다. 길이 둘이다.

| | 길 가 — 표시 표에 '주문 카드' 줄(**권고**) | 길 나 — 파트 계정에게 공정 API 를 열기 |
|---|---|---|
| 방법 | 도면이 0장인 생산 주문에 한해 약속된 key 한 개(`@order`)로 표시 줄을 쓴다 | 도면이 0장인 주문만 파트 계정도 `…/production/steps` 를 부르게 잠금을 푼다 |
| 담기(작업 중 · 담당 · 같이 작업 · 담당 바꾸기) | 지금 카드와 같은 코드 그대로 | **담을 곳이 없다** — 공정 칸은 끝/안 끝만 안다. 담당을 넣으려면 주문 JSON 을 고쳐야 하고, 그러면 누를 때마다 주문 버전이 올라 편집 화면이 409 로 깨진다(표시 표를 따로 둔 바로 그 까닭 — `models.py:576-578`) |
| 표 · 마이그레이션 | 없음(`drawing_key` 는 글 칸이라 그대로 들어간다) | 없음 |
| 고칠 곳 | key 검사(`part_mark_write.py:157`) · 공정 칸 맞추기("0장이면 안 건드림" → "0장 + 주문 카드 줄이 있으면 그 줄을 따른다") · 판(기다림 묶음 대신 카드) · 표시 줄 읽을 주문(`part_screen.py:26` 이 도면 있는 주문만 고른다) | 잠금 한 곳 + 담당을 넣을 새 저장 자리 |

- **권고 = 길 가.** 까닭 세 줄: ① 사장님 답은 "카드 한 장처럼 **담고** 끝냄"인데 담기(담당)는 표시 표만 담을 수 있다 ② 표 · 마이그레이션이 필요 없다 ③ 나중에 도면이 올라오면 이 줄은 저절로 "옛 key 줄"이 되어, 지금 **도면이 바뀌었을 때와 같은 규칙**(새 장은 미정, 공정 칸은 다시 꺼짐)이 그대로 돈다 — 새 규칙을 안 만든다. → 이 결과가 맞는지는 §7 물을 것 2.
- 주문 카드: 그림 자리에 "도면 없음" 글, 도면 번호 자리도 "도면 없음", 나머지 줄(고객 · 시공일 · 품목 · 다른 파트 한 줄)과 단추는 보통 카드와 같다(재단 `[기본][재단 시작]` 포함). 크게 보기 · 펜 기록 · [도면 수정 요청]은 없다.
- 쓰기 규칙: key `@order` 는 **지금 확정 도면이 0장일 때만** 받는다(1장 이상이면 409 `DRAWING_NOT_CURRENT` — 지금 코드 이름 그대로). 그 밖의 문(생산 단계 · 보류 · 공장 · 파트 권한 · 검수 앞 공정)은 보통 카드와 같다.
- 반장이 '남은 공정'에서 손으로 끝내는 지금 길(공정 API)은 그대로 둔다. 손으로 끝낸 파트는 주문 카드가 "재단 완료 · 박반장 / 작업 시트에서 완료"(지금 `hand` 칸 — `home_parts.html:39-40`)로 보인다.
- 새 모듈 `foms/services/production/order_card.py`(약속 key · "이 주문은 주문 카드인가" · 카드 재료). 표시 줄을 읽는 다른 곳(§8 목록)이 `@order` 줄을 만나도 깨지지 않는지는 **만들 때 하나씩 시험으로** 본다.

### 3-6. '작업 중' 탭 (`tab=crew`) — 반장 · 관리자 · 읽기 전용(태블릿 가로)
- 위: 파트 칩 `전체` · `재단` · `엣지` · `조립` · `검수`(주소 `?part=`). 2공장 그림이 켜진 관리자는 지금 공장 고르기가 그대로 붙는다.
- 사람 묶음: 그 파트에서 내 몫이 작업 중인 장을 가진 사람마다 한 묶음 — "김재단 · 재단 2장". 사람 순서 = 파트 순서(재단 → 검수) 안에서 이름순. 같이 작업하는 카드는 **두 사람 묶음에 모두** 보인다(→ §7 물을 것 6).
- 카드: 날짜 탭 반장 카드와 같은 조각 — `[김재단 작업 중 ›]`(누르면 지금 창 `[시작 취소][담당 바꾸기 ›][대신 완료]`) + `[재단 완료]`. 걷기에서 본 "칩 안에서는 담당 이름이 사라짐"이 여기서는 없다(묶음 머리 + 카드 칸 둘 다 이름).
- 미정(맨 아래 — 13 · 18번 답): 파트 칩 `전체` = 단추 넷 "재단 미정 2장 ›" …(누르면 그 파트 칩으로), 파트를 고르면 미정 카드가 펼쳐진다(시공일 순, 200장 캡). 미정 카드 단추 = 날짜 탭 반장 카드와 같다(§3-3).
- 읽기 전용(보기만 계정)은 같은 화면에 단추 없이(지금 `pb.writable` 거짓 꼴).
- 읽기: §3-4 와 같은 표시 줄 한 번. 쿼리 수 = `tab=parts` 와 같다.
- **지금 '남은 공정' 판이 하던 일이 어디로 가는가**

| 지금 '남은 공정'의 것 | 새 자리 |
|---|---|
| 공정마다 주문 한 줄 보기 | 날짜 탭의 주문 줄(지금 있음 — 공정 네 칸 + 담당 이름) |
| 도면 있는 주문의 "재단 3/5 · 2장 미완료" → 도면 판 이동 | '작업 중' 탭의 사람 묶음 · 미정 묶음에서 바로 |
| 도면 없는 주문의 [재단 완료] 한 번에 | 주문 카드(§3-5) — [재단 시작] → 창 안 "바로 완료" |
| 오른쪽 판의 [불량] · [보류] | 작업 시트(지금도 같은 단추가 있다 — 판이 시트 배선을 빌려 쓴다) |
| "곧 올 것"(앞 공정에 와 있는 주문) | **새 탭에는 없다** |
| 위 안내 "도면 마감 지난 집 n건" · 제작 대기 숫자 | **새 탭에는 없다**(날짜 탭 '도면·컨펌 기다림'에 집마다 마감이 보이긴 한다) |
| 탭 숫자 "남은 공정 N"(주문 수) | "작업 중 N"(장 수)로 뜻이 바뀐다 |

- 사라지는 것 둘("곧 올 것" · 위 안내 숫자)을 숨기지 않으려고 **권고: 태블릿 '작업 중' 탭 맨 아래에 작은 링크 [주문 줄로 보기 ›](지금 `tab=steps` 화면 그대로)를 둔다.** PC · 폰의 '남은 공정'은 손대지 않는다. → §7 물을 것 1.

### 3-7. 바로 완료
- 반장 · 관리자가 미정 카드의 [재단 시작]을 누르면 지금 창 "재단 시작할까요?"가 뜨고, 실행 단추 아래에 작은 글 단추 **"이미 끝난 작업이면 바로 완료"**(눌리는 자리 44px)가 있다. 누르면 지금 동작 `check` 를 그대로 부르고 창을 닫는다(두 번째 확인 창 없음 — 시안대로, 누름 수 2). 알림 = 지금 글 "재단 완료했어요".
- 파트 직원 창에는 이 글이 없다(서버도 `check` 를 반장 · 관리자에게만 받는다 — `part_marks.py:245`).
- 검수 마지막 장이면 지금처럼 "제작 완료할까요?" 창이 이어 뜬다(`modal.js:260-264`).

## 5. API · 쿼리

- **새 API 없음.** 쓰기는 지금 `POST /api/production/part-marks` 그대로(주문 카드는 `drawing_key: "@order"`). 읽기는 지금 화면 길에 탭 둘이 늘 뿐이다.
- 받아 오기 `GET /api/production/part-marks` 는 그대로. 주문 카드 줄도 같은 응답에 실린다(key 가 `@order`).
- 쿼리 수 계약(시험으로 못 박는다): 스위치 꺼짐 = 모든 탭이 지금과 같다 · `tab=mine` = 파트 계정 날짜 탭과 같다 · `tab=crew` = `tab=parts` 와 같다 · 날짜 탭은 +0(도면 없는 생산 주문이 표시 줄 읽기의 `IN` 목록에 더 들어갈 뿐이다).
- 마이그레이션 없음. alembic 머리는 `prodpen_01_pen_record` 그대로다.

## 6. 스위치 · 시험 · 래칫 · 나누기

### 6-1. 스위치 — 기본 꺼짐으로 올린다(권고)
`FOMS_PRODUCTION_MY_STEPS`(기본 꺼짐), 읽는 곳은 `foms/services/production/my_steps.py` 의 `enabled()` 하나, 템플릿 플래그 `flag_my_steps`(`screen_flags.production_template_flags()` 에 더함). 까닭: ① 탭 · 칩 · 단추가 한꺼번에 바뀌는 고침이고 공장이 날마다 쓰는 화면이다 ② 글을 박은 시험이 많다(§2-6) — 꺼짐 = 지금과 한 글자도 같다로 두면 옛 시험이 그대로 지킨다 ③ 스테이징 · 공장 태블릿에서 며칠 써 본 뒤 켤 수 있다. 값: 템플릿 · JS 에 갈래가 생긴다 — 운영에서 굳으면 옛 갈래를 지우는 정리 커밋을 따로 한다. → §7 물을 것 5.

### 6-2. 시험
- 서버: 탭 문(파트 계정 `mine` 열림 · `crew` 날짜로 / 반장 반대 / PC · 폰 날짜로) · 파트 계정 판에서 내 카드 빠짐과 숫자 · 남이 담은 카드 남음 · 내 공정 묶음 순서(날짜 → 주문) · 오늘 끝낸 것(어제 것 빠짐, KST 자정 경계) · 완료 취소 단추 없음 · 작업 중 사람 묶음 · 같이 작업 카드가 두 묶음에 · 미정 단추 넷 숫자 = 파트 고른 카드 수 · 200장 캡 글 · 쿼리 수 넷.
- 주문 카드: 도면 0장 + `@order` 받음 · 도면 1장 이상이면 409 · take · join · done · release · takeover · basic · check 한 바퀴 · 공정 칸 켜짐/꺼짐 · 뒤에 도면이 올라오면 옛 key 줄 규칙 · 반장이 손으로 끝낸 파트는 `hand` 칸 · 표시 줄을 읽는 곳마다 `@order` 줄을 줘도 안 깨짐(§8 목록).
- 화면(Node): 담으면 카드 빠짐 + 탭 숫자 +1 · 받아 오기가 "내 것 됨/아님"을 보면 그 날 장 다시 받기 · 바로 완료 글은 반장 설정에서만 · 바로 완료 = `check` 한 번 · 반장 미정 카드에 [완료] 없음.
- 템플릿: 스위치 꺼짐 = 탭 줄 · 칩 · 카드 단추가 바탕 커밋과 같다.
- 실화면(로컬 가짜 준비물, 1280×720 터치): 김재단 · 박엣지 · 박반장 · 관리자로 시안과 같은 걸음을 걷고 누름 수를 다시 잰다. 카드 키(도면 보기 = 내 공정 = 작업 중, 반장 재단 판 = 파트 직원 재단 판).

## 7. 사장님께 여쭐 것

시안의 '제가 정한 것' 20줄 가운데 답을 받은 것(④ 같이 작업도 빠짐 · ⑩ 미정 단추 넷 · ⑬ 반장은 안 빠짐)은 뺐다.

1. **태블릿 반장 화면의 지금 '남은 공정'.** '작업 중' 탭으로 바꾸면 "곧 올 것"(앞 공정에 와 있는 주문)과 위 안내(도면 마감 지난 집 · 제작 대기 숫자)는 새 탭에 없습니다. (가) '작업 중' 탭 맨 아래에 작은 [주문 줄로 보기 ›]를 두어 지금 화면을 그대로 열 수 있게 한다(권함) · (나) 태블릿에서는 아예 없앤다. PC 화면의 '남은 공정'은 어느 쪽이든 그대로 둡니다.
2. **도면 없이 끝낸 뒤 도면이 올라오면.** 김재단이 '도면 없음' 카드로 재단을 끝냈는데 나중에 도면팀이 도면을 올리면, 그 주문의 재단은 다시 미완료가 되고 새 도면 카드가 미정으로 나옵니다(지금 도면이 바뀌었을 때와 같은 규칙 — 권함). 끝낸 것을 그대로 완료로 두어야 합니까?
3. **탭 숫자의 뜻.** '내 공정 3' = 담아 놓고 아직 안 끝낸 장수, '작업 중 4' = 지금 누가 담아 작업 중인 장수로 하겠습니다(권함). 지금 "남은 공정 8"(주문 수)은 태블릿 탭에서 사라집니다.
4. **담은 뒤 알림 글.** 지금은 "재단 시작했어요"입니다. 카드가 화면에서 사라지므로 "재단 시작했어요 · 내 공정에 담았어요"로 하겠습니다(권함). 시안은 "내 공정에 담았어요."였습니다.
5. **올리는 방법.** 스위치를 꺼 둔 채 운영에 올리고, 공장 태블릿에서 며칠 켜 본 뒤 굳히겠습니다(권함). 한 번에 바꾸기를 바라시면 스위치 없이 만듭니다.
6. **같이 작업 · 여러 파트.** 김재단 · 오재단이 같이 작업하는 카드는 반장 '작업 중' 탭에서 두 사람 묶음에 모두 보입니다(권함). 재단 · 엣지를 둘 다 맡은 직원의 '내 공정'은 파트를 섞어 한 화면에 보입니다(권함).
7. **'오늘 끝낸 것'.** 접지 않고 '내 공정' 맨 아래에 늘 펼쳐 두고, 자정이 지나면 비웁니다. 끝낸 카드는 날짜 탭 도면 보기의 '완료' 칩에도 지금처럼 보입니다(권함).

**시안과 다르게 적은 것(알림)**
- [재단 시작 취소]는 시안에서 확인 창 없이 바로였지만, 지금 화면에 확인 창이 있어 그대로 둔다(6번 답).
- 시안에서 뺐던 재단 카드의 [기본] · [도면 수정 요청] 단추는 실제 화면에 그대로 있다.
- 같이 작업한 카드는 시안에서 한 사람이 끝내면 끝이었지만, 실제는 지금처럼 사람마다 자기 몫을 끝낸다("재단 1/2 완료").
- 반장 날짜 탭의 주문 줄 보기는 시안에 안 그렸지만 지금 그대로 있다.
- 검수 막힌 칸 글 · 확인 창 글 · 알림 글은 시안 글이 아니라 지금 화면 글을 쓴다(§4).

## 8. 확인하지 못한 것

- **표시 줄을 읽는 곳 전부를 열어 보지 않았다.** `ProductionPartMark` 를 읽는 파일은 23개다(grep): `foms/api/orders/status.py` · `foms/services/drawing_workbench_production.py` · `orders/drawing_factory.py` · `orders/drawing_fix_transfer.py` · `production/complete_move.py` · `home_step_panel.py` · `mark_crew.py` · `part_holders.py` · `part_marks_query.py` · `part_mark_bulk.py` · `part_mark_rules.py` · `part_progress.py` · `part_receivers.py` · `rework_sheets.py` · `step_expand.py` 등. 이 가운데 `@order` 줄을 만나면 숫자가 틀어지는 곳(예: "재단 0/1 · 1장 미완료" 세기, 제작 완료 판정, 수정 제작 고르기, 2공장 나누기)이 있는지는 만들 때 본다 — 길 가의 값이 여기서 커질 수 있다.
- '오늘 끝낸 것'에 넣을 카드의 주문이 그사이 제작 완료로 넘어가면(검수 마지막 장) 화면 행에 남아 있는지 — 날짜 탭에 '제작 완료' 줄이 있는 것으로 보아 남는다고 **추정**했다. 행 읽는 범위(`build_production_home`)를 끝까지 읽지 않았다.
- 화면에 든 생산 주문 수 · 표시 줄 수를 운영 숫자로 재지 않았다(파이썬에서 "내 것" 고르기의 값). 만들기 전에 읽기 전용으로 한 번 잰다.
- 파트 계정 판에서 내 카드를 서버에서 뺄 때 일괄 [남은 N장 모두 기본] 창 · 아침 칩 · 2공장 '다른 공장' 묶음이 어떻게 되는지 — 코드를 따라가 보지 않았다.
- `foms-production-parts-claim.js` · `-crew.js` 의 다시 그리기 규칙을 줄 단위로 읽지 않았다(템플릿 머리말의 "같이 고친다"만 확인).
- 읽기 전용 계정의 태블릿 화면을 걷기 일꾼이 걸어 본 적이 없다.
- 누름 수는 시안에서 센 값이다. 실제 화면 값은 만든 뒤 로컬에서 다시 잰다.
- 실행해 본 것은 없다. 경로:행은 읽은 그대로지만 다른 창이 그사이 고치면 밀린다.
