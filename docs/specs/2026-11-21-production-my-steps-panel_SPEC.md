## 0. 한 줄

태블릿 가로에서 '내 공정' 탭 줄을 누르면 오른쪽 판(목업 안 3)에 그 주문의 도면 그림 · 색 · 앞 공정 · 다음 공정 · 큰 [<공정> 끝] · [불량] · [보류] · "끝내면 다음은 ○○" 가 나온다. 쓰기는 **지금 있는 API 셋을 그대로** 쓰고, 판 자료는 첫 화면이 이미 읽은 행에서 만든다(쿼리 0개 더함). 세로 · 폰 · PC 는 지금 그대로다.

## 1. 왜 하나

- 목업(`docs/design/mockups/tablet-production-ui-alternatives.html:446-500` 안 3)은 줄 + 오른쪽 470px 판이 한 화면이다. 지금 구현(`templates/production/partials/home_steps.html:11-23`)은 줄마다 190×72 [재단 끝] 단추뿐이고, 도면 · 색 · 앞 공정 · 불량 · 보류를 보려면 작업 시트로 들어가야 한다.
- 목업 글(같은 파일 `:484-498`): "그 공정에 와 있는 주문만 줄로 보고, 큰 단추 하나로 넘겨요" · "[엣지 끝] 96px 하나 … 다음 사람 이름이 미리 보여요" · "[엣지 끝] = 공정 체크 POST 한 번. 보류 · 불량은 지금 시트 단추와 같은 API".

## 2. 지금 코드의 사실 (직접 확인)

**탭 · 누가 보나**
- 탭은 `?tab=steps`, 줄은 `production_home_step_queues(rows)`(`foms/web/production/home.py:171`). 화면 주인 = `can_view_production_home`(관리자 · CS · 영업 · 생산, 협력사 제외, `foms/services/production/home_access.py:21-27`).
- **파트 계정은 이 탭이 없다(D50)** — 탭 단추를 안 그리고(`templates/production/partials/home_body.html:16`, `hide_steps_tab` = `home.py:96`), `?tab=steps` 는 날짜로 돌린다(`home.py:62-66`). 그래서 판을 보는 사람 = 관리자 · CS · 영업 · **파트 없는** 생산팀.

**줄 자료(판도 여기서 만든다)**
- 행은 `build_production_home`(`foms/services/production_home_read_model.py:307-379`) — 쿼리 4회 + 제작 회차 id 1회(`:339`). 행마다 `structured_data` 통째(`foms/services/production_dashboard_display.py:222`) · 이름(`:223`) · 보류(`:228`) · 품목 글 `v3_product_label` · 첫 품목 치수 `v3_spec_display`(W×D×H, `:246-247` · 만드는 곳 `:64-89`) · 색 `v3_material`(`:248`, 첫 품목 `color`/`material`/`finish`, `:92-100`)이 이미 있다.
- 공정 4칸 `home_steps`(`{key, label, done, now}`, `production_home_read_model.py:53-69`), 줄 공정 = 첫 미완 공정(`:240-249`), 줄 순서 = 시공일 빠른 순(`:252-255`), 공정별 줄 · 곧 올 것(`:258-286`). 도면 장 수는 `resolve_final_drawing_files(sd)` 로 이미 센다(`:358`).
- 앞 공정의 "누가 · 몇 시"는 `sd.production.steps[].by_name` · `at`(UTC)에 있다 — 작업 시트가 "이름 · M/D HH:MM" 으로 그린다(`foms/services/production_sheet_view.py:139-151`, `:185-191`). 지금 첫 화면 행에는 이 글이 없다(`home_steps` 는 done 만).
- '제작 시작' 시각은 `ProductionRun.started_at`(`models.py` ProductionRun)에만 있고 누가 했는지는 없다. 첫 화면은 회차 **id 만** 읽는다(`foms/services/production_read_model.py:276-290`).
- **엣지 사양(목업 "엣지 동색 1T")은 ERP 에 칸이 없다.** 품목 칸은 `color` · `handle`(손잡이) · `internal` · `misc`(`foms/api/erp_order_draft.py:159-162`, `foms/api/wdcalculator/blueprint.py:51`). 손잡이는 `item.handle`(예 `templates/orders/partials/order_detail_mobile_v2.html:236`).

**도면 그림**
- 확정 도면 = `resolve_final_drawing_files(sd)`(`foms/services/drawing_confirm_cleanup.py:93-108`). 그림 · 파일 가르기 = 파일 이름 확장자(`production_sheet_view.py:34`, `:121-136`).
- 640 중간 그림 주소 = `mid_thumb_url(key)`(`foms/services/files/list_thumb.py:85-87`, 운영 #880). 없으면 이번만 원본으로 가고 워커가 만든다(2026-11-20 설계서 §10-2 ③). 한글 이름 key(`_png`)도 그림으로 친다(`list_thumb.py:90-`).
- 눌러 크게 보기 = 전역 `window.GlobalImageViewer.open(files, i)`(`templates/partials/shared/layout_scripts.html:387`), 작업 시트가 원본 주소 목록으로 연다(`static/js/production/foms-production-sheet-page.js:66-88`).

**쓰기 셋 — 모두 지금 있다**
- [<공정> 끝] = `POST /api/orders/<id>/production/steps {key, done:true}`(`foms/api/production/orders.py:1427-1507`). 권한 = 관리자 또는 CS · 영업 · 생산(`_production_steps_edit_required`), 파트 계정은 403(`:1442-1444`). 지금 줄 단추가 부른다(`static/js/production/foms-production-home.js:126-142`) — **확인 창 없이 바로 저장 → 페이지 새로고침**.
- [불량] = `POST …/production/defect {reason}`, 사유 넷 `_PRODUCTION_DEFECT_REASONS`(`orders.py:93`, `:1510-1599`). 작업 시트는 [불량 알리기] → 사유 칩 → 칩을 누르면 바로 저장(`foms-production-sheet-page.js:137-166`). 이 JS 는 루트 `[data-foms-prod-sheet-page]` 마다 묶고 셸 교체 때 다시 묶는다(`:194-214`) — 옆 시트도 카드 하나를 그 루트로 써서 재사용한다(`templates/production/partials/tablet_sheet.html:156-174`).
- [보류] = `POST …/production/hold {active, reason}`(`orders.py:1643-1715`). 화면 배선은 `tablet-domain-sheets.js` 의 `data-tablet-sheet-action="production-hold"` — 걸기는 사유 창(`FomsReasonSheet`), 풀기는 `window.confirm`(`static/js/foms/tablet-domain-sheets.js:216-271`). 이 파일의 클릭 문은 생산 첫 화면 안이면 기기와 상관없이 연다(`:646`). 지금 첫 화면은 '바뀐 것' 탭에서만 이 파일을 싣고(`home_body.html:44-47`), 사유 창 조각 · JS 는 싣지 않는다.

**확인 창 선례(D53)**
- 원장 `:518` **D53**(사용자, 11-13): "재단 · 엣지 · 조립 · 검수 등 체크 시 각 계정이 맡은 파트만 체크할 수 있고, 체크 시 확인하는 모달 띄워". 꼴 = 진짜 생산 보드 확인 창 `foms-prod-change-modal`(`templates/production/partials/home_parts_overlays.html:7-21`, 설계서 §15.6 '확인 창' 표 — "[재단 완료] | 재단 끝으로 바꿀까요? | 작업 필요 → 재단 끝 · 김재단 | #047857").

## 3. 동작 (제안)

### 3-1. 어디에 · 누구에게

- **문**: 판은 도면 카드와 같은 기기 문 — 모바일 v2 셸 + 터치(`_tablet_part_surface`, `home.py:53-59`) + 넓은 창(`wants_wide_viewport_surfaces`). 이 문 밖(PC 마우스 · 폰 · 세로 쿠키)은 판을 **아예 그리지 않는다**(원장 §29 "안 보이는 표면을 보내지 않는다").
- 보이기는 `(min-width: 992px) and (orientation: landscape) and (pointer: coarse)` 아래 `body.erp-mobile-v2-layout`(확인 창 CSS 와 같은 조건).
- 줄 [끝] 단추는 마크업에 남기고 판이 보일 때만 CSS 로 숨긴다 — 태블릿을 세로로 돌리면 판이 숨고 줄 [끝]이 다시 보인다(지금 그대로).
- 보는 사람 = 지금 이 탭을 보는 사람 그대로(관리자 · CS · 영업 · 파트 없는 생산). 누를 수 있는 사람도 지금 줄 [끝]과 같다(같은 API · 같은 권한). 파트 계정은 D50 으로 탭이 없어 판도 없다.

### 3-2. 배치 (1280×800 기준 목업 값)

```
제목 줄 73 (공용)
공정 탭 72 (재단 · 엣지 · 조립 · 검수 — 지금 그대로)
┌ 줄 칸 (남는 폭) ───────────────┬ 판 clamp(360px, 40%, 470px) ┐
│ 머리 글 (지금 '제작 대기 n건…' 을 이 칸으로) │ 이름 26/800 #번호 16           │
│ 줄 96px × n (번호 · 이름 · 시공일) │ 품목 · W×D×H 16                  │
│ 곧 올 것 (지금 그대로)          │ 그림 (남는 키를 모두, 최소 96)    │
│ ↕ 이 칸만 굴러간다             │ 색 / 앞 공정 / 다음 공정 표 16    │
│                                 │ [✓ 엣지 끝] 96 · 28/800 초록      │
│                                 │ [⚠ 불량] [Ⅱ 보류] 48 · 16/700    │
│                                 │ 끝내면 다음은 ○○ 15              │
└─────────────────────────────────┴───────────────────────────────┘
```

- 몸통 키 = 화면 키 − 제목 줄 − 공정 탭(`calc(100dvh / var(--foms-ui-zoom, 1) - var(--fph-bar-h) - 72px)`), 페이지는 안 굴러가고 **줄 칸만** 굴러간다 — 작업 시트 선례(설계서 §12.3 11-11 "페이지 높이 = 화면 높이, 오른쪽만 스크롤")와 같다. 판은 늘 다 보인다.
- 고른 줄 = 3px 남색 테두리 + 연남색 바탕, 번호 남색(목업 `alternatives.html:175-177`). 판이 있는 화면의 줄은 `64px | 이름 | 시공일` 세 칸(목업 `:174`), [끝] 칸 없음.
- 판 안 꾸밈은 목업 값(`alternatives.html:184-196`, `:241-242`, 단추 `:76-83`) 그대로, 글자는 모두 `calc(Npx * var(--foms-fs, 1))`.
- **빈 공간 없이(사용자 11-10 ②)**: 목업은 표와 단추 사이가 빈 칸(`.sp{flex:1}`)이다. 여기서는 그 자리를 **그림이 채운다**(그림 칸이 남는 키를 모두 가짐). 새 칸 · 새 꾸밈은 없다.
- 판이 짧을 때(컨테이너 쿼리, 판 키 < 560px — 날짜 띠 11-14 선례처럼 media 대신 판 자신의 키를 잰다): [끝] 96 → 72px(지금 줄 [끝]과 같은 키, 장갑 D5 기준 위), 칸 사이 12 → 8px. 그래도 모자라면 판 **위 칸(이름 · 품목 · 그림 · 표)만** 판 안에서 굴러가고 아래 단추 묶음은 늘 보인다.
- 그 공정 줄이 0개면 판을 그리지 않고 줄 칸이 화면 전체(지금 화면 그대로).

### 3-4. 줄을 누르면 판이 바뀌는 방식 — 화면 안 자료(보이기/숨기기)

- 서버가 **공정 줄 전부의 판**을 한 응답에 그려 두고(숨김), 줄을 누르면 보이기/숨기기만 한다. 새 요청 없음.
- 까닭: ① 같은 탭의 공정 4탭이 이미 이 방식이다 ② 판 자료가 이미 읽은 행에서 나와 쿼리가 0개 더한다 ③ 공장 와이파이가 가끔 언다(D5) — 누를 때마다 받으면 언 동안 판이 안 바뀐다 ④ 줄 수가 작다(운영 '내 공정' 탭 숫자 1~4 — 원장 `:251` · `:273` · `:342` 실측, 생산팀이 손댈 주문 전체도 52건 — 원장 `:198`).
- 날짜 탭이 조각으로 바꾼 까닭(15장 × 카드 = 1.03MB)과 크기가 다르다. 판 하나 약 2KB(그림은 숨은 동안 `loading="lazy"` 라 안 받는다) → 52줄이어도 약 100KB. **검증에서 줄 4 · 12 · 52 일 때 응답 크기를 재고, 52줄에서 지금 '내 공정' 조각의 1.5배를 넘으면 날짜 탭처럼 `view=step&order=` 조각 방식으로 바꾼다**(같은 판 조각 · 같은 함수라 바꾸기 쉽다).
- 판은 새 조각 `templates/production/partials/home_step_panel.html`(`home_steps.html` 이 줄 칸 옆에서 include). 인라인 style · script 없음, 그림 목록은 `data-*` JSON 을 `safeJsonParse` 로.

### 3-6. 첫 진입에 고른 줄 · 주소

- 공정 탭: 주소 `order=` 가 있고 그 주문이 어느 공정 줄에 있으면 **그 탭**(지금의 "마지막 탭 기억" localStorage 보다 앞). 없으면 지금처럼 마지막 탭 → 첫 탭.
- 줄: 탭마다 `order=` 의 줄, 없으면 **보류 아닌 첫 줄**, 모두 보류면 첫 줄. 서버가 탭마다 고른 줄을 표시해 그린다(탭을 바꿔도 그 탭의 고른 판이 바로 보임).
- 줄을 누르면 고른 표시 · 판을 바꾸고 주소와 [다시 받기] 주소를 `?tab=steps&order=<id>` 로 `replaceState`(날짜 탭 `keepDayUrl` 선례, `foms-production-home-days.js:53-59`). 공정 탭을 바꾸면 그 탭의 고른 줄로 주소를 맞춘다.
- 판이 있는 화면의 줄 링크 = `?tab=steps&order=<id>`(진짜 링크). JS 가 묶이기 전에 누르면 그 줄이 고른 채로 페이지가 뜬다(날 단추 선례 — 엉뚱한 화면으로 안 간다). 새 JS 는 `home_early.html` 에 실어 일찍 묶는다(11-14 '눌러도 안 됨' 고침 선례). 판이 없는 화면의 줄 링크는 지금처럼 작업 시트.
- 서버는 `order` 를 숫자로만 읽고 줄에 없으면 무시한다(읽기 · 표시만).
