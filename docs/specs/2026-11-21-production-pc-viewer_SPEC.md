## 0. 한 줄

PC 메뉴 '생산' 을 새 첫 화면(`/erp/production/home`)으로 바꾸고, PC 에서는 **보기만** 되게 한다(관리자만 [고치기] 로 켬). 넓은 화면을 줄이 꽉 채우고, 공정 칸에 마우스를 올리면 누가 · 언제 했는지 보이고, 시공일보다 늦은 줄은 색으로 드러난다. **모든 줄에 시공일(요일 · D-n)이 늘 보인다.** 그다음 도면 · 시공 · 출고 팀에도 보기를 열고, 알림 · 바로가기 주소를 옮긴 뒤 옛 보드를 PC 메뉴에서 뺀다.

## 1. 누가 · 왜

- 공장은 태블릿으로 일한다. **PC 로 생산 화면을 쓰는 사람 = 관리자 + 생산이 어디까지 왔는지 확인하는 다른 팀**(보기가 대부분). 지금 PC 로 생산 일을 하는 사람은 없다.
- 지금 PC 메뉴 '생산' 은 옛 보드(`templates/partials/shared/erp_sub_nav.html:36-37`)로 간다. 옛 보드는 줄마다 [제작 시작] 같은 쓰기 단추가 있고(`board_1440x900.png`), 공정이 어디까지 왔는지는 안 보인다.
- 새 첫 화면을 PC 로 열면(`home_date_1920x1080.png`): ① ERP 둘째 줄 메뉴(대시보드 · 실측 · 도면작업실 · 생산 …)가 없다(`metrics.txt` `shell_nav: 0`, 보드는 11) ② 이름 글과 공정 칸 사이가 비고 공정 칸이 오른쪽 끝에 붙는다 ③ 시공일이 상태 글 아래 13px 회색으로만 있다 ④ 공정 칸이 끝났는지만 보이고 누가 · 언제는 작업 시트에 들어가야 보인다.

## 2. 지금 코드의 사실 (origin/deploy 에서 직접 확인)

- **보는 사람**: `can_view_production_home` = 관리자 또는 CS · 영업 · 생산 능력 팀, 협력사 제외(`foms/services/production/home_access.py:18`, `:21-27`). 회계팀은 CS 별칭이라 들어간다(`foms/services/orders/order_mutation_policy.py:60`). 도면 · 시공 · 출고 팀은 403(`foms/web/production/home.py:135-141`).
- **쓰는 사람(서버)**: 생산 쓰기 API 아홉(start · complete · rework · cancel · uncomplete · change-ack · steps POST · defect · hold)이 모두 `_production_steps_edit_required` = 관리자 또는 CS · 영업 · 생산(`foms/api/production/orders.py:86`, `:103-109`, 라우트 `:747-749` … `:1669-1671`). 도면 · 시공 · 출고 팀은 이미 403 이다.
- **기기 문**: 태블릿 = 모바일 v2 셸 + 터치(`home.py:60-66`). 터치 판정은 `foms_ptr` 쿠키가 `fine` 이 **아니면** 터치로 친다(`foms/services/feature_flags.py:144-176`) — 쿠키가 없는 첫 요청도 터치 쪽이다.
- **줄 자료**: `build_production_home`(`foms/services/production_home_read_model.py:315-397`) 쿼리 4회 + 회차 1회. 행마다 `structured_data` 통째(`foms/services/production_dashboard_display.py:235`) · 회차 시작 `run_started_at`(`production_home_read_model.py:375`) · 시공일 머리 `day_label` · `day_sub`(만드는 곳 `:107-120`, 달력 날 수 D-n · "n일 지남" · 오늘 · 내일).
- **누가 · 언제**: 공정 칸 저장 모양 `{key, label, done, at, by_name}`(`foms/services/production/steps.py:9`, `:139-140`). 작업 시트는 이것을 "이름 · M/D HH:MM"(KST)로 그린다(`foms/services/production_sheet_view.py:153-165`, `:205`). 첫 화면 공정 4칸 `production_home_steps` 는 `done` 만 꺼낸다(`production_home_read_model.py:53-69`) — **같은 행에 이미 있는 자료라 쿼리를 더하지 않고 꺼낼 수 있다.**
- **쿼리 수 계약**: 날짜 탭 실측 9 · 상한 11(`tests/domains/test_production_home_query_count.py:21-28`).
- **기존 '생산 D-2' 배지**: 시공일까지 **영업일** 0~2 이고 시공 단계가 아니면(`foms/services/erp_display.py:490`) — 옛 보드 · 주문 대시보드에 쓴다.
- **옛 보드**: 로그인만 되면 누구나(`foms/web/production/dashboard.py:91-94`), '내 것만' · 협력사 거르기(`partner_order_filter.py:14-17`)가 있다. 켜진 프리랜서는 문지기 허용 목록에 옛 보드만 있다(`foms/services/auth/freelancer_screens/production.py:29-31`, `:48` `focus_order`).
- **[보드 →]**: 첫 화면 위 탭 끝(`templates/production/partials/home_body.html:20`). 태블릿에서는 `e2ddab14b` 가 뺐고 PC · 폰에는 남는다.

## 4. 기기별 동작

| 기기 | 어떻게 가르나 | 화면 |
|---|---|---|
| **PC 마우스** | `foms_ptr=fine` | ERP 위 줄 + **ERP 둘째 줄 메뉴(생산 켜짐)** + 첫 화면 제목 줄 · 탭. 보기 전용 — 쓰기 단추 · 쓰기 JS 를 **서버가 그리지 않는다**. 줄 꼴은 §6. 관리자는 제목 줄에 [고치기] |
| **태블릿** | 모바일 v2 셸 + `foms_ptr=coarse` | **지금 그대로**(탭 넷 · 도면 카드 · 내 공정 판 · 확인 창). 출력 바이트가 바뀌지 않는다(시험) |
| **폰** | 모바일 v2 셸 + 좁은 창 | 지금 그대로. 2단계에서 아래 메뉴 '생산' 주소만 바뀐다. 보는 팀에게는 쓰기 단추를 안 그린다(§5) |
| **쿠키 없음** | 첫 요청 | 쓰기 단추를 **안 그린다**(쓰기 = `foms_ptr=coarse` 일 때만). 터치 기기는 부트 스크립트가 쿠키를 심은 다음 화면부터 단추가 보인다 |

## 5. 권한 표 — 누가 보고, 누가 누르나

| 사람 | 보기 | 태블릿 · 폰에서 누르기 | PC 에서 누르기 | 막는 곳 |
|---|---|---|---|---|
| 관리자 | 예 | 예 | **[고치기] 켰을 때만** | 화면: 서버가 그리기 · 안 그리기. API: 지금 그대로 허용 |
| 생산팀(파트 없음) | 예 | 예(지금 그대로) | 아니요 | 화면만 — API 는 기기를 모른다(아래) |
| 생산팀 파트 계정 | 예 | 자기 파트 카드만(D53), '내 공정' 탭 없음(D50) | 아니요 | 지금 그대로 |
| CS · 회계 · 영업 | 예 | 예(지금 API 권한) | 아니요 | 화면만 |
| **도면 · 시공 · 출고 (2단계)** | **예(새로)** | 아니요 | 아니요 | **서버 API 가 이미 403** + 화면에 안 그림 |
| 협력사 · 켜진 프리랜서 | 아니요(지금 그대로) | — | — | `can_view_production_home` · 문지기 |

- **서버 강제의 뜻**: ① 보기만 하는 팀은 쓰기 API 여덟(start · complete · rework · cancel · uncomplete · steps POST · defect · hold)이 403(이미 그렇다, 시험으로 못 박는다) ② PC 화면은 쓰기 단추 · 쓰기 JS(`tablet-domain-sheets.js` 의 쓰기 배선, '내 공정' [끝], 작업 시트 단추)를 **응답에 넣지 않는다** — CSS 숨김이 아니다. [확인했어요](change-ack)는 쓰기가 아니라 사람마다 남기는 확인 기록이라 **보는 사람 모두**가 기기와 상관없이 누른다(PC 보기 전용 포함, §13 결정 5) — API 문지기 `PRODUCTION_ACK` = `write_access.can_ack_production_change`(보기 판정 − 조회 전용).
- **기기는 보안 경계가 아니다.** CS · 영업 · 생산 계정이 PC 에서 API 를 직접 부르면 지금처럼 통과한다(태블릿과 같은 API). 이 팀들을 **어느 기기에서나** 보기만으로 만들려면 `_PRODUCTION_STEPS_EDIT_TEAMS` 를 좁힌다 — §13 결정 2.
- 화면 판정 한 줄: `쓰기를 그린다 = API 권한 있음 and (foms_ptr == 'coarse' or (관리자 and 고치기 켬))`. 한 함수(`foms/services/production/home_access.py` 에 `production_home_can_act`)로 두고 첫 화면 · 작업 시트 · 셸 조각이 같이 쓴다.

## 6. PC 화면 꼴

### 6-1. 틀
- 위: ERP 위 줄(지금) → ERP 둘째 줄 메뉴 `erp_sub_nav.html`(`erp_sub_nav_active='production'`, 다른 화면과 같은 조각) → 첫 화면 제목 줄(생산 · 날짜 · 전체 n건 | 날짜 · 내 공정 · 바뀐 것 · 찾기 · 보드 → | **보기 전용** 표 · [고치기](관리자) · 글자 · 다시 받기).
- 둘째 줄 메뉴는 PC 마우스 응답에만 넣는다(태블릿은 레일이 있다). 셸 조각(`home_fragment.html`)과 온전한 페이지가 같은 조각을 써야 한다(parity 계약).

### 6-2. 줄 한 개 = 여섯 칸 (날짜 · 바뀐 것 · 찾기 탭 공통, '내 공정' 줄은 §6-4)
`grid-template-columns: 8.5rem 7rem minmax(14rem, 1.3fr) minmax(19rem, 2fr) minmax(7.5rem, .8fr) 5rem; gap: 10px` (목업에서 1440×900 넘침 0 으로 맞춘 값)

| 칸 | 글 | 크기 |
|---|---|---|
| ① **시공일** | `11/23 (월)` 큰 글 + 아래 `D-2` · `오늘` · `내일` · `2일 지남` · `시공일 없음` | 22px/800 · 16px/700 |
| ② 상태 | 제작 대기 · 재단 중 … · 보류 + 늦음이면 한 줄 까닭 | 18px/800 |
| ③ 손님 · 품목 | 이름 #번호 · 품목 · W×D×H · 색(두 줄까지, 자르지 않음) | 20px/800 · 15px |
| ④ 공정 4칸 | 재단 · 엣지 · 조립 · 검수 칸이 칸 폭을 4등분(오른쪽 끝에 붙지 않음) | 칸 키 56px, 글 15px |
| ⑤ 발주 · 담당 | 발주사 · 영업 담당(D21) | 15px |
| ⑥ 도면 | 도면 n장 | 15px/700 |

- **빈 가운데 없음**: ③ · ④ · ⑤ 가 남는 폭을 1.3 : 2 : .8 로 나눈다. 1440×900 에서 줄 칸(왼쪽 띠 316 뺀 약 1,100px)이 다 찬다.
- **아주 넓을 때**(줄 칸 ≥ 1,500px — 1920@80% = CSS 2,400px): 컨테이너 쿼리로 비율을 1 : 2.4 : .8 로 바꾸고(공정 칸이 더 가짐), 공정 칸 안에 `김재단 11/20` 을 글로 보인다(마우스를 안 올려도). 마우스를 올리면 시각까지.
- **좁을 때**(글자를 키우거나 창이 좁아 줄 칸 < 1,070px): ⑤ 발주 · 담당을 ③ 아래 줄로 내린다(컨테이너 쿼리). 가로 넘침 0.
- **글자 · 단추를 줄이지 않는다**(사용자 80% 배율). 지금 줄 이름 20px · 제목 탭 크기를 아래로 내리지 않는다. 새 글자는 `calc(Npx * var(--foms-fs, 1))`.
- 인라인 style 없음, 꾸밈은 `static/css/contexts/production/home.css` 의 PC 블록(`body` 가 모바일 v2 셸이 아닐 때) + 핀 올림.

### 6-3. 시공일 칸 규칙 (사용자 11-21 "아주 중요한 정보")
1. **모든 탭의 모든 주문 줄 · 카드에** ① 칸이 있다 — 날짜 탭(같은 날 장 안에서도), 내 공정, 바뀐 것, 찾기, 도면 · 컨펌 기다림 작은 줄, 작업 시트 머리(이미 `시공 11/19 (목)`, D-n 더함).
2. 글 = `M/D (요일)` + D-n. D-n 은 날짜 띠와 같은 달력 날 수(`production_home_day`, KST 오늘 기준). 시공일이 없으면 `시공일 없음`(빈칸 아님).
3. 마우스 올리기 뒤에 숨기지 않는다. '바뀜' 표 · 날짜 장 머리가 대신하지 않는다. 시공일이 바뀐 줄은 `11/23 (월)` 그대로 두고 아래에 `← 11/27` 작게 더한다.
4. 늦음 · 빠듯 줄(§8)이면 ① 칸 글자 색이 빨강 · 주황으로 바뀐다(무채색 금지).
5. 여러 시공일로 나뉜 주문은 지금 장 나누기와 같은 납작 칸(`erp_construction_date`) 를 바탕으로 "가장 가까운 날 + 외 n" 으로 보인다 — §13 결정 5.

### 6-4. '내 공정' 탭(PC)
- 줄 = `시공일 | 번호 · 이름 · 품목 | 앞 공정 누가 · 언제 | 발주 · 담당`. 보기 전용이면 [<공정> 끝] 칸 자체가 없다(남는 폭은 이름 칸). [고치기] 켬이면 지금 줄 [끝] 단추가 그 자리에 다시 나온다(지금 PC 동작과 같은 단추 · 같은 POST).

### 6-5. 누가 · 언제 (마우스 올리기)

| 칸 | 올렸을 때 글 | 출처 |
|---|---|---|
| 끝난 칸 | `재단 끝 · 김재단 · 11/20 14:05` | `sd.production.steps[].by_name · at` → `_format_at_kst` |
| 끝났는데 기록 없음(옛 주문) | `재단 끝 · 기록 없음` | 같은 곳 |
| 지금 칸 | `엣지 · 지금 여기(아직)` | `home_steps[].now` |
| 남은 칸 | `조립 · 아직` | |
| 상태 칸(회차 있음) | `제작 시작 11/20 08:40` | 행 `run_started_at`(이미 읽음) |

- `production_home_steps` 가 칸마다 `by` · `at_label` 을 더 낸다(같은 행 · 쿼리 0). 날짜 탭 상한 11 그대로 — 시험.
- 보이기는 CSS(`[data-tip]:hover` · `:focus-visible`), 칸에 `tabindex="0"` · `aria-label` 같은 글. JS 없음. 태블릿 · 폰에서는 글을 안 넣는다(출력 그대로).

## 7. [고치기] (관리자 · 생산팀 — §13 결정 1)

- 제목 줄 오른쪽에 **관리자 · 생산팀에게만** 그린다(§13 결정 1). 누르면 `foms_prod_edit=<발급 시각>` 쿠키(`Path=/erp/production`, 만료 없음 = 브라우저를 닫으면 사라짐, `SameSite=Lax`)를 심고 다시 받는다. 새 API 없음.
- 서버는 **관리자 · 생산팀이고 쿠키가 2시간 안**일 때만 켬으로 본다. 그 밖은 쿠키를 무시한다.
- 켬이면 제목 줄 아래 주황 띠 `고치는 중이에요 — 누르면 바로 저장돼요 [그만 고치기]`, 그리고 **지금 태블릿과 같은 쓰기 단추**가 나온다('내 공정' [끝], 작업 시트 단추). '바뀐 것' [확인했어요]는 [고치기]와 상관없이 늘 있다(§13 결정 5). 새 쓰기 화면은 만들지 않는다.
- 왜 사람 설정에 저장하지 않나: 켠 채 잊으면 보기만 하려던 날 잘못 누른다. 왜 주소 `?edit=1` 이 아닌가: 탭을 옮기면 꺼진다.

## 8. 늦은 줄 규칙

**일하는 날로 센다(§13 결정 3 — 주말 · 공휴일 뺌).** W = 오늘(KST) 다음 날부터 시공일까지의 일하는 날 수(`foms/services/common/business_calendar.py` 한 곳을 쓴다, 새 달력 금지). 아래 표의 D 는 W 로 읽는다. 줄에 쓰는 D-n 글은 달력 날 그대로 두되, 색 기준이 일하는 날이라는 것을 마우스 글에 적는다(`시공까지 일하는 날 2일`). 지금 자리는 `home_stage` · 첫 미완 공정.

| 지금 자리 | 빠듯(주황) | 늦음(빨강) |
|---|---|---|
| 도면 · 컨펌 기다림 | D ≤ 5 | D ≤ 3 |
| 제작 대기(회차 없음 · 재단 전) | D ≤ 4 | D ≤ 2 |
| 재단 중 · 엣지 중 | D ≤ 3 | D ≤ 1 |
| 조립 중 · 검수 중 | D ≤ 2 | D ≤ 0 |
| 보류 | 멈춘 공정의 줄과 같다 | |
| 제작 완료 · 시공 단계 · 시공일 없음 | 없음 | 없음 |

- 시공일이 오늘보다 앞(지남)인데 제작 완료가 아니면 자리와 상관없이 늦음.
- 숫자는 제안값으로 시작한다(§13 결정 3). 기준점 = 지금 '생산 D-2' 배지(제작 대기 늦음 D ≤ 2 와 맞춤). 값은 `foms/services/production/late_rule.py` 상수 표 한 곳, 순수 함수 `production_late_level(row, today) -> 'late' | 'tight' | None`(쿼리 0).
- 꼴: 줄 왼쪽 6px 띠 + 연한 바탕(빨강 `--app-danger-50` · 주황 `--app-warn-50`), ② 상태 칸 아래 한 줄 `늦음 — 시공 D-1, 아직 엣지`. 줄 순서는 바꾸지 않는다.

## 13. 사장님 결정 (2026-11-21 질문 창)

1. **[고치기] = 관리자 · 생산팀.** CS 는 켤 수 없다.
2. **CS · 영업의 생산 쓰기 권한을 모든 기기에서 뺀다** — 쓰기 팀 = 관리자 + 생산팀만(`foms/api/production/orders.py` `_PRODUCTION_STEPS_EDIT_TEAMS` 등 서버에서). PC 보기 전용이 서버 끝까지 완전해진다. 태블릿에서 CS · 영업이 보류 · 제작 시작을 누르던 길도 막힌다(사장님 승인).
3. **늦음 · 빠듯은 일하는 날(주말 · 공휴일 뺌)로 센다**(§8). 숫자 표는 제안값 그대로 시작한다.
4. **1 · 2단계를 한꺼번에** 만든다. 옛 보드 넘겨주기(R2)는 설계대로 2주 뒤 접속 기록을 본 다음 따로 묻는다.
5. 나머지(시공팀 PC 메뉴 '생산' 더하기 · 시공팀 · 영업은 전체 주문 보기 · 여러 시공일은 "가장 가까운 날 + 외 n" · PC 보기 전용에서도 [확인했어요] 허용 · 태블릿 줄 시공일은 별도 커밋 a1f95737c 로 이미 늘 보임)는 설계서 기본값.
