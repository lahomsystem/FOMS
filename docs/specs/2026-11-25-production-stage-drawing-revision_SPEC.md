## 2. 화면마다 바뀌는 것 (PC · 태블릿 공장 화면)

### 2-1. 도면 작업실 목록 — '생산 중' 칸 (시안 01)

- **자리**: 지금 프로세스 맵 줄 끝에 떨어진 칸 하나 "생산 중 N"(누적 완료 · 지연 · 미확인과 같은 꼴, `data-status="PRODUCTION"`). 새 탭 줄을 만들지 않는다 — 사장님 말 '탭'은 이 칸으로 옮긴다(**풀이** §11-1). 숫자 = 그 사람 범위(내 것만 · 협력사 거르개 그대로)의 생산 + 시공 단계 주문 수.
- **모집단**: 이 칸을 누르면 목록이 `erp_stage_code IN ('PRODUCTION','생산','CONSTRUCTION','시공')` 주문 **전부**(도면 상태 상관없음)로 바뀐다. 다른 칸 · 기본 목록은 지금 그대로(생산 주문을 기본 목록에 섞지 않는다).
- **줄 구성**: 칸(열)은 지금 그대로. 값만 생산 칸일 때 바뀐다.
  - 주문/고객 칸 아래: 요청 표시 "수정 요청 · 영업" / "수정 요청 · 공장" · 고치는 중 표시 "도면 고치는 중"(색 있는 표시 — 회색 금지).
  - 다음 액션: "영업 수정 요청 · 이영업" / "공장 수정 요청 · 박반장 · 도면 3" / "도면 2 고치는 중 · 김도면". 아무것도 없으면 지금 글 그대로.
  - 상태: 둘째 줄에 단계 "생산" / "시공 대기", 셋째 줄에 공장 진행 요약 "재단 5/5 · 엣지 3/5 · 조립 1/5 · 검수 0/5"(2공장 장이 있으면 공장마다 한 줄, 앞에 공장 칩). 시공 대기는 "제작 완료".
  - 대상 번호: 요청 · 고치는 도면 번호 "도면 2" · "도면 2 · 3".
- **정렬**(위에서부터): ① 열린 요청이 있는 주문(영업 · 공장, 요청 시각 오래된 것 먼저) ② 고치는 도면이 있는 주문 ③ 나머지 시공일 빠른 순(시공일 없음은 맨 뒤). 지금 정렬 단추(`sort=`)를 고르면 그 정렬이 이긴다(지금 규칙과 같음).
- **상한 1,000건 문제**: 생산 칸은 따로 모집단을 뽑는다(아래 §7). SQL 에서 ① 요청 · 고치는 중이 있는 주문을 **먼저 모두** 뽑고(상한 없음 — 많아야 수십 건 **추측**) ② 나머지를 시공일 순으로 1,000건까지. 캡에 닿으면 지금처럼 경고 로그 + 목록 아래 한 줄 "더 있는 N건은 안 보여요. 찾기로 찾아 주세요."(새 글). 요청 주문이 잘려 안 보이는 일은 없게 한다.
- **시공 대기 주문 중 시공일이 지난 것**(옛 시공 단계 주문 — 조사에 "시공 이후 옛 주문 운영 65건" 주석) — §9 정할 것 Q1.

### 2-2. 작업실 상세 (시안 02)

생산 · 시공 단계 주문에서만 보인다(그 밖 단계는 지금 그대로).

- **머리 줄**(지금 "단계: 생산 · 주문 담당 · 도면 담당 ✎" 줄): 끝에 링크 "생산 작업 시트 열기"(`/erp/production/sheet/<id>`, 새 탭). 도면팀은 지금도 볼 권한이 있다(`home_access.py:21-41`). 지금 [생산 현황 보기]는 ERP 대시보드로 가므로 그대로 둔다.
- **본문 왼쪽 '공장 진행' 접는 칸**(새 칸 — 지금 '타임라인' · '요청사항' · '파일 비교' 접는 칸과 같은 꼴, 맨 위에 펼친 채). 오른쪽 고정 패널(현재 버전 · 결정 바 · 체크리스트) 뒤에는 두지 않는다 — 패널 뒤 형제는 스크롤하면 깔린다.
  - 도면마다 한 줄: "도면 2" + 공장 칩 · 재단 · 엣지 · 조립 · 검수 칸 = "재단 완료 · 김재단" / "엣지 작업 중 · 박엣지" / "재단 기본" / "조립 미정" / 손 체크 파트는 "재단 완료 · 박반장(작업 시트)". 공장 제작 완료면 줄 끝 "1공장 제작 완료".
  - 줄 끝 단추: [수정 시작] — 누르면 확인 창 "도면 2를 고치는 중으로 표시할까요? 공장에서 도면 2만 작업이 막혀요." `[취소]` `[수정 시작]`.
  - 고치는 중인 줄: 빨간 바탕 + "도면 고치는 중 · 김도면 · 11/25 14:10" + [수정 취소](§9 Q2).
  - 영업 · 공장 요청이 걸린 줄: "수정 요청 · 영업" / "수정 요청 · 공장" 표시.
  - 시공 대기 주문은 진행 칸 대신 줄마다 "제작 완료" 한 칸, [수정 시작] 없음(§9 Q8).
- **요청사항 칸**(지금 그대로 + 공장 요청이 같은 목록에 쌓임): 공장 요청 = "수정 요청 · 공장" 표시 · 시각 · 요청한 사람 · 대상 도면 칩 · "사유: …" · [반영 완료](지금 단추 — 같은 뜻) · [요청 닫기](§9 Q5).
- **결정 바 · 전달 단추**: 지금 그대로. 단, 생산 · 시공 단계에서는 도면팀 누구나 [수정본 전달]이 켜진다(답 4 — "담당자만 전달할 수 있어요." 줄이 생산 단계에서는 안 나온다).

### 2-3. 보내는 창 (시안 03)

두 길이 같은 규칙을 쓴다: 작업실 [도면 전달]/[수정본 전달] 창(`POST /api/orders/<id>/transfer-drawing`) · 마법사 [저장] 창 '도면 발송'(`POST …/drawing-wizard/transfer-pending`).

- **바뀐 도면 자동 표시**: 창 안 대기 도면 목록 아래 한 줄 "바뀐 도면: 도면 2 (고침) · 도면 6 (새 도면)"(빠진 도면은 "· 도면 4 (빠짐)"). 고른 시트가 바뀔 때마다 다시 그린다. 서버도 같은 계산을 해서 전달 이력에 적는다(§3-4) — 화면 값은 미리 보기일 뿐.
- **메모 꼭 적기**(생산 · 시공 단계만): 지금 메모 칸(작업실 창 이름 "메모", 칸 안 안내 "전달 메모")에 빨간 "꼭 적기" + 아래 안내 "생산으로 넘어간 주문은 메모를 적어야 보낼 수 있어요." 비우고 누르면 "공장에 남길 메모를 적어 주세요."(화면 · 서버 같은 글, 서버 400 `NOTE_REQUIRED`). 공백만은 빈 글로 본다.
- **마법사 저장 창**: 생산 · 시공 단계에서 '도면 발송'을 켜면 그 아래 "바뀐 도면" 줄 + 새 칸 "전달 메모"(꼭 적기). `save-send.js:169` 의 빈 글 대신 이 칸 값을 보낸다. 다른 단계는 지금 그대로(칸 없음).
- **이미 작업된 도면 경고**(답 3): [전달하기]/[저장 + 전달]을 누르면 서버가 바뀌는 도면 중 작업된 것이 있으면 409 `WORKED_DRAWING` + 도면별 글을 돌려주고, 창이 한 번 묻는다 — 제목 "보내기 전 확인", 본문 "도면 2는 재단이 완료된 도면입니다. 보내면 공장에서 다시 작업해야 합니다." + 둘째 줄 진행 "도면 2 · 재단 완료 · 엣지 작업 중", `[취소]` `[그래도 보내기]`. [그래도 보내기]는 `ack_worked=true` 로 다시 보낸다. 여러 장이면 도면마다 한 문장. 지금 생산 · 시공 확인 창(`save-send.js:193` · `workbench_detail_body.html:2923-2925`)은 이 창 안 아래 글로 합친다(확인 창 두 번 금지).
  - 글 꼴: "도면 {n}{은/는} {파트들}{이/가} 완료된 도면입니다. 보내면 공장에서 다시 작업해야 합니다." — 조사는 숫자 · 파트 이름 끝소리로(1 · 3 · 6 · 7 · 8 · 0 → 은, 2 · 4 · 5 · 9 → 는; 재단 · 조립 → 이, 엣지 · 검수 → 가; 여럿이면 마지막 파트로 "재단 · 엣지가"). 지금 `part_mark_rules.subject_particle` 을 숫자 읽기까지 넓혀 쓴다.
  - "작업된" = 그 도면(지금 key)에 파트 표시 `DONE`/`BASIC` 이 하나라도 있거나, 그 도면 파트가 손 체크로 완료거나, 그 도면 공장이 제작 완료. '작업 중'(맡음)만인 도면은 경고하지 않고 진행 줄에만 보인다(**풀이** §11-4).

**추천: 안 ⓐ.** 생산 쪽 읽기가 모두 주문 JSON 을 이미 들고 있어 쿼리가 늘지 않고, 수정본 전달이 같은 JSON 사본을 쓰는 순간 막힘이 같이 풀려 "보냈는데 막힘이 남음"이 생기지 않는다. 파트 표시(`ProductionPartMark`)를 따로 표로 뺀 까닭(여러 사람이 동시에 자주 누름)은 여기에 없다 — 도면 수정 누름은 하루 몇 번이다. 마이그레이션이 없다.

### 3-2. 모양

```json
"drawing_fix": {
  "fixing": {
    "sheet:Sk3a9": {"no": 2, "by_user_id": 31, "by_name": "김도면", "at": "2026-11-25T05:10:00Z", "request_ids": ["fr_7c1e"]},
    "file:drawing_gateway/5801/abc.pdf": {"no": 4, "by_user_id": 31, "by_name": "김도면", "at": "…"}
  },
  "requests": [
    {"id": "fr_7c1e", "from": "factory", "targets": ["sheet:Q8b21"], "numbers": [3], "note": "측판 길이가 실측과 달라요",
     "photos": [], "factory": 1, "by_user_id": 52, "by_name": "박반장", "at": "…",
     "state": "open", "done_at": null, "closed_by_name": null, "close_note": null}
  ]
}
```

- **열쇠(도면 신원)** = `sheet:<sheet_id>`(마법사 시트 — 판이 바뀌어도 같다) 또는 `file:<저장 key>`(직접 올린 파일). `drawing_factory.py:6-12` 이 푼 방식 · 출고 패킹 줄 열쇠 `sheet:<id>`(`packing_factory.py:11-22`)와 같은 꼴. 판정 함수 하나 `fix_ident(entry)` 를 새 순수 모듈 `foms/services/orders/drawing_fix.py` 에 두고 모든 자리가 그것만 쓴다.
- `no` 는 표시용 스냅샷(그때 도면 번호) — 판정에는 안 쓴다.
- 영업 요청은 지금처럼 `drawing_transfer_history` 의 `REQUEST_REVISION` 에 남기고, 그 줄에 `target_idents`(요청 순간 대상 key → 열쇠)를 더 적는다. 옛 줄(이 칸 없음)은 `target_drawing_keys` 를 그때 `drawing_current_files` 로 풀고, 못 풀면 통째로 본다.
- 공장 요청은 `requests` 에(영업 요청과 섞지 않는다 — 영업 요청은 `drawing_status` 를 RETURNED 로 바꾸는 지금 흐름 · [수정요청 취소] · 반영 완료 체크가 걸려 있다). 공장 요청은 `drawing_status` 를 바꾸지 않는다.

### 3-3. 막힘 판정 (하나의 순수 함수)

`drawing_fix.blocked(sd) -> Block(whole: bool, idents: frozenset, why_by_ident)`:

1. **통째** = `drawing_status == TRANSFERRED`(옛 자료 · 강제 단계 변경 — 지금 그대로) 또는 (`RETURNED` 이고 마지막 열린 영업 요청에 대상이 없음/못 풂)(답 5 "안 고른 요청은 지금처럼 전체").
2. **도면별** = (`RETURNED` 이면 그 요청 `target_idents`) ∪ `fixing` 열쇠 ∪ (§9 Q6 이 "바로 막음"이면 열린 공장 요청 `targets`).
3. 지금 `drawing_revision_in_progress(sd)` 는 "통째" 만 뜻하게 이름 그대로 두고(지금 시험 · 관리자 뚫기 `GATE_DRAWING_REVISING` 가 그대로 산다), 새 함수 `drawing_blocked(sd, entry)` · `any_drawing_blocked(sd)` · `factory_drawing_blocked(sd, factory)` 를 더한다.

### 3-4. 풀림 · 적기

- 생산 · 시공 단계 전달(바로 반영) 쓰기 안에서: 이번 전달이 **건드린 열쇠**(같은 시트 자리 교체 · 교체 대상 key · 빠진 key · 새 시트) 의 `fixing` 을 지우고, 그 열쇠를 가리키는 열린 공장 요청을 `state=done` 으로. 안 건드린 도면의 `fixing` 은 남는다(2번을 고친다 해 놓고 3번만 보냄 → 2번 그대로 막힘).
- 영업 요청은 지금처럼 `CONFIRMED` 로 돌아가며 풀린다(반영 완료 체크를 모두 해야 보낼 수 있는 지금 규칙 그대로 — 요청이 2 · 3 을 가리켰는데 2만 보내도 3이 풀린다. 도면팀이 "반영 완료"로 확인했기 때문).
- 전달 이력 `TRANSFER` 줄에 `changed: {"replaced": [2], "added": [6], "removed": [4]}`(도면 번호) 와 `by_user_name`(지금 있음 — 답 4 "누가 보냈는지 기록")을 적는다. '바뀐 것' 줄 글이 이것을 읽는다.

### 3-5. 폼 저장 · 초안 · 주문 만들기가 덮지 못하게

- `structured_form_projection.SERVER_LOCKED_KEYS` 에 `"drawing_fix"` 를 더한다(`drawing_factory` 와 같은 자리 — `structured_form_projection.py:78-101`).
- `drawing_factory.strip_client_factory_state` 옆에 같은 꼴로 `drawing_fix` 를 빼거나, 그 함수 이름을 넓혀 주문 만들기(`order_create._prepare_structured`, `order_create.py:116`) · 초안 자동 저장(`erp_orders_structured.py:2391`)에서 뺀다.
- 쓰는 길 = 새 API 넷(§5) + 두 전달 길(풀림)만.

### 3-6. 마이그레이션 — **필요 없음**

새 칸은 주문 JSON 안이고, 없으면 "아무것도 고치는 중 아님"이다(오늘과 같은 값). 옛 영업 요청 줄은 읽을 때 푼다.

## 7. 성능 · 예산

- **작업실 '생산 중' 칸**: 모집단 SQL 두 번(① 요청 · 고치는 중 — `structured_data ? 'drawing_fix'` 또는 `drawing_status='RETURNED'` · ② 나머지, 단계 미러 칼럼 `erp_stage_code` 색인) + 지금 하이드레이트 + **파트 표시 1번**(그 쪽 25줄 주문 IN). 다른 칸 · 기본 목록 쿼리 수 = 지금과 같음(0 증가). 가드: `tests/domains/test_drawing_workbench_query_count.py` 에 생산 칸 경우를 더해 "주문 8건 더해도 증가 0 · 절대 상한 지금 + 3".
- **작업실 상세**: 생산 · 시공 단계만 파트 표시 1번 더(주문 하나). 다른 단계 0.
- **생산 첫 화면 · 도면 판 · 작업 시트 · PC 보드**: 막힘 판정은 이미 든 주문 JSON 에서 — **쿼리 0 증가**. 지금 가드(`test_production_home_query_count.py` · `test_production_selfclaim_query_count.py` · `test_production_factory_query_count.py`) 숫자를 바꾸지 않는다.
- **출고 조각(fragment)은 건드리지 않는다**(패킹 막힘은 패킹 쓰기 API 안 판정만).
- 전달 경고(409 판정): 파트 표시 1번(그 주문) — 쓰기 길이라 예산 밖이지만 N+1 금지.

- 추천 ② — 시공이 끝난 집 도면은 [AS 도면 보내기] 길이 따로 있어요. 시안은 ① 로 그렸어요.

**Q2. [수정 시작]을 눌렀다가 보내지 않고 그만둘 때는 어떻게 할까요?**

- 추천 ① — 누구나 보낼 수 있으니(답 4) 그만두는 것도 누구나가 맞고, 기록은 남아요.

- 추천 ① — 보내기(답 4)와 같은 사람이어야 "시작은 못 하는데 보내기는 됨"이 안 생겨요.

**Q13. 작업 시트에서 손으로 완료 처리한 파트(도면별 작업을 안 쓴 파트)가 있는 주문의 도면을 고치면요?**
지금은 새 도면도 "완료"로 보여요(조사 §5).
- ① 고친 도면만 다시 작업으로 — 나머지 도면은 손 처리한 사람 이름으로 완료 그대로, 고친 도면만 그 파트 할 일로 나옴 ② 그 파트 전체를 다시 미완료로 ③ 지금 그대로 + 보내기 전 경고에만 "재단은 작업 시트에서 통째 완료로 처리된 주문이에요"
- 추천 ① — 다시 할 일은 고친 도면뿐이에요. ② 는 다 자른 판까지 다시 하라는 뜻이 돼요.

**Q14. 직접 올린 파일(마법사가 아닌 도면)을 고쳐 보낼 때는요?**
지금 직접 올린 파일은 새로 올리면 공장 지정이 1공장으로 돌아가고 '바뀐 도면' 표시도 안 나와요.
- ① 생산 중 주문은 [교체]에서 어느 도면을 바꾸는지 꼭 고르게 하고, 공장 지정 · 막힘 · '바뀐 도면' 표시를 그 도면에서 이어받기 ② 지금 그대로(새 도면으로 봄)
- 추천 ① — 2공장 도면이 말없이 1공장으로 가면 두 공장이 같은 도면을 만들 수 있어요.

**Q15. 시공을 시작한(방문이 열린) 주문도 '생산 중' 칸에 넣을까요?**
시공 단계 안에 '시공 대기'와 '시공 중'이 섞여 있어요.
- ① 넣음(도면을 바꿀 일이 생길 수 있음) ② 시공 대기만
- 추천 ② — 답 1 이 "생산 · 시공 대기"예요. 시공 중 도면 변경은 AS 길이 맞아요.

## 11. 풀이 (사장님 답을 코드에 옮기며 정한 것 — 틀리면 고침)

1. '탭' = 프로세스 맵 끝의 새 칸. 작업실에는 탭 줄이 없고, 새 줄을 만들지 않는 규칙(이미 있는 칸에 얹기)을 따랐다.
2. "도면팀 누구나 보냄"(답 4)이면 생산 · 시공 단계에서 "도면 담당자가 지정되지 않아 전달할 수 없습니다" 400 도 넘어간다. 보낸 사람은 전달 이력 `by_user_name` 에 남는다(지금도 적힘).
3. 영업 요청 "요청한 도면만 막기"(답 5)는 생산 · 시공 단계에만 적용한다. 고객컨펌 단계의 영업 요청은 지금처럼 통째(제작 시작 문이 따로 있음).
4. 경고(답 3)는 '완료'(파트 완료 · 기본 · 손 처리 · 공장 제작 완료)만. '작업 중'(맡기만 함)은 진행 줄에 보이되 묻지 않는다 — 답의 예시 글이 "완료된 도면".
5. 이미 완료한 파트에게는 막힘이 안 보인다(그 파트 도면은 "재단 끝 · 김재단"). 새 판이 오면 새 도면으로 나오므로 지금 그대로.

## 12. 조사와 다르게 · 새로 안 것 · 확신이 낮은 곳

- 영업 요청은 도면 2장 이상이면 번호를 꼭 고르게 되어 있어(`erp_orders_revision.py:132-152`) 답 5 의 "안 고른 요청"은 도면 1장 · 협력사 요청 · 옛 자료에만 생긴다.
- 작업실 전달 창 메모 칸의 이름은 "메모"(칸 안 안내가 "전달 메모")다. 마법사 저장 창에는 메모 칸이 없다.
- 작업실 상세 [생산 현황 보기]는 생산 작업 시트가 아니라 ERP 대시보드로 간다.
- 요청사항의 지금 "미완료" 표시가 회색이다 — 무채색 배지 금지와 부딪히지만 지금 글 · 모양이라 이번에 바꾸지 않는다(따로 여쭐 일).
- **추측**: 생산 + 시공 단계 주문 수는 1,000건보다 훨씬 적을 것(운영 건수 안 셈). 열린 요청 · 고치는 중 주문은 수십 건 이하.
- **추측**: 주문 버전 +1(N1 · N3)이 열린 주문 편집 폼의 If-Match 저장을 409 로 만들 수 있다 — 공장 지정 API 와 같은 성질이라 새 위험은 아니지만 D1 에서 영업 편집 화면으로 한 번 확인한다. 마법사 시트 저장은 If-Match 를 안 보낸다(`static/js/drawing` 확인).
- **확신 낮음**: 숫자 조사(은/는) 넓히기 — 지금 `part_mark_rules.subject_particle` 이 한글 끝소리만 보는지 숫자도 보는지 구현 때 확인.
