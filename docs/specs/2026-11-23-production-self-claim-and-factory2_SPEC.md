## 0. 한 줄

지금 파트 화면(도면 카드 골라 맡기)을 그대로 두고 **막힌 곳 · 헷갈리는 곳만** 고친다 — 파트 일이 남으면 [제작 완료]를 막고 **마지막 검수 장**에서 "제작 완료할까요?"를 묻는다, 검수만 **그 장의 재단 · 엣지 · 조립이 끝나야** 맡는다, 맡기 풀기 · 넘겨받기, '어제 맡음', 보류 · 도면 고치는 중 막기, 손으로 켠 공정 칸 = 카드 끝, 첫 맡기 = 제작 시작, 날짜 탭 줄 공정 칸 아래에 **맡은 사람 · 끝낸 사람**. 그다음 **계정 하나에 파트 여럿** · 파트 없는 생산팀은 자기 공장에서 아무 파트나 대신. 마지막으로 **2공장**: 도면 한 장마다 만드는 공장을 **도면팀만**(그 주문 도면 담당 · 관리자) 정하고 내려온 뒤에도 바꾸되 **아무도 맡거나 끝내지 않은 장만** 옮긴다, 계정마다 한 공장, 남의 공장 카드는 흐리게 보기만, 주문 단위(단계 · 마감 · 공정 4칸 · 제작 완료)는 그대로 하나. 기존 주문 표시 `flags.factory2`("라홈시스템(2공장)")는 계약 회사 표시라 따로 두고 이름에서 '2공장'을 뺀다.

## 1. 누가 · 왜 · 흐름

- **파트 사람**(재단 · 엣지 · 조립 · 검수, 태블릿 가로 1176 × 626 · 화면 크기 80%): 아침에 태블릿을 켜고 그날 도면 카드에서 자기 할 장을 **스스로** 맡는다(반장이 나눠 주지 않는다). 끝나면 [끝]. 잘못 맡았으면 풀고, 쉬는 동료 장은 넘겨받는다. 검수는 앞 세 파트가 끝난 장부터.
- **파트 없는 생산팀 계정 · 관리자**: 공장 전체를 본다. 빠진 사람 대신 카드를 누르고, 공정 칸을 손으로 켜기도 한다. 파트 없는 생산팀은 자기 공장만, 관리자는 두 공장.
- **도면팀**(그 주문의 지정 도면 담당 · 관리자): 도면 장마다 1공장 · 2공장을 정한다. 1공장이 넘칠 때 몇 장을 2공장으로 돌린다. 생산에 내려간 뒤에도 바꾸되 일이 시작된 장은 못 옮긴다.
- **PC 사람**(관리자 · 다른 부서): 보기만. 누가 무엇을 맡았고 누가 끝냈는지 한눈에.
- 흐름(한 주문): 도면 내려옴(생산 단계) → 파트 사람이 첫 카드를 맡음 = **제작 시작** → 장마다 재단 · 엣지 · 조립이 알아서 맡고 끝냄(순서 안 막음, D46) → 세 파트가 끝난 장부터 검수 → **마지막 검수 장** 끝 = "제작 완료할까요?" → 시공 대기. 2공장 장이 섞이면 2공장 사람들이 그 장만 같은 방식으로 하고, 물건은 1공장에 모여 함께 나간다.

## 4. 자료 규칙

### 4-1. 낱말 뜻

- **지금 장** = 주문의 지금 확정 도면 항목들(`resolve_final_drawing_files`).
- **카드를 썼다**(주문) = 그 주문에 상태가 NONE 이 아닌 표시 줄이 하나라도 있다(옛 key 줄 포함). 맡았다 푼 줄(NONE)만 있으면 안 쓴 것 — 실수로 맡았다 푼 주문이 '칸 안 쓴 주문' 길을 잃지 않게. 판정은 쿼리 1(`order_id IN (…) AND state <> 'NONE'`, 유일 제약 앞머리 `order_id` 를 탄다).
- **파트가 끝났다**(주문 · 파트) = 그 파트 공정 칸이 켜져 있다(손으로든 카드로든). 카드 동기화가 "지금 모든 장 끝"일 때만 카드 칸을 켜므로, 카드로 일한 파트는 칸 = 모든 장 끝이다(§4-4).
- **장이 끝났다**(장 · 파트) = 그 파트 공정 칸이 손으로 켜져 있거나(§4-4), 그 장 표시가 재단 DONE 또는 BASIC · 그 밖 DONE(지금 `_finished` `part_steps_sync.py:53-56` 그대로).
- **일이 시작된 장**(C3) = 그 장의 **지금 key** 에 상태가 NONE 이 아닌 표시 줄이 어느 파트든 하나라도 있다(맡음 · 기본 · 끝). 맡았다 푼 줄(NONE)과 옛 판 key 의 줄은 치지 않는다. 손으로 켠 공정 칸은 주문 단위라 장을 가리지 못해 치지 않는다.

- 누가 확인하나: 마지막 검수 장을 끝낸 사람(생산팀 · 관리자 — 지금도 [제작 완료]를 누를 수 있는 사람들). 따로 정한 '완료 담당'은 없다.

### 4-4. 손으로 켠 공정 칸 — B5

- **칸에 표지를 더한다**: `{key, label, done, at, by_name, via}` — `via` = `'sheet'`(공정 API · 작업 시트 · 내 공정 판에서 사람이 켬) · `'part_marks'`(카드 동기화가 켬). 끄면 `via` 도 지운다. `set_production_step(…, via=…)` 한 함수(`steps.py:119-141`)가 쓴다. JSON 칸 하나 더함 — 마이그레이션 없음.
- **옛 칸(`via` 없음)** = 손으로 켠 것으로 본다(안전한 쪽 — 사람이 켰을지 모르는 칸을 카드가 끄지 않는다). 운영은 칸을 거의 안 쓴다(11-12 실측 0, 원장 `:495`) — 내보내기 전에 생산 단계 주문의 켜진 칸 수를 읽기로 센다(§13).

| 칸 상태 | 그 파트 카드 화면 | 그 파트 카드 쓰기 | 카드 동기화 | 검수 순서(§4-7) |
|---|---|---|---|---|
| 꺼짐 | 표시 줄대로(지금) | 됨 | 모든 장 끝이면 켬(`via='part_marks'`) | 장마다 표시로 판정 |
| 켜짐 · `via='part_marks'` | 표시 줄대로(모두 끝) | 되돌리기 됨 → 동기화가 끔(지금). 단 그 장 검수가 끝났으면 막음(§4-7) | 지금 그대로 | 끝 |
| 켜짐 · `via='sheet'` 또는 없음 | **모든 장 "재단 끝 · 작업 시트"**, 단추 없음, 누르면 "작업 시트에서 재단을 끝으로 켰어요. 다시 하려면 작업 시트에서 꺼 주세요." | 막음 409 `STEP_SET_BY_HAND`(맡기 풀기만 됨) | **안 건드림**(끄지도 켜지도 않음) | **모든 장 끝**(검수 카드가 열림) |

- 켤 때 그 파트에 맡음 줄이 있으면 **줄은 그대로 둔다**(지우지 않음). 화면은 '끝'만 보이고, 작업 시트에서 칸을 끄면 카드가 그 전 모습("김재단 맡음")으로 돌아온다 — "다시 하려면 끄면 카드가 다시 열림".
- 카드로 켜진 칸(`via='part_marks'`)을 작업 시트에서 끄려 하면 막는다 409 `STEP_SET_BY_CARDS` "카드로 끝낸 공정이에요. 다시 하려면 도면 카드에서 되돌려 주세요." — 끄면 다음 카드 쓰기 때 동기화가 다시 켜 버린다(칸 · 카드가 서로 덮음). 사장님 예(손으로 켠 칸)와는 부딪히지 않는다(§15 ④).
- 손으로 켠 재단 · 엣지 · 조립 칸을 끄면 그 칸 덕에 열렸던 검수 카드가 다시 '검수 전'이 된다. 이미 끝난 검수 표시는 그대로 둔다(칸 끄기는 사람이 일부러 하는 비상구 — 숨은 쓰기 없음).
- 섞인 주문: 칸이 주문에 하나라 1공장 관리자가 손으로 켜면 2공장 장도 '끝'으로 보인다(§14).

### 4-5. 맡기 · 풀기 · 넘겨받기 — B2 (+ 검수 순서 B11)

표시 줄 전이(⊙ = 새로 더함). '할 수 있는 사람' = 그 파트를 할 수 있는 사람(§5). 검수(`part = inspect`)의 맡기 · 기본 없음 · 끝 · 넘겨받기는 **그 장이 검수 준비됨(§4-7)일 때만**.

| 누름 | 지금 → 새 | 누가 | 화면이 보내는 것 | 더 보는 것 | 기록 |
|---|---|---|---|---|---|
| take 맡기 | 없음 · NONE → NEED(나) | 할 수 있는 사람 | `seen:none` | 검수면 준비됨 | 지금 |
| basic 기본(재단) | NONE → BASIC | 할 수 있는 사람 | `seen:none` | — | 지금 |
| done 끝 | NEED(나) → DONE | 맡은 사람 · 관리자/대신(덮어쓰기) | `seen:need` + ⊙`seen_by` | 검수면 준비됨 | 지금 |
| undo 되돌리기 | DONE → NEED · BASIC → NONE | 끝낸 사람 · 관리자/대신 | `seen:done/basic` | ⊙재단 · 엣지 · 조립이면 그 장 검수가 DONE 이 아님 | 지금 |
| ⊙ release 맡기 풀기 | NEED(나) → NONE(맡은 사람 · 때 지움) | 맡은 사람 · 관리자/대신 | `seen:need` + `seen_by` | — | 이벤트 `action:'release'` |
| ⊙ takeover 내가 맡기 | NEED(남) → NEED(나, `picked_at` = 지금) | 할 수 있는 사람(맡은 사람 아님) | `seen:need` + `seen_by=<그 사람 id>` | 검수면 준비됨 | 이벤트 `action:'takeover'`, payload `from_user_id` · `from_name` + 감사 "재단 넘겨받음 김재단 → 박재단" |

- `seen_by`(화면이 본 맡은 사람 id)를 더하는 까닭: 지금 `seen` 은 상태만 봐서 "김재단 맡음"과 "박재단 맡음"을 못 가린다. 넘겨받기 · 풀기 · 끝은 맡은 사람이 화면과 같을 때만 한다.
- **경합**(주문 행 잠금이 줄 세움 — 지금 그대로): 화면이 본 상태 · 맡은 사람과 서버가 다르면 409 `MARK_CONFLICT` + 지금 모습. 글 = "박재단이 먼저 맡았어요"(take) · "박재단이 넘겨받았어요"(그사이 남이 넘겨받음) · "김재단이 먼저 끝냈어요" · "그사이 맡기를 풀었어요". **글은 확인 창 안**에 보이고 창 아래 카드는 서버 모습으로 바뀐다, 실행 단추는 [닫기](W4).
- 멱등: 같은 사람이 같은 결과를 다시 보내면 200(지금 `_same_result` 규칙에 release = NONE · 마지막으로 바꾼 사람이 나, takeover = NEED · 맡은 사람이 나).
- 넘겨받은 기록은 카드에 따로 그리지 않는다(카드는 지금 맡은 사람만). 기록 = 이벤트 `PRODUCTION_PART_MARKED` payload + 감사 한 줄 — 주문 이력 탭에서 보인다. 새 칸 · 새 표 없음(§6-4).
- 풀기 · 넘겨받기도 30초 받아 오기(`part_marks_read.py`)로 남의 화면에 간다(표시 줄이라 그대로).
- 검수 쓰기는 그 주문의 **모든 파트** 표시 줄을 읽는다(지금은 누른 파트만 — 같은 쿼리 1 에서 파트 거르기만 뺀다).

### 4-7. 검수 순서 — 장마다 (B11, D46 의 하나뿐인 예외)

- **검수 준비됨**(장 k) = 재단 · 엣지 · 조립 셋 모두 '장이 끝났다'(§4-1): 그 파트 칸이 손으로 켜졌거나(`via` ≠ `'part_marks'`), 장 k 의 표시가 재단 DONE · BASIC / 엣지 DONE / 조립 DONE. 카드로 켜진 칸(`via='part_marks'`)은 모든 장 끝이라 저절로 맞다.
- **장마다인 까닭**: 검수는 다 만든 판 묶음(도면 한 장의 물건)을 보는 일이다. 재단 · 엣지 · 조립은 순서 없이 장마다 따로 진행되므로(D46), 세 파트가 끝난 장은 다른 장을 기다리지 않고 바로 검수할 수 있어야 한다 — 주문 단위로 묶으면 검수가 가장 늦은 장을 기다려 끝에 몰린다. 카드 단위(D48) · 공장 나누기 단위(C2)와도 같은 단위다(2공장 장은 2공장 검수가 본다).
- **할 일이 없는 파트**: 장마다 모든 파트가 카드를 갖고(지금 구조), '할 일 없음' 상태는 재단의 '기본'(이미 잘라 둔 판, D49)뿐이다. 엣지 · 조립이 필요 없는 장은 그 파트 사람이 [끝]을 한 번 누르거나, 파트 없는 생산팀 · 관리자가 작업 시트에서 그 파트 칸을 손으로 켠다(그러면 모든 장이 끝으로 쳐진다). 엣지 · 조립 '필요 없음' 상태는 이번에 만들지 않는다(§17).
- 막힌 검수 카드 글은 남은 파트 순서대로 `엣지(김민준 맡음) · 조립(아무도 안 맡음)` — 맡은 사람이 있으면 이름, 없으면 "아무도 안 맡음".
- 이미 검수가 DONE 인 장의 재단 · 엣지 · 조립을 카드에서 되돌리려 하면 막는다(§4-6) — 검수를 먼저 되돌리게 해서 "검수 끝인데 앞 파트가 안 끝남"이 생기지 않게.
- 옛 검수 맡음(이 규칙 전 맡은 NEED)은 지우지 않는다 — 끝은 준비될 때까지 막히고, 풀기는 된다.

### 4-8. 첫 맡기 = 제작 시작 — B6

- 카드 쓰기(take · basic · takeover · 일괄 기본) 뒤 표시가 NONE 이 아닌데 그 주문에 **지금 회차가 없으면**(제작 대기) 같은 tx 안에서 제작 시작을 한다. 회차 찾기 쿼리 1(`fetch_production_current_run_ids` 꼴).
- 하는 일은 지금 [제작 시작] 단계 그대로 길(a)과 같다 — `execute_order_mutation`(정책 `PRODUCTION_START`, 단계 이동 없음) 안에서 단계 기록 "제작 시작 (도면 카드 첫 맡기)" · 회차 발급 · 감사 · 이벤트 `PRODUCTION_STARTED`(payload `via:'part_marks'`) · 버전 +1. 카드 쓰기가 이미 잡은 주문 행 잠금 안에서 한 tx. **누가** = 카드를 맡은 사람(이벤트 `created_by_user_id` · 단계 기록 이름).
- 코드: 지금 `orders.py:604-617` · `:857-890` 을 새 서비스 `foms/services/production/start_run.py` `start_production_run(db, order, user, *, via)` 로 옮겨 제작 시작 API 와 카드 쓰기가 같이 쓴다(api 가 api 를 부르지 않게, 자리 고정 시험).
- 막는 것은 카드 쓰기 막음(§4-6)과 같다(보류 · 도면 고치는 중 → 맡기 자체가 막힘). 생산 단계가 아니면 카드가 없다(`_check_order`). 이미 회차가 있으면 아무것도 안 함(멱등 — 주문 행 잠금 안에서 본다).
- 첫 맡기를 풀어도 **제작 시작은 그대로**(되돌리지 않음) — 되돌리려면 작업 시트 [제작 취소](지금 그대로). 바뀐 것 감지는 생산 → 생산 이동이라 바닥선을 안 옮긴다(`production_change_alerts.py:61` `_DOWNSTREAM_STAGES`).
- 작업 시트 [제작 시작] 단추는 칸만 쓰는 주문을 위해 그대로 둔다.

### 4-9. 맡은 때 · 어제 맡음 · 아침 글 — B3

- 카드 상태 글: 오늘 맡음 "김재단 맡음" · 어제(KST 날짜) "김재단 맡음 · 어제" · 그 전 "김재단 맡음 · 11/20 (금)". 내 카드는 이름 대신 "내가 맡음". `picked_at`(UTC) → KST 날짜로. 표시 줄 응답 `mark_payload`(`part_mark_rules.py:254-270`)에 `picked_day`(KST `YYYY-MM-DD`)를 더해 30초 받아 오기 뒤에도 글이 맞게.
- '어제' 글 조각은 호박 글자(`#9a3412` 위 `#ffedd5`) — 무채색 아님, 맡음 바탕과 ΔE 20.7 / 29.9(§8-9).
- **아침 글**(파트 계정, 전체 페이지에만): 위 줄 아래 한 줄 "어제부터 맡은 도면 2장 — 11/23 (월) 1장 · 지난 7일 1장", 날마다 그 날 장 링크(`home_href`). 셈 = 내가 맡은 NEED 줄 중 `picked_at` 이 오늘 KST 0시 전. 쿼리 1(`order_id IN (첫 화면 생산 주문) AND picked_by_user_id = 나 AND state = 'NEED'`, 유일 제약 앞머리 `order_id` 를 탄다). 날 조각(`view=day`)에는 없다(조각 쿼리 그대로).
- 저절로 풀지 않는다(지금도 푸는 곳이 없다).

### 4-12. 2공장 (P3)

**계정 공장**(C9): 생산팀 계정마다 1공장 또는 2공장(§6-2, 비면 1공장) — 한 사람 한 공장. 파트 계정 · 대신 모드 모두 자기 공장 장만 쓴다. 관리자만 두 공장 — 판 머리 공장 고르기 [1공장 | 2공장](처음 = 계정 값 또는 1, §16 질문 3).

**장의 공장**(§6-3): `structured_data.drawing_factory` — 시트 신원(`sheet_id`)마다, 직접 올린 파일은 저장 key 마다 1 · 2. 없으면 1공장. 읽기 함수 하나 `sheet_factory(sd, entry) -> int`(순수, 쿼리 0): `sheet_id` 가 있고 표에 있으면 그 값 → key 가 표에 있으면 그 값 → 1.

| 일 | 장의 공장 |
|---|---|
| 같은 시트 다시 보내기(새 판) · 한 장만 바꾸기 | 같은 `sheet_id` → 그대로(새 key 여도) |
| 수령 확정 · 전달 취소 되살리기 · 품목 취소로 장 빠짐 | 표가 따로라 그대로(빠진 장의 표 줄은 다음 쓰기 때 정리) |
| 직접 올린 파일(시트 신원 없음) | key 로 — 같은 파일을 새로 올리면 새 key 라 **1공장으로 돌아간다**(§14, 작업실 목록에 공장이 보여 놓치기 어렵게) |
| 마법사 시트 복제 | 새 시트 신원 → 1공장 |
| AS 도면 | 생산 카드가 없어 공장을 두지 않는다(§17) |

**누가 정하고 바꾸나**(C3): **도면팀만** = 그 주문의 지정 도면 담당 + 관리자(ADMIN) — 지금 도면 전달과 같은 판정(§5-1). 생산팀 · 영업 · CS 는 못 바꾼다(화면에 고르는 칸이 없고 서버도 403). 새 API `POST /api/orders/<id>/drawing/sheet-factory`(§7). 마법사 탭 · 작업실 '현재 버전' · 보낼 시트 칸 어디서 바꿔도 같은 API · 같은 표.

**언제 옮길 수 있나**(C3):

### 5-1. '도면팀' = 지금 도면을 보내는 사람 (새 역할 없음)

- 장 공장 API 는 **지금 도면 전달과 같은 두 문**을 쓴다.
  1. 앞문 정책 **`DRAWING_ASSIGNED`**(매니페스트 등재, `order_mutation_policy.py:218-219`): ADMIN 통과 · MANAGER 는 팀과 상관없이 통과 · STAFF 는 팀 DRAWING(능력 — 별칭 팀 포함)이고, 그 주문에 도면 배정 줄이 있으면 배정된 사람만 · VIEWER · 협력사 막음(`:441-462`).
  2. 처리기 술어 **`can_transfer_drawing(user, order)`**(`erp_policy_permissions.py:127-149`): **ADMIN 또는 그 주문의 지정 도면 담당**(`assignments.drawing_assignee_user_ids`). 도면팀 소속만으로는 안 된다(M14-a). 그 주문에 도면 담당이 아무도 없으면 ADMIN 도 안 된다 — 지금 전달이 400 "도면 담당자가 지정되지 않아…"로 막는 것과 같다(`erp_orders_drawing.py:190-192`).
- 그래서 실제로 바꿀 수 있는 사람 = **관리자(ADMIN, 도면 담당이 있는 주문)** + **그 주문의 지정 도면 담당**(STAFF 면 팀 DRAWING 이어야 앞문 통과, MANAGER 면 팀 무관).
- 전달에 있는 **MANAGER 긴급 오버라이드(사유)는 공장 API 에 두지 않는다**(`erp_orders_drawing.py:203-204` 의 그 갈래) — MANAGER 는 앞문을 팀과 상관없이 지나므로 이것을 두면 생산팀 MANAGER 가 사유만 적고 공장을 바꿀 수 있게 된다(C3 "생산팀은 못 바꿈"에 어긋남). 같은 술어 함수 `can_transfer_drawing` 만 부른다.
- 화면 고르기 칸도 같은 술어로 그린다(마법사 `can_transfer` `foms/web/drawing/wizard.py:47`, 작업실 `foms/web/drawing/workbench.py:1293-1295`). 담당 아닌 도면팀에게는 지금 전달 단추 자리처럼 "담당자만 바꿀 수 있어요" 한 줄.

### 6-2. 계정 공장 (P3)

- **`users.production_factory` SmallInteger NULL, CHECK `production_factory IS NULL OR production_factory IN (1, 2)`**(`ck_users_production_factory`, 두 DB). NULL = 1공장으로 본다(채우기 없음). 생산팀이 아니면 저장 때 비운다(파트와 같은 규칙 `production_part_for_team`).

### 6-3. 장의 공장 표지 (P3)

| 안 | 문제 |
|---|---|
| ⓐ 마법사 시트 `drawing_wizard.sheets[i].factory` | sheets 는 **화면이 가진 값**이라 저장 때 통째로 바뀐다(`wizard.py:179`, `:851-867`). 작업실에서 바꾼 값을 서버가 sheets 에 써 넣으면, 열려 있던 마법사의 다음 자동 저장이 옛 값으로 덮거나(조용한 되돌림) `base_updated_at` 이 어긋나 저장 충돌이 난다. 직접 올린 파일은 시트가 없어 못 담는다 |

### 6-4. 넘겨받은 기록

## 9. 알림 · 바뀜

- **새 알림 없음.** 장의 공장이 바뀌면(도면팀만, 일이 시작 안 된 장만) 이벤트 `DRAWING_SHEET_FACTORY_CHANGED`(payload `key` · `sheet_id` · `sheet_no` · `from` · `to`, `created_by_user_id`)를 남기고, 생산 변경 감지 목록(`production_change_alerts.py:65-71`)에 이 종류를 더한다 → 주문 '바뀜' 테두리 · 바뀐 것 탭 장 · 줄 '바뀜' 글 "공장 바뀜 도면 2/2 1공장 → 2공장 · 도면 장미래 · 2시간 전" · [확인했어요]가 지금 길 그대로 두 공장 모두에 뜬다. 같은 목록이 조각 304 지문이라 받아 오기도 바로 안다. 이미 읽는 이벤트 쿼리에 종류만 더함 — 쿼리 0.

- 생산 진입 전(도면 · 컨펌 단계) 바꾼 것은 D22 바닥선으로 안 뜬다(내려오기 전이라 맞다).
- 넘겨받기 · 풀기 · 검수 준비됨 알림(다음 사람에게)은 없다 — 30초 받아 오기가 카드를 바꾼다(§17).

## 15. 사장님 결정과 지금 코드 · 옛 결정이 부딪히는 곳

1. **B5 ↔ 카드 동기화(§15.5 "카드로 일한 파트는 카드가 칸을 정한다")**: 지금은 맡기만 해도 손 칸을 끈다(`part_steps_sync.py:69-86`). → 칸에 `via` 를 더해 손 칸은 동기화가 안 건드린다(§4-4). 옛 칸은 손으로 본다.
2. **B1 ↔ 2026-11-21 "공정 칸을 쓴 주문만 막기"**: 카드를 쓴 주문은 칸을 안 켜도 막는다(§4-2). 카드를 안 쓴 주문의 예외는 그대로 — 운영 습관(칸 · 카드 안 씀)을 막지 않는다.
3. **풀림 — B1 "마지막 검수 장" ↔ D46(순서 안 막음)**: 1판은 "어느 파트든 마지막 장"으로 했고 사장님께 여쭸다 → 답 **"검수 장을 끝낼 때만"**. 그러려면 검수가 마지막이어야 하므로 **검수만 장마다 순서를 둔다**(B11, §4-7) — D46 의 하나뿐인 예외. 재단 · 엣지 · 조립 사이는 그대로 순서 없음. 승인되면 DECISIONS 에 "D46 예외: 검수는 그 장의 재단 · 엣지 · 조립 뒤"로 적는다.
4. **B5 "다시 하려면 끄면 열림" ↔ 카드로 켠 칸**: 카드로 끝낸 칸을 작업 시트에서 끄면 다음 쓰기 때 다시 켜진다 → 그 칸은 끄기를 막고 카드에서 되돌리게(§4-4). 사장님 예(손 칸)와는 안 부딪힘.
5. **B2 · B6 ↔ D55 ~ D57 설계서 승인 때 추천안("넘겨받기 없음, 제작 시작 자동 안 함", 원장 §28 `:521`)**: 이번 답이 옛 추천안을 바꾼다 — 승인되면 DECISIONS 에 바뀜으로 적는다.
6. **B7 ↔ D55("나머지 직원은 읽기 전용")**: 파트 없는 생산팀만 읽기 전용에서 '대신'으로. CS · 영업 · 도면 등은 그대로 읽기 전용.
7. **B9 ↔ D47("계정 하나에 파트 하나")**: 여러 파트로 바꾼다(§6-1).
8. **풀림 — C6 ↔ B7**: 사장님 답 = 계정마다 한 공장, 두 공장은 관리자만(C9). 대신 모드는 파트를 넘고 공장은 넘지 않는다.
9. **C3 "생산 뒤에도 바꿈" ↔ D56("도면 바뀜 = 새 판 안 봄부터")**: 공장만 바꾸는 것은 새 판이 아니다 — 도면 key 를 안 바꾸는 따로 API(§6-3). 사장님 답으로 **일이 시작된 장은 못 옮기므로** 표시 줄을 옮기거나 지킬 일 자체가 없다.
10. **C3 "도면팀만" ↔ 지금 도면 전달 권한**: 지금 코드의 '도면을 보내는 사람'은 **팀이 아니라 그 주문의 지정 도면 담당 + 관리자**다(`can_transfer_drawing`, M14-a). 그래서 '도면팀만' = 이 둘이고, 담당이 아닌 도면팀원은 못 바꾸며 담당이 없는 주문은 관리자도 못 바꾼다(§5-1). 또 앞문 정책 `DRAWING_ASSIGNED` 는 MANAGER 를 팀과 상관없이 통과시키고 전달에는 MANAGER 긴급 갈래가 있다 — 이 갈래를 공장 API 에 두면 생산팀 MANAGER 가 바꿀 수 있어 빼었다. 새 역할은 만들지 않는다.
11. **C2 장 단위 ↔ 주문 단위로 남는 것(공정 4칸 · 단계 · 보류 · 불량 · 제작 시작/완료 · 마감)**: 섞인 주문의 '재단 중'은 두 공장 합친 모습이다. C5 · C8 과 맞는다. 칸 아래 끝낸 사람 '외 n' 도 두 공장을 함께 센다.

## 16. 사장님께 여쭐 것 (넷 — 추천값으로 먼저 시작)

1. **파트 계정 날짜 띠 숫자 '만들 것 / 전체'를 '내 파트 남은 장'으로 바꿀까요?** → 추천: **지금 그대로**(주문 수, 반장과 같은 띠).
2. **'라홈시스템'만 쓰는 곳도 '라홈시스템 계약'으로 맞출까요?** → 추천: **'2공장'이 보이는 다섯 곳만**(§8-7).
3. **관리자는 두 공장 카드를 한 화면에 같이 보나요?** → 추천: **판은 공장을 골라 하나씩**, 날짜 탭 · PC 줄은 합쳐서 "1공장 3장 · 2공장 2장".
4. **도면 마감과 '도면 x/n'은 주문 하나로 셉니다(총괄이 정함).** → 추천: **주문 하나로** — 공장마다 따로 보고 싶으시면 말씀해 주세요.
