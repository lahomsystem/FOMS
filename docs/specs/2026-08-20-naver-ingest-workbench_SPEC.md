## 게이트

`foms/services/feature_flags.py` 의 2단계 관례를 그대로 쓴다.

```
FOMS_NAVER_WORKBENCH_ENABLED   전역 on/off
FOMS_NAVER_WORKBENCH_COHORT    사용자 id 목록 또는 all
```

- `is_enabled_for_user("FOMS_NAVER_WORKBENCH_ENABLED", uid, cohort_key="FOMS_NAVER_WORKBENCH_COHORT")`
- **꺼져 있으면 지금 화면 그대로**(기본값 off). 켜진 사용자만 워크벤치를 본다.
- 쿠키 토글은 두지 않는다 — 관리자 화면이고, 코호트만으로 충분하다(표면을 늘리지 않는다).

## 화면 구조 (v2 목업 기준)

```
[상태 스트립]  네이버 수집 · 43집 · 상품주문 140건 · 마지막 실행 · 인증 만료 · [지금 수집]
[실행 결과 띠] 성공 n집 / 실패 m집 → 펼치면 건별 사유 + 실패건만 재시도   (있을 때만)
[탭] 처리 대기 | 발주확인 전 | 취소·반품 | 전체 이력
[좌: 큐 한 집 한 줄]              [우: 선택한 집 상세]
  색띠 + 진행배지 + 클레임배지        집 단위 대조표
  + "지금 처리 가능" 글자 라벨        상품주문 n행 표(옵션 원문 전문)
                                    액션 → 확인 모달
```

### 결정별 구현 위치

| 결정 | 구현 |
|---|---|
| 1 탭 4개 통합 | `?tab=work\|place\|claim\|all`, 기본 `work` |
| 2 취소·반품 전체 이력 잔존 | `all` 탭에서 회색 행 + 액션 비활성(빼지 않는다) |
| 3 숫자 이중 표기 | 헤더 한 곳(`{{ group_count }}집 · 상품주문 {{ pending_count }}건`). 탭 배지는 집만 |
| 4 상태 3층 | 진행 배지 + 클레임 배지 + 좌측 색띠·글자 라벨(색맹 대비, 손대면 안 되는 집은 띠를 끊어 그린다) |
| 5 행 인라인 확장 | 우측 상세에 상품주문 n행 표 — 옵션 원문 전문 |
| 6 불가역 4종 세트 | 모달: 건수 재진술 + "되돌릴 수 없음" + 사후 경로. **선택 0집이면 버튼 비활성** |
| 7 대조표 2단 | 위=집 단위(수취인·주소·결제), 아래=상품주문 행 단위. 단위 다른 둘을 한 표에 안 섞는다 |
| 8 좌우 분할 | 유지 |

클라이언트로 따로 쓴다 — 기존 79건을 개편 중에 빨갛게 두지 않는다(회귀 감지력 유지).

## 하지 않는 것

- `erporder` 편집 폼(규격 입력) — 범위 밖. 1px 도 안 건드린다.
- 규격 자동 파싱 — 사람이 옵션 원문을 읽고 채운다(도메인 규칙 6).
- 선택 없이 버튼=전체 대상 — 2026-08-14 AS 증발 사고 패턴. 선택 0집이면 아무것도 안 한다.
- 100건 일괄 덮어쓰기 — 우리는 한 집 안 2~14품목을 조립하는 반대 축.
- 스캐너·핫키 파워유저 최적화 — 병목은 키 입력이 아니라 건당 판단.
- 담당자 지정 UI 확대 — 실측 일정 단계 일이다(도메인 규칙 5).
