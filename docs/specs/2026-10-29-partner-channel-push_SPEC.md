# 협력사 주문 화면 영발 PUSH · 발주 PUSH · 변환 — 설계 (승인 · 구현 2026-10-29)

작성 2026-10-29. 요청: 협력사 주문 상세(`/partner/orders/<id>`)에 우리 ERP 주문 탭과 같은
"변환"(보낼 글 미리 보기) · "영발 PUSH" · "발주 PUSH" 를 둔다.

## 1. 왜

본사는 시공 스케줄을 채널톡 영발방 · 발주방을 보고 손으로 짠다(나중에 ERP 출고 스케줄로 옮길 예정).
협력사 주문은 지금 이 두 방에 들어가지 않아 스케줄 판에서 빠진다.

## 2. 지금 코드 (사실)

- ERP 버튼: `templates/orders/partials/erp_order_tab.html:510-547`, 동작 `static/js/orders/erp-order-shared.js:5962-6120`.
- 보낼 글은 **브라우저가 ERP 폼에서** 만든다(`erpGenerateConversionText`). 영발 · 발주는 실측일 · 시간 · 실측/주소/연락처
  특이사항 줄을 잘라 보낸다(`erpSliceConversionTextForChannelPush`, 같은 파일 5306행).
- 같은 글의 **서버판**이 이미 있다: `foms/services/channel_measure_message.py::build_measure_push_text(sd)`
  (마법사 · 실측방용, PC 변환 글과 같은 모양).
- 보내기: `POST /api/channel/push-manual` (`foms/api/channel/channel_integration.py:479`). 직원 역할만
  (`ADMIN · MANAGER · STAFF`), 협력사 계정은 못 부른다. 종류별 방 · 첨부 분류:
  영발 = `measurement` 첨부 → 영발방, 발주 = `drawing` 첨부 → 발주방. 두 번째부터는 "변경 내용"(재전송 메모) 필수,
  동시 클릭 막기, 이력 · 감사 기록이 이 라우트 안에 다 들어 있다(한 함수 약 300줄).
- 협력사 흐름: 저장하면 바로 도면 단계. 우리가 도면을 보내면 협력사가 "받음"(수령 확인, DRAWING→CONFIRM),
  그다음 "이대로 만들어 주세요"(승인, CONFIRM→생산).
- 협력사가 올린 파일: 실측 사진은 `measurement`(폴더 `partner_measurement`), 초안 도면은 **`drawing`**(폴더 `partner_draft`).

## 3. 만들 것

1. **보내기 핵심을 함수로 뺀다** — `push-manual` 라우트 안의 "글 · 첨부 고르기 → 전송 → 이력 · 감사 기록"을
   같은 모듈의 `run_manual_push(db, payload, actor)` 로 옮기고 ERP 라우트와 협력사 라우트가 같이 쓴다
   (같은 모듈에 두어 기존 시험의 바꿔 끼우기가 그대로 먹는다).
   ERP 동작은 바꾸지 않는다(기존 시험 그대로 통과가 기준).
2. **글은 서버가 만든다** — 협력사 화면에는 ERP 폼이 없으므로 `build_measure_push_text(sd)` 에 영발 · 발주용
   자르기(실측일 · 시간 · 특이사항 줄 빼기, ★★ 유지)를 서버에 같은 규칙으로 둔다. 협력사가 글을 고칠 수는 없다
   (보내는 글은 저장된 주문 그대로).
3. **협력사 API** (`foms/api/partner/channel_push.py`, 블루프린트 `partner_channel_push`): `GET .../orders/<id>/channel-push`
   (변환 + 버튼 상태), `POST .../orders/<id>/channel-push` (`kind`, 재전송이면 `change_note`). 자기 회사 주문만.
   협력사 문지기 허용 목록 · 쓰기 정책(PARTNER_PORTAL) · 쓰기 가드 목록에 올렸다.
4. **협력사 화면**: 주문 상세에 "변환" 버튼 + 읽기 전용 글 칸 + "영발 PUSH" · "발주 PUSH". 보낸 적 있으면 다시 보낼 때
   변경 내용을 묻는다. 보낸 시각을 버튼 옆에 보인다.
5. **발주 PUSH 첨부**: `drawing` 분류 중 협력사가 올린 초안(`partner_draft`)은 뺀다 — 발주방에는 우리가 보낸
   최종 도면만 나가야 한다(도면은 ERP 에 최종본만, 09-30 결정과 같은 방향).
6. 이력은 ERP 와 같은 칸(`channeltalk_push`, `channeltalk_push_drawing`)에 남긴다 — 그래서 협력사가 보낸 뒤 직원이
   ERP 에서 다시 누르면 재전송으로 본다(같은 방에 두 번 첫 전송이 나가지 않게).

## 4. 결정 (사용자 2026-10-29)

- A. 영발: **처음 저장할 때 "영발방에도 보낼까요?"를 묻는다**(고칠 수 있으니 자동으로 보내지 않는다). 사진이 다
  올라갔을 때만 묻고, 빠진 사진이 있으면 다시 보낸 뒤 주문 화면 버튼으로. 그 뒤 수정 때는 버튼으로 직접.
- B. 발주: **"이대로 만들어 주세요" 뒤 자동으로 한 번** 보내고, 다시 보내기는 버튼. 승인 전에는 버튼이 회색.
  자동 전송이 실패해도 승인은 그대로 두고 "다시 보내 주세요"를 알린다. 이미 보낸 적 있으면 자동으로 다시 보내지 않는다.
- C. 발주방 첨부: 협력사 초안 도면은 **빼고 우리 최종 도면만** — ERP 발주 PUSH 에도 같이 적용.
- D. (구현 판단) 확정 전이면 '시공일' 줄에 "협력사 희망 11월 3일 오후 · 확정 대기"를 싣는다 — 본사가 이 글로
  스케줄을 짜므로 희망일이 보여야 한다.
- E. (구현 판단) 5xx · 설정 오류 문구(환경변수 이름 · 예외 글)는 협력사에게 "지금은 보내지 못했습니다"로만 보인다.

## 5. 시험

- 서비스로 뺀 뒤 기존 push-manual 시험 전부 통과(ERP 동작 보존).
- 협력사: 자기 회사 주문만 · 다른 회사 404, 직원 계정은 협력사 API 못 씀, 글에 실측일 · 시간 줄 없음,
  발주 첨부에 `partner_draft` 없음(대조군: 우리 도면은 있음), 두 번째는 변경 내용 없으면 400,
  발주는 정한 단계 전이면 409. 채널톡 전송은 가짜로 바꿔 끼워 실제로 안 나가게.
- 스테이징에서 실제 영발 · 발주방으로 1건씩(시험 주문 `CLAUDE-TEST-`) 보내 보고 방에 뜬 모양을 확인.
