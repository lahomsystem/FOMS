# 도면 작업실 [저장]·[일괄 저장] → 도면방 PUSH / 도면 발송 같이 하기 — 설계서

- 날짜: 2026-11-05
- 상태: 승인 (2026-11-05)
- 목업: `docs/design/mockups/wizard-save-send-options.html`
- 화면: 도면 마법사 앱바 (`templates/drawing/wizard.html:157-158`)

## 1. 왜

지금은 도면팀이 [저장] 으로 전달 대기함에 넣은 뒤, 작업실로 나가 [전달하기] 창을 열고, 다시 [도면방 PUSH] 를 눌러야 한다. 세 번 오가는 일을 저장 한 번에 끝낸다.

## 2. 사용자 결정 (2026-11-05)

1. [저장] 이나 [일괄 저장] 을 누르면 작은 창이 뜨고, **도면방 PUSH** 와 **도면 발송** 을 켜고 끈다.
2. **도면 발송 = 영업에게 전달하기** (작업실 [전달하기] 와 같은 일). 고객 알림톡이 아니다.
3. PUSH·발송은 **방금 저장한 도면** 을 보낸다 — 저장한 도면을 전달본으로 올린 뒤 보낸다.
4. **PUSH 를 켜면 발송도 같이 켜진다.** 도면방 PUSH 는 일부러 전달본만 보내게 되어 있으므로 (전달 대기 도면은 안 나감) 발송 없이 PUSH 만 하면 방금 그린 도면이 안 간다.
5. **협력사 주문은 담당자에게 전달만 한다.** 협력사는 채널톡에 없으므로 도면방 PUSH 칸이 없다. 저장 창에서 바로 전달하고, 협력사가 고른 옵션은 그대로 둔다 (옵션을 고칠 때만 작업실 [전달하기] 창을 쓴다 — 태블릿 '시트 전달' 과 같다).
6. 목업 모양 승인.

## 3. 화면

- 창 제목: `지금 시트 저장` / `모든 시트 저장 (N장)`.
- 칸 두 개 (체크 상자):
  - `도면 발송` — 영업에게 전달해요 (전달본으로 올려요)
  - `도면방 PUSH` — 채널톡 도면방에 도면을 올려요. 켜면 `도면 발송` 이 같이 켜지고, 발송을 끄면 PUSH 도 꺼진다.
- 아래 단추 글이 고른 대로 바뀐다: `저장만` · `저장 + 전달` · `저장 + 전달 + 도면방`.
- `다음에도 이대로 고르기` (기본 켬) — 고른 것을 이 브라우저에 기억해 다음에 미리 켠다 (localStorage, 사용자별 키).
- 칸을 못 쓰는 경우는 칸을 잠그고 한 줄로 이유를 쓴다:
  - 전달 권한 없음 (지정 도면 담당자·관리자가 아님) → `도면 담당자만 전달할 수 있어요`
  - 협력사 주문 → 도면방 PUSH 칸을 보이지 않는다.
- **Ctrl+S 는 창 없이 바로 저장만 한다** (그리는 중에 창이 뜨면 손이 멈춘다). 자동 저장도 그대로.
- V2 화면 ⋯ 메뉴의 `일괄 저장` 도 같은 창을 연다 (원래 단추를 눌러 주는 구조라 저절로 따라온다).
- 오른쪽 끝 [도면방 PUSH] 단추는 그대로 둔다 (저장 없이 PUSH 만 다시 할 때).

## 4. 처리 순서

### 4.1 [저장] (지금 시트 한 장)

1. 기존 `save()` 그대로 — 상태 PUT → 시트 PNG 를 전달 대기함에.
2. 저장이 실패하면 여기서 멈춘다 (기존 알림).
3. `도면 발송` 켬 → 저장 뒤 `GET /drawing-wizard/pending` 으로 대기함을 다시 읽고 → `POST /api/orders/<id>/transfer-drawing`
   `{ pending_sheet_ids: [지금 시트 id + 대기함에 있는 다른 시트 id], files: [], mode: 'APPEND', note: '' }`
   - **고침 (2026-11-06 보고)**: 처음엔 지금 시트 하나만 보냈다. 운영 주문 5862 · 5803 에서 시트 A 를 고쳐 [저장]만 하고
     시트 B 에서 [저장 + 전달 + 도면방] 을 누르자 B 만 전달되고, 도면방에는 A 의 옛 전달본이 나갔다.
     대기함에 넣어 둔 시트는 "전달을 기다리는 도면" 이므로 함께 보낸다 (작업실 [전달하기] 창도 대기 도면을 모두 골라 둔다).
     지운 시트의 옛 대기 항목은 지금 시트 목록으로 걸러 뺀다. 대기함을 못 읽으면 전달하지 않는다.
   - `APPEND` 를 꼭 적는다. 비우면 영업 확정 전 (TRANSFERRED) 에 서버가 전체 교체로 보고, 한 장만 보내도 다른 장이 전부 빠진다.
   - `APPEND` 면 서버의 같은 시트 자리 교체 규칙 (`replace_same_sheet_files`) 이 그 시트 옛 판만 바꾸고 나머지 장은 둔다.
4. `도면방 PUSH` 켬 → 전달이 성공했을 때만 기존 `pushDrawingRoom` 흐름. 첫 확인창 (`현재 전달본 도면 N장을 … 진행할까요?`) 만 뺀다 — 이미 창에서 골랐다. 담당자 개인방 못 찾음 확인·재전송 변경 내용 입력은 그대로 묻는다.

### 4.2 [일괄 저장] (모든 시트)

1. 기존 `saveAll()` 그대로.
2. **한 장이라도 PNG 가 실패하면 전달·PUSH 를 하지 않는다.** 일부만 전달되면 영업이 빠진 장을 모른다. 알림: `N장을 못 넣어서 전달은 하지 않았어요`.
3. `도면 발송` 켬 → `POST /api/orders/<id>/transfer-drawing`
   `{ pending_sheet_ids: [모든 시트 id], files: [], mode: '', note: '' }`
   - 모드는 서버가 정한다 (확정 전 재전달 = 전체 교체 — 2026-09-30 결정 "도면은 ERP 에 최종본만").
   - `transfer-pending` 대신 이것을 쓰는 까닭: 지운 시트의 옛 대기 도면이 같이 나가지 않게 지금 시트 id 만 보낸다.
4. `도면방 PUSH` 켬 → 4.1-4 와 같다.

### 4.3 공통 규칙

- **생산·시공 단계 (바로 반영)** 주문이면 전달 전에 확인창 하나: `생산·시공 단계라 영업 확인 없이 바로 최종 도면이 되고 생산팀에 알림이 갑니다. 전달 취소로 되돌릴 수 없습니다.` — 작업실 전달 창의 문구와 같다.
- 전달이 실패하면 PUSH 는 하지 않고, 저장은 됐다고 알린다: `저장은 됐어요 · 전달 못 함: <서버 사유>`. 서버 사유 예: 수정 요청이 아직 반영 완료가 아님, 교체할 도면 번호를 골라야 함 (돌려받은 주문에 새 장) — 이때는 `작업실 [전달하기] 에서 골라 주세요` 를 덧붙인다.
- 끝 알림은 한 줄: `저장했어요 · 영업에게 전달했어요 · 도면방에 올렸어요`.
- 전달 메모·교체 대상 고르기·직접 파일 올리기는 하지 않는다 — 필요하면 작업실 [전달하기] 창을 쓴다.

## 5. 서버 변경 (새 API 없음)

`foms/web/drawing/wizard.py` 의 `wizard_config` 에 세 값을 더한다:

| 키 | 값 | 출처 |
|---|---|---|
| `can_transfer` | 전달 권한 | `can_transfer_drawing(current_user, order)` (`foms/services/orders/erp_policy_permissions.py:127`) — 서버가 다시 검사하므로 화면 표시용 |
| `hotfix_stage` | 바로 반영 단계 | `is_drawing_hotfix_stage(order)` (`foms/services/orders/drawing_transfer.py:47`) |
| `is_partner` | 협력사 주문 | `bool(order.partner_org_id)` |

전달·PUSH 는 기존 `/transfer-drawing`·`/api/channel/push-manual` 를 그대로 부른다 — 권한·잠금·알림·스냅샷이 모두 기존 경로를 탄다.

## 7. 확인 방법

1. `python -c "import app; print('APP_OK')"`
2. `wizard_config` 세 값 시험 (권한 있음/없음 · 협력사 · 생산 단계)
3. `node --check static/js/drawing/save-send.js static/js/drawing/wizard.js`
4. 스테이징 `claude_master` 로 가상 주문 (`CLAUDE-TEST-`) 에서 실화면:
   저장만 / 저장+전달 / 저장+전달+PUSH / 일괄 저장+전달 (5장 중 다른 장이 그대로인지) / 돌려받은 주문 / 협력사 주문 (PUSH 칸 없음).
   - 주의: 스테이징 도면방은 운영 실제 방 (209990) 이다 — PUSH 시험은 사용자 허락 뒤 한 번만.
5. `scripts/ops/pre_push_smoke.ps1` exit 0 → deploy push → CI green.
