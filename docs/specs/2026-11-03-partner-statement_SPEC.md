## 0. 사용자 결정 (2026-11-03)

1. 이카운트와 연결하지 않는다. 거래명세서는 우리 ERP 가 이카운트 양식 모양으로(조사로 더 나은 칸을 더해) 직접 발행한다.
2. 하우드 도장은 견적서 도장(`static/images/company-stamp.png`)을 쓴다.
3. 자 수 = 가로 ÷ 300, **소수 둘째 자리에서 반올림**(12.33 → 12.3, 9.33 → 9.3).
4. 협력사는 금액을 **명세서가 발행된 뒤에만** 본다. 옵션 고르기 · 도면 확인 화면에는 금액이 없다.
5. 입금 확인 · 잔액 장부는 우리 ERP 가 갖는다.
6. 단가표는 사용자가 쓰던 "통합 단가표" 모양 그대로 우리 ERP 에서 고치고 저장한다(저장 = 새 판).
7. 제품이 여러 개인 주문은 명세서 한 장에 **제품마다 묶음 + 소계 + 제품별 최종 도면**.
8. **협력사가 옵션을 직접 고른다.** 단가표 품목 이름 목록에서 고르고, 없는 것은 "커스텀" 메뉴에 글 · 사진으로 적는다. 옵션 칸을 "사진참조"로만 끝낼 수 없다.
9. **내부 옵션은 기본 제품가에 녹였다.** 협력사 단가표에서 TYPE A~K(0원) · 깊이 줄임(값 빈칸)은 기본 가격에 포함이다. 명세서에 따로 줄을 만들지 않고 기본 제품 줄 비고에 "내부 A·A·J · 깊이 줄임 포함"으로 적는다. 협력사는 고르기는 한다(도면팀이 보는 정보).
10. 단가표 제품 이름 "TV 월플렉스, 침대 벽박이장"은 "침대 붙박이장"으로 바꿔 쓴다(11-03 사용자 — 협력사가 고르는 이름도 "침대 붙박이장"). 단가 자료는 DB 에만 있으므로 단가표를 불러온 뒤 편집기에서 이름을 고친다.

9. 출고 대시보드 = `foms/web/shipment/dashboard.py`(협력사 주문 필터 이미 있음).
10. 협력사 새 라우트는 문지기 허용 목록 `PARTNER_ALLOWED_ENDPOINTS`(`foms/services/auth/partner_scope.py:26`) + 매니페스트 2개(`docs/harness/foms_order_mutation_policy_manifest.json` · `docs/harness/foms_write_guard_manifest.json`)에 같이 넣는다.
11. **운영 실측(2026-11-03, 읽기 전용)**: 운영 협력사 1곳, 주문 34건(MEASURE 16 · DRAWING 10 · PRODUCTION 5 · 삭제 3). 품목 59개 중 내용을 적은 것 28개, 그중 **18개(64%)가 내부 · 옵션 칸에 "사진참조"**. 도면이 나간 8건 중 6건이 마법사 내보내기. 마법사 시트 7장: 자재표 계산 칸(`calc`) **0장**, `[마이다]`(서랍) 머리글 1장 · 빈칸, 옵션은 머리글 없는 글("LED" 등)로 흩어져 있다. → 도면이나 글에서 옵션을 자동으로 읽어 금액을 내는 길은 지금 자료로는 서지 않는다. 결정 8의 근거.

## 2. 설계 원칙

- **금액 = 확정 옵션 목록 × 단가표 판.** 사람은 숫자를 계산하지 않는다(커스텀 금액만 넣는다). 모델(AI)은 금액을 내지 않는다.
- **발행본은 스냅샷이고 잠긴다.** 단가표 판 · 도면 회차 · 줄 전부를 복사해 둔다. 고칠 일은 "수정본"으로 새 명세서를 낸다.
- **판정 축은 ID 칸.** 협력사 = `partner_org_id`, 단가표 줄 = 판이 바뀌어도 이어지는 줄 열쇠(`key`). 이름 글자로 맞추지 않는다.
- **주문 JSON 을 무겁게 하지 않는다.** 옵션 · 명세서 · 입금은 새 표에 둔다(1장 6번 · JSONB TOAST 비용).
- **우리 직원 화면 · 소비자 계산기는 바뀌지 않는다.** 대조군 시험으로 고정한다.

### 3.1 `partner_price_lists` — 단가표 판
| 칸 | 형 | 설명 |
|---|---|---|
| id | int PK | |
| partner_org_id | int FK partner_orgs | |
| version | int | 협력사 안에서 1, 2, 3 … (`unique(partner_org_id, version)`) |

| sheet | JSONB | 단가표 전체 — 카테고리(왼쪽/오른쪽 · 제목 · 열 · 칸 구성 · 폭) · 줄. 사용자 HTML 의 `<script id="data">` 모양을 받는다 |
| rules | JSONB | 자 수 반올림 자리 · 원 단위 · 번호 머리 |
| created_by / created_at | | |

줄(칸 목록) 하나에 품목이 하나(이름 · 금액) 또는 둘(이름 · 금액 · 이름 · 금액). 품목마다: `{key, name_col, price_col, role, unit, kind, cond, partner_label, pick_names, for_products, pickable}` — 이름 · 금액은 칸(`cells`)에만 둔다.
- `role`: `product`(협력사 제품명 ▾ 목록) · `option`(옵션 칸 목록). 불러올 때 "기본 제품 가격" 표와 가로 구간 줄(책상 · 오픈장)은 제품, 나머지는 옵션(1단계 구현 — 관리 화면에서 고친다).
- 불러오기(`POST …/import`)는 화면에 띄우기만 하고 저장하지 않는다. "저장 (새 판)"을 눌러야 판이 생긴다(DRAFT 상태는 지금 쓰지 않는다). 지금 판이 있으면 같은 이름 줄은 같은 열쇠를 다시 쓴다.
- `key`: 판이 바뀌어도 그대로 이어지는 짧은 열쇠. 새 판은 옛 판을 복사해서 만들고, 줄을 지우면 `pickable=false` 로 남긴다(옛 선택이 끊기지 않게).
- `unit`: 자 · m · 개 · 짝 · 통 · 식.
- `kind`: 계산 방법 — `included`(기본 포함 — 값이 빈칸 · 0원, 줄 없이 기본 줄 비고에) · `ja`(자 단가) · `meter`(m 단가) · `band`(크기 구간) · `over`(넘친 만큼, 100mm 당) · `count`(개수) · `fixed`(정해진 값 한 번).
- `cond`: 구간 조건(예: 가로 801~900 · 깊이 601~800) · `over` 의 기준 줄.
- `partner_label`: 협력사에게 보일 이름(내부 말 "마이다" 대신 "서랍" 등). 비면 첫 칸 이름.
- `pick_names`: **협력사가 고르는 이름 목록**(11-03 사용자 — 제품명은 하나씩 고를 수 있어야 한다). 단가표 한 줄에 이름 여러 개가 붙고 모두 그 줄 단가로 계산한다. 예: "여닫이 / 몰딩, 무몰딩" ← 몰딩 여닫이 · 무몰딩 여닫이, "여닫이 / 아라 시리즈" ← 아라 01 · 02 · 03 · 아라 투도어 01 · 02 · 03, "거울/유리도어 슬라이딩" ← 거울도어 슬라이딩 · 유리도어 슬라이딩. 비면 `partner_label` 하나. 고른 품목에는 이름과 줄 열쇠(`key`)를 함께 남긴다.
- `for_products`: 이 옵션 줄이 보이는 제품(`pick_names` 목록). 비면 모든 제품. 예: 침대 프레임 SS · Q · K · LK · 침대 헤드 템바보드 → **침대 붙박이장만**(11-03 사용자 — 침대 프레임은 제품이 아니라 침대 붙박이장의 옵션). 협력사 옵션 고르기 창은 그 품목 제품명에 맞는 줄만 보인다.

## 4. 계산 규칙 (순수 함수 하나 — `foms/services/partners/statement_calc.py`)

- **기본 제품 줄**: 품목 규격 줄마다 한 줄. 가로 = 그 줄 가로 칸의 숫자 합(복합 폭 `5700(2402+1864+1434)` 은 5700).
  - `ja`: 수량 = 가로 ÷ 300 을 소수 둘째 자리에서 반올림(0.5 는 위로). 금액 = 수량 × 단가.
  - `meter`: 수량 = 가로 ÷ 1000 을 소수 둘째 자리에서 반올림(같은 규칙 — 열린 질문 10).
  - `band`: 가로(또는 깊이)가 드는 구간 줄 하나. 가장 큰 구간을 넘으면 그 줄 + `over` 줄.
  - `over`: (가로 − 구간 최대) ÷ 100 올림.
- **옵션 줄**: 고른 줄 × 수. `count` 줄 중 측면 EP 처럼 폭 구간이 있는 것은 품목 깊이로 구간을 고른다.
- **기본 포함(`included`)**: TYPE A~K · 깊이 줄임처럼 값이 빈칸 · 0원인 줄은 명세서 줄을 만들지 않는다. 그 품목 기본 제품 줄 비고에 이름을 붙인다(예: "내부 A·A·J · 깊이 줄임 포함"). 판에서 값이 생기면(0 → 금액) 그 판부터 줄이 된다 — 규칙은 값으로만 판정한다.
- **커스텀**: 금액 빈 줄로 초안에 들어온다. CS 가 금액 · 사유를 넣는다. 사유는 협력사에게 보인다.
- **원 단위**: 줄 금액 = 반올림(수량 × 단가). 합계 = 줄 합. 공급가액 = 반올림(합계 ÷ 1.1), 세액 = 합계 − 공급가액. 단가는 VAT 포함으로 적는다.
- **취소 품목**(`is_item_cancelled`)은 묶음에서 뺀다.
- 금액 계산은 이 함수 하나뿐이다. 화면 JS 는 서버 값을 보여만 준다.

## 5. 화면

### 5.1 관리 — 단가표 편집기 (ADMIN, `/admin/partners/<org_id>/price-list`)
- 사용자 단가표 HTML 과 같은 모양: 로고 · 왼쪽/오른쪽 카테고리 · 열 · 줄 · 칸 구성 1~4 · 칸 폭. 편집하기 / 편집 종료 · 줄 추가 · 지우기 · 위아래 · 카테고리 좌우 이동 · 복제 · 인쇄.
- "단가표 HTML 불러오기": HTML 파일의 `<script id="data">` JSON 을 읽어 DRAFT 판으로 만든다(처음 한 번 + 백업 되살리기).
- 줄을 누르면 오른쪽 칸: 단위 · 계산 방법 · 조건 · 협력사에게 보일 이름 · **협력사가 고르는 이름들(`pick_names`, 한 줄에 여러 개)** · 협력사 목록에 보임.
- "저장" = 새 판(ACTIVE, 적용 시작일). 발행된 명세서는 옛 판 값을 그대로 갖는다.

### 5.2 협력사 — 새 주문 · 품목 고치기: **"옵션" 칸 하나만 고르는 칸으로** (2026-11-03 사용자 교정)
- **켜지는 조건(2단계 구현)**: 그 협력사에 단가표 지금 판(ACTIVE)이 있을 때만. 없으면 지금 그대로(제품명 ▾ 은 계산기 이름, 옵션은 글 칸) — 운영은 단가표를 저장하기 전까지 바뀌지 않는다. 고른 값 요약은 품목 `option_detail` 글에도 적어 우리 직원 · 도면팀 화면이 지금처럼 본다(정본은 표). 옵션 칸 검사는 새 스크립트(`partner-item-options.js`)가 저장 단추보다 먼저(캡처) 하고, 서버(`foms/services/partners/item_options.py`)가 다시 본다.
- 화면은 지금 협력사 새 주문(우리 erporder 틀) 그대로다. 제품 속성 다섯 칸 중 **옵션 칸만** 바뀐다. 내부 · 색상 · 손잡이 · 기타·설치는 지금처럼 글 칸.
  - 통 · 문 그림 · TYPE 칩 판 · 손잡이 칩 · 요약 상자를 넣은 안은 "쓸데없이 복잡 · 시인성 매우 떨어짐"으로 거절됐다.
- 옵션 칸을 누르면 우리 계산기의 여러 개 고르기 창(`ErpSpecPicker.openMulti`, 검색 · 묶음 · 체크)이 열린다. 목록 = 협력사 단가표 옵션 줄의 `partner_label`(금액 없음) + 맨 위 "옵션 없음" · "상담 후 정함" + 맨 아래 "커스텀 (직접 적기)".
- 고른 것은 옵션 칸 안에 한 줄씩: 이름 · 수(−/+) · 단위 · 위치(선택, 한 줄 글) · ×. 커스텀은 글 한 줄. 끝에 "+ 옵션 더 고르기". 휴대폰은 이름 · × 한 줄, 수 · 위치 다음 줄.
- **휴대폰(768px 미만) 제품 속성 다섯 칸은 두 줄**: 이름(내부 · 색상 · 옵션 · 손잡이 · 기타·설치)은 작은 글씨(11px)로 위, 입력 칸은 아래 한 줄을 꽉 채운다(11-03 사용자 — 이름이 왼쪽에 있으면 입력 칸이 너무 작다). 협력사 화면 CSS 에만 둔다(우리 직원 화면은 그대로).
- 제품명 ▾ 목록 = 단가표 기본 제품 줄의 `pick_names` 를 묶음별로 하나씩(몰딩 여닫이 · 무몰딩 여닫이 · 아라 01 … 따로). 지금 계산기 이름 목록을 대신하고, 고르기 창은 지금 것 그대로.
- **옵션 칸은 꼭 넣을 칸**: 비어 있으면 저장 때 그 품목으로 가서 빨간 테두리 + "옵션을 골라 주세요. 없으면 '옵션 없음'". "상담 후 정함"은 첫 도면 전까지 고칠 수 있고 도면 확인 때 꼭 골라야 확정된다.
- 사진은 지금처럼 붙인다(도면팀 참고). 고칠 수 있는 때는 지금 규칙(`partner_edit_open`). 저장하면 PARTNER · CURRENT 두 줄을 함께 쓴다.

### 5.3 우리 도면팀 — 도면 전달 창에 "옵션 확인"
- 품목마다 CURRENT 옵션 목록을 보여 주고 고칠 수 있게 한다(같은 고르기 부품). 바꾼 줄은 까닭 한 줄 필수.
- `state = later` 인 품목이 있으면 "옵션이 아직 안 정해진 품목이 있어요" 경고(전달은 막지 않음 — 협력사가 도면 확인 때 고른다).
- 전달 처리(1장 5번)와 같은 트랜잭션에서 CURRENT 를 저장한다.

### 5.4 협력사 — 도면 확인
- 도면 아래 "옵션" 칸: CURRENT 목록 + PARTNER 원문과 다른 줄은 "바뀐 옵션"(까닭 함께). `later` 품목은 여기서 고르게 한다.
- "도면 · 옵션 이대로 만들어 주세요" = 지금 `approve_partner_drawing` + 같은 트랜잭션에서 CURRENT → CONFIRMED 복사, 감사 기록에 옵션 지문(sha256)과 도면 회차.
- "수정 요청"은 지금 그대로.

### 5.5 우리 CS — 발행 대기 · 명세서 만들기 (`/erp/partner-statements`)
- 목록: 도면 확정(CONFIRMED 있음) 주문, 출고일 가까운 순. 묶음 = 내일 출고 · 다음 출고 · 출고일 없음. 초안 상태 = 자동 완성 / 커스텀 금액 필요. "자동 완성만 한꺼번에 발행".
- 명세서 화면: 왼쪽 확정 도면(제품별 탭), 오른쪽 묶음별 줄(자동 줄은 글자 · "고치기", 커스텀 줄만 금액 칸). 단가를 고치면 원래 값 · 사유가 남는다(`edited`).
- 발행: 일자(출고일) · 번호 · 잠금 · 잔액 스냅샷 · 협력사 화면에 보임. 수정본 · 취소(VOID)는 사유 필수.

### 5.6 협력사 — 거래명세서 메뉴
- 월 장부: 지난달 이월 · 이달 판매 · 이달 입금 · 지금 잔액. 줄 = 일자 · 문서번호 · 고객(현장) · 제품 수 · 판매 · 입금 · 잔액 · 상태(새 명세서 · 확인함 · 입금 대기 · 수정본). 제품 여러 개 주문은 ▾ 로 제품별 금액. 엑셀 받기.
- 명세서 보기: 양식(5.8) + 오른쪽 제품별 최종 도면 + "명세서 확인했어요" + "금액 문의"(줄 골라 묻기) + 인쇄(공급받는자용 · 공급자용 2장) · PDF(브라우저 인쇄). 휴대폰은 제품 묶음 접기 · 입금 계좌 복사.
- 주문 화면에도 "거래명세서" 탭.

### 5.7 입금 · 출고
- CS 입금 기록 화면: 날짜 · 금액 · 메모 · 명세서 맞추기. 지우기는 사유 필수.
- 출고 대시보드(1장 9번): 협력사 주문 카드에 "입금 대기"(그 명세서 입금이 다 맞지 않았으면). 막지는 않고 표시만.

### 5.8 양식 칸 (이카운트 양식 + 조사로 더한 것)
문서번호 · 발행일 · 출고일 · 담당자 · 쪽 · QR(온라인 원본) · 공급받는자 / 공급자 블록(등록번호 · 상호 · 성명 · 주소 · 업태 · 종목) · 도장 · 합계 금액(한글 + 숫자) · 공급가액 / 세액 · "단가는 VAT 포함" · 현장(고객) · 주문번호 · 최종 도면 회차 · 제품 묶음 · 소계 · 0원 기본 구성 줄 · 계산 근거 칸 · 전일 잔액 / 판매 합계 / 금일 잔액 · 입금 계좌 · 입금 기한(출고 전날 16:00) · 받는 쪽 확인(누가 · 언제, 온라인) · 세금계산서 발행 안내 · 주의 문구 · 공급받는자용 / 공급자용.

## 6. 권한

## 10. 남는 위험

- 협력사 입력이 늘어난다 → 거부감. 공지 + "상담 중(나중에 고름)" + 위치 메모로 사진 습관을 살린다.
- 도면팀이 옵션 고치기를 잊음 → 협력사 도면 확인의 "바뀐 옵션"이 마지막 그물. 전달 창에서 옵션 확인 체크를 필수로 할지는 3단계에서 실화면으로 정한다.

- 저장소 공개: 단가 · 업체 정보는 DB 에만 둔다. 시험 자료는 가짜 값.
- 같은 날 순번 번호가 겹치는 경합 → 번호는 발행 트랜잭션 안에서 협력사 · 날짜 줄을 잠그고 낸다.
