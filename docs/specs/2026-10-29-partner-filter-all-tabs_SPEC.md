# 협력사 필터 전 탭·모바일 확장 Spec

> 작성일: 2026-10-29 | 범위: 사용자 추가 요청으로 확정 — ERP 각 탭·모바일, 성능 회귀 차단

## 1. What

- 기존 협력사 ID 선택을 ERP 10탭(대시보드·실측·도면·생산·출고·AS·시공·완료·정산·이력)에 적용한다.
- 선택한 탭을 유지하며 회사를 바꾼다. 내 담당·검색·날짜·단계 조건과 교집합이다.
- 목록뿐 아니라 KPI·단계 수·날짜 패널·칸반·취소 카드·완료 JSON/CSV·정산 조회도 같은 범위로 제한한다.
- 모바일 상단에 악수 버튼을 추가하고 기존 긴급 호출·내 작업·검색·알림·더보기 기능을 유지한다.
- 필터 해제 시 종전 동작을 보존한다. 기존 권한·시공팀 본인 주문 제한·쓰기 API는 유지한다.

## 2. How

- `partner_order_filter.py`의 정규화·indexed FK 조건을 재사용한다. JSONB 회사명 조회·추가 N+1은 금지한다.
- 각 탭의 원본 쿼리에서 count/페이지/집계 이전에 조건을 적용한다. focus 행과 보조 모집단도 포함한다.
- 서버 캐시와 생산 렌더 전 키에 **실제 선택값**을 넣어 회사 간 결과 재사용을 막는다.
- 필터가 꺼졌을 때 기존 쿼리·캐시 경로에 추가 DB 왕복을 만들지 않는다.
- 모바일 메뉴 데이터는 같은 요청에서 한 번만 읽어 PC/모바일이 공유한다. fragment에서
  쓰지 않는 메뉴 목록을 읽지 않도록 lazy 평가를 유지한다.
- 회사 전환은 full navigation으로 클라이언트 캐시를 초기화한다. 단순 탭 이동은 기존 셸 캐시를 유지한다.
- 정산은 페이지 HTML뿐 아니라 실제 데이터 로더/API까지 추적한다. 권한/금액 계산식은 변경하지 않는다.
- DB 마이그레이션·새 주기 폴링·무조건 전역 캐시 무효화는 추가하지 않는다.

## 6. 구현·검증 기록

- 모든 탭의 원본 SQL에 `orders.partner_org_id` 조건을 추가했다. 실측 전달 원본/기준 주문,
  별도 focus, 생산 취소 카드/지문, 완료 API/CSV, 정산 단계별 금액까지 같은 범위다.
- 정산의 네이버 채널 원장은 협력사 축이 없는 전체 자료다. 선택 중에는 상시 안내를
  표시하고 채널 GET/CSV/진행 조회를 차단한다. 기존 권한과 쓰기 정책은 유지한다.
- 전역 네이버 발송 작업 띠도 선택 중에는 조회/표시하지 않는다(협력사 주문 작업과
  채널 전체 작업의 범위 혼동 방지). 필터 해제 시 기존 화면을 복원한다.
- 모바일 헤더 버튼은 기존 조직 목록을 복제한 Bootstrap 시트를 연다. 전체 HTML의
  조직 목록 쿼리는 1회, fragment는 0회임을 실제 SQL 기록으로 검증했다.
- 신규 회귀 19개: 2회사+일반 주문, 회사 전환/쿠키/foreign focus, 실제 캐시 재사용,
  완료 API, 정산 세 로더 SQL/금액/쿼리 수, API 및 모바일 컨트롤/쿼리 수.
- 타깃 검증 229개 통과. perf guard 신규 high/medium 0. 독립 전 탭 소스 리뷰 완료.
- 변경 전 공식 PC/태블릿 성능 게이트 PASS. 같은 가상 주문 18건으로 13경로 전후 측정 준비.
- staging PostgreSQL EXPLAIN (ANALYZE, BUFFERS): 활성 주문·최근 ERP·생산 쿼리 모두
  Index Scan, Seq Scan 0. 각각 0.174/0.070/0.110ms (단일 샘플, 네트워크 제외).
- 전체 smoke, 실제 staging 모바일/전 탭 및 배포 후 성능 비교는 다음 검증 단계다.
