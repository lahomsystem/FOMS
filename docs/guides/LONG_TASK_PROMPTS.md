# 작업 크기별 공통 프롬프트 (복붙 템플릿)

> 2026-07-28 작성. `<>` 자리만 채워 쓴다. 배경 스택: SDD 프로토콜(전역 CLAUDE.md, 상시) + CTX-GATE 훅(55% 자가정리) + `/overnight` 스킬 + AI_STATUS 40줄 계약. 설계 근거: `docs/specs/2026-07-28-context-ledger-hygiene-design.md`

## 크기 판정

| 작업 크기 | 시키는 법 |
|---|---|
| 1~2시간 | ① 그냥 시켜 — 프로토콜이 위임·검증 |
| 하루 | ② 플랜+ledger 만들게 하고 한 세션 완주, 55%에서 compact 1회 |
| 며칠~몇 주 | ③ 설계 1세션 → 플랜+ledger → 낮 릴레이+밤 `/overnight` → 아침 검수 반복 |
| 위험·불확실 큼 | ④ = ③ + 설계 전 CEO/3-agent 리뷰 + 무인 전 파일럿 1개 |

## ① 1~2시간 — 소형

```
<수정할 것>.
대상: <파일/화면/기능 — 아는 만큼>.
완료 기준: <이게 되면 끝 — 예: OO 화면에서 OO 동작, 관련 테스트 green>.
```

파일 모르면 "대상:" 줄 생략 가능(탐색 토큰 약간 추가).

## ② 하루 — 한 세션 완주

```
아래 작업을 플랜 파일+progress ledger로 만들고, 내 승인 후 이 세션에서 완주해.
작업: <무엇을 왜>
범위: <포함> / 제외: <건드리지 말 것>
완료 기준: <검증 명령 또는 확인 방법>
task마다 완료 기준 명시하고, 구현은 서브에이전트 위임, 검증 후 task 단위 커밋.
```

중간에 CTX-GATE 뜨면 1회:

```
/compact <지금 작업> 관련만 남기고 탐색 로그 버려
```

## ③ 며칠~몇 주 — 세션 릴레이

### A. 설계 세션 (첫날 저녁)

```
큰 작업 설계하자.
목표: <최종 상태를 한 문단으로>
배경: <왜 하는지, 알려진 제약>
결과물: docs/specs 스펙 + docs/plans 실행 플랜 + progress ledger.
플랜의 각 task는 한 세션 크기로 쪼개고, task마다 완료 기준(검증 명령)·대상 파일·경계를 명시해.
검증 불가능한 task는 넣지 마. 다 되면 요약 보여주고 내 승인 받아.
```

### B-1. 낮 재개 (매 세션 첫 프롬프트)

```
docs/plans/<플랜파일>.md 와 ledger 읽고 <T번호>부터 이어서.
구현은 서브에이전트 위임, task마다 검증→커밋→ledger 갱신.
막히면 BLOCKED 기록하고 다음 task 진행.
```

### B-2. 밤 무인 (퇴근 전)

```
/overnight docs/plans/<플랜파일>.md의 <T번호>~<T번호> 실행
```

### C. 아침 검수

```
OVERNIGHT_REPORT(또는 ledger)와 git log 기준으로 밤 작업 요약해.
BLOCKED 항목은 원인 원문과 권장 다음 수 포함. CI 상태(gh run list, perf-gate 포함)도.
```

### 세션 교체 (작업 단위 끝날 때)

```
/clear <작업명>
```

## ④ 위험·불확실 큼 — ③에 앞단 추가

### A-0. 설계 전 도전 (A 치기 전)

```
/gstack-plan-ceo-review <작업 한 줄 요약>
```

```
이 설계를 3개 리뷰 에이전트로 교차 체크해:
①반증 전담(실물 코드로 깨뜨리기) ②단순화 심판(지울 것 찾기) ③사실 검증(전제 팩트체크).
finding은 네가 직접 재검증한 뒤 설계에 반영해.
```

### 파일럿 (무인 투입 전)

```
플랜에서 제일 작은 task 1개만 지금 실행해 봐. 지켜본다.
위임→검증→커밋 흐름이 플랜대로 도는지 확인 목적.
```

파일럿 통과 후 B-2 무인 투입.

## 공통 마무리 (모든 크기)

```
production 승격            ← 스테이징 검증 끝났을 때만, 명시적으로 (cherry-pick 기본)
docs/AI_STATUS.md 진행 중 섹션 최신화해   ← 큰 단위 끝날 때 (hygiene 계약 테스트가 감시)
```

## 1회 준비 (밤샘 무인용)

```
/fewer-permission-prompts   ← allowlist 생성. 권한 프롬프트로 밤에 멈추는 것 방지
```

## 운영 원칙 요약

- 세션은 소모품, **파일(플랜·ledger·AI_STATUS·git)이 본체** — 방향 수정은 대화가 아니라 플랜 파일을 고쳐라
- 작업 단위 끝 = `/clear` — 압축 반복(요약의 요약)보다 항상 우월
- statusline 55%+ = 정리 시점(CTX-GATE가 자동으로도 알림)
- `/goal`은 지속 보강, `/loop`는 주기 감시 — 품질은 SDD 프로토콜·훅·CI 계약이 담당
