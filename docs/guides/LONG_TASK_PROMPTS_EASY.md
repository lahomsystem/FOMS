# 작업 시키는 법 — 아주 쉬운 해설판

> `LONG_TASK_PROMPTS.md`(복붙용 원본)의 각 명령어·문장이 **왜 그렇게 생겼는지**까지 풀어쓴 해설. 처음 보는 사람용.

## 먼저 이해할 것: Claude의 공책 한 권

Claude는 아주 똑똑한 일꾼인데 **기억 공책이 딱 한 권**이다(= 컨텍스트).
- 대화·읽은 파일·실행 결과가 전부 이 공책에 적힌다
- 공책이 다 차면 앞장을 요약하고 지워야 한다(= compact) — 이때 세세한 기억이 흐려진다
- **그래서 중요한 건 공책이 아니라 "종이에 따로 적어두기"** — 계획표(플랜 파일), 체크리스트(ledger), 저장(커밋). 종이는 안 지워진다

일 시키는 요령 전부가 이 한 문장에서 나온다: **"공책은 아끼고, 중요한 건 종이에."**

---

## ① 짧은 일 (1~2시간) — 심부름 쪽지

```
견적서 탭에서 할인율 입력하면 합계가 안 바뀌는 것 고쳐줘.
대상: templates/erp/estimate 쪽, static/js/orders 쪽으로 추정.
완료 기준: 할인율 10 입력 시 합계 즉시 갱신 + 관련 테스트 green.
```

| 줄 | 왜 쓰나 |
|---|---|
| 1줄: 뭘 고칠지 | 당연히 필요. **증상**을 적어라("느려" 말고 "할인율 넣어도 합계 그대로") |
| `대상:` | 어딜 고칠지 힌트를 주면 일꾼이 **온 집을 뒤지지 않는다**(공책 절약). 모르면 빼도 됨 — 대신 찾느라 공책 몇 장 씀 |
| `완료 기준:` | **"이게 되면 성공"을 미리 정해주는 것.** 그러면 일꾼이 스스로 시험 쳐보고 통과해야 "다 했다"고 말한다. 이 줄이 없으면 "다 했어요" 했는데 안 되어 있는 사태가 생긴다 |

## ② 하루짜리 일 — 계획표 먼저, 세이브 자주

```
아래 작업을 플랜 파일+progress ledger로 만들고, 내 승인 후 이 세션에서 완주해.
작업: 출고 대시보드에 차량별 그룹 보기 추가 (배차 확인이 느려서)
범위: 출고 대시보드만 / 제외: 생산·시공 대시보드는 손대지 마
완료 기준: 그룹 토글 동작 + pytest tests/domains 출고 테스트 green
task마다 완료 기준 명시하고, 구현은 서브에이전트 위임, 검증 후 task 단위 커밋.
```

| 문구 | 무슨 의미인가 |
|---|---|
| `플랜 파일+ledger로 만들고` | 계획표와 체크리스트를 **종이(파일)에** 적게 한다. 공책(기억)이 지워져도 종이는 남아서, 중간에 무슨 일이 생겨도 이어갈 수 있다 |
| `내 승인 후` | 계획을 먼저 보여달라 = **잘못된 방향으로 하루 종일 일하는 것 방지.** 색칠 전에 밑그림 검사 |
| `범위 / 제외` | 하라는 것만 해라. "청소해" 하면 옆 방까지 치우는 사고 방지 — 손대면 안 되는 곳을 미리 봉인 |
| `작업: ... (배차 확인이 느려서)` | 괄호의 "왜"가 중요 — 이유를 알면 일꾼이 중간 판단을 네 의도대로 한다 |
| `구현은 서브에이전트 위임` | 대장 일꾼이 직접 삽질하지 않고 **부하 일꾼들에게 시킨다.** 부하는 각자 새 공책을 갖고 와서 일하고 결과만 보고 → **대장 공책이 안 닳는다.** 이게 긴 작업의 최대 비결 |
| `task 단위 커밋` | 한 단계 끝날 때마다 저장 = **게임 세이브.** 뭐가 잘못돼도 마지막 세이브로 돌아가면 된다 |

공책이 절반 넘게 차면(화면 하단 게이지 55%+) 자동 알림이 온다. 그때:

```
/compact 출고 그룹 보기 작업 관련만 남기고 탐색 로그는 버려
```
→ `/compact` 뒤의 말 = **"요약할 때 이건 꼭 남겨"라는 지시.** 말 안 붙이면 일꾼이 알아서 추측으로 요약하는데, 네 다음 계획을 모르니 필요한 걸 버릴 수 있다.

## ③ 며칠~몇 주 — 일꾼 릴레이

핵심 발상: **일꾼(세션)을 갈아끼운다.** 어제의 일꾼과 오늘의 일꾼은 남남 — 대신 계획표·체크리스트·세이브가 이어준다. 일꾼을 오래 쓰면 공책이 요약의 요약이 돼서 멍청해진다.

### A. 첫날 저녁 — 설계만 시킨다 (아직 코딩 금지)

```
큰 작업 설계하자.
목표: AS 처리 전 과정을 태블릿에서 끝낼 수 있게 한다 (사무실 복귀 없이)
배경: 현장 기사들이 PC로만 입력 가능해 저녁에 몰아서 입력, 누락 잦음
결과물: docs/specs 스펙 + docs/plans 실행 플랜 + progress ledger.
플랜의 각 task는 한 세션 크기로 쪼개고, task마다 완료 기준(검증 명령)·대상 파일·경계를 명시해.
검증 불가능한 task는 넣지 마. 다 되면 요약 보여주고 내 승인 받아.
```

| 문구 | 왜 |
|---|---|
| `한 세션 크기로 쪼개` | 일꾼 한 명(공책 한 권)이 끝낼 수 있는 조각으로 썰어라. 조각이 크면 중간에 공책이 차서 품질 하락 |
| `검증 불가능한 task는 넣지 마` | **시험 문제 없는 숙제는 했는지 확인할 방법이 없다.** "코드 개선" 같은 건 task가 아님 — "OO 테스트 통과"여야 함 |
| `경계를 명시` | 각 조각마다 "여긴 손대지 마"를 미리 — 부하 일꾼들이 서로 같은 파일을 고치다 충돌하는 것 방지 |

### B-1. 낮에 이어서 — 매번 새 일꾼에게 이 한 장

```
docs/plans/2026-07-29-as-tablet-plan.md 와 ledger 읽고 T5부터 이어서.
구현은 서브에이전트 위임, task마다 검증→커밋→ledger 갱신.
막히면 BLOCKED 기록하고 다음 task 진행.
```

| 문구 | 왜 |
|---|---|
| `플랜과 ledger 읽고 T5부터` | 새 일꾼은 아무것도 모른다 — **계획표를 읽으면 5분 만에 전임자 수준이 된다.** 어제 대화를 설명할 필요 없음 |
| `막히면 BLOCKED 기록하고 다음` | 안 풀리는 문제 하나를 붙잡고 밤새지 마라 — **별표 치고 다음 문제.** 막힌 이유가 기록되니 아침에 사람이 판단 |

### B-2. 퇴근 전 — 밤샘 무인

```
/overnight docs/plans/2026-07-29-as-tablet-plan.md의 T8~T14 실행
```
→ 이 한 줄이 하는 일: 안전점검 → 계획 요약을 보여주고 **딱 한 번 승인 질문**(커밋까지만? push까지?) → 밤새 자율 실행 → 아침 보고서(`OVERNIGHT_REPORT.md`). 승인 후엔 질문 안 하고 애매하면 가정을 기록하고 진행한다.

사전 준비 1회: `/fewer-permission-prompts` — "이 명령 실행해도 돼요?" 팝업 허락 목록을 만들어 둔다. 안 하면 밤에 팝업 하나로 아침까지 멈춤.

### C. 아침 — 검사

```
OVERNIGHT_REPORT와 git log 기준으로 밤 작업 요약해.
BLOCKED 항목은 원인 원문과 권장 다음 수 포함. CI 상태(gh run list, perf-gate 포함)도.
```
→ 숙제 검사. BLOCKED(별표 문제)만 사람이 판단해주면 된다.

### 일 단위 끝날 때마다

```
/clear as-태블릿-1주차
```
→ **공책을 새로 편다.** 뒤의 이름 = 옛 공책 표지에 제목 붙이기 — 나중에 `/resume` 목록에서 바로 찾는다. 이름 없이 `/clear`만 하면 무제 공책이 쌓여 못 찾는다.

## ④ 위험하거나 불확실한 일 — 검사 3번 더

### 설계를 선생님 3명에게 검사받기 (설계 세션 전에)

```
/gstack-plan-ceo-review AS 태블릿 전환 — 방향 자체가 맞는지
```
```
이 설계를 3개 리뷰 에이전트로 교차 체크해:
①반증 전담(실물 코드로 깨뜨리기) ②단순화 심판(지울 것 찾기) ③사실 검증(전제 팩트체크).
finding은 네가 직접 재검증한 뒤 설계에 반영해.
```

| 선생님 | 하는 일 |
|---|---|
| ① 반증 | **트집쟁이** — "이 설계 이래서 안 돼"를 실제 코드 열어보며 증명 시도. 살아남은 설계만 튼튼 |
| ② 단순화 | "이거 꼭 필요해? 더 간단하게 안 돼?" — 과잉 설계 사냥 |
| ③ 사실 검증 | 설계가 깔고 있는 전제("OO 기능이 지원된다")가 진짜인지 문서로 확인 |
| `직접 재검증` | **선생님들 말도 그대로 믿지 말고** 대장이 다시 확인 — 리뷰어도 틀린다 |

### 무인 투입 전 연습 1판

```
플랜에서 제일 작은 task 1개만 지금 실행해 봐. 지켜본다.
위임→검증→커밋 흐름이 플랜대로 도는지 확인 목적.
```
→ 본게임(밤샘) 전에 튜토리얼 1판. 여기서 부러지는 걸 고치고 무인 투입.

## 자주 쓰는 명령어 — 뒤에 붙는 말의 의미까지

| 명령 | 쉬운 뜻 | 뒤에 붙는 말의 의미 |
|---|---|---|
| `/clear 이름` | 새 공책 펴기 | `이름` = 옛 공책 표지 제목. `/resume`에서 찾을 때 씀 |
| `/compact 남길것` | 공책 앞장 요약해서 자리 만들기 | `남길것` = 요약할 때 지우면 안 되는 것 지정. **항상 붙여라** |
| `/resume` | 옛 공책 다시 펴기 | 목록에서 골라 그 대화로 복귀 |
| `Esc` | "잠깐 멈춰!" | 방향 틀렸다 싶으면 즉시. 늦을수록 낭비 |
| `Esc Esc` (rewind) | 지우개 — 과거 지점으로 점프 | 메뉴에서 선택: 코드만/대화만/둘 다 되돌리기, 또는 특정 구간만 요약 |
| `/goal 조건` | "이거 될 때까지 퇴근 금지" | `조건` = 검증 가능해야 함("테스트 전부 green"). 해제는 `/goal clear` |
| `/overnight 플랜의 T범위` | 밤샘 무인 근무 지시 | 플랜 경로+task 범위. 승인 1회 후 아침 보고서까지 자율 |
| `Shift+Tab` (plan mode) | "만지지 말고 계획만 세워 와" | 코드 수정 없이 탐색·계획 → 승인 후 실행 |
| `& 프롬프트` | "이건 뒤에서 따로 해놔" | 백그라운드 일꾼에게 던지고 나는 딴 일 |
| `! 명령` | 내가 직접 터미널 치기 | 결과가 대화에 들어와 일꾼도 본다 |
| `/context` | 공책 얼마나 찼나 보기 | 화면 하단 게이지가 상시 버전 |

## 한 문장 요약

**공책(세션)은 아끼고 갈아끼우되, 계획표·체크리스트·세이브(파일·커밋)에 모든 것을 남겨라 — 그리고 시킬 때마다 "완료 기준" 한 줄을 붙여라.**
