# 네이버 주문 자동 수집 — 사람이 직접 해야 하는 준비 (T0)

**이 문서 한 장만 따라 하면 준비가 끝난다.** 코드는 이미 다 만들어져 배포돼 있고,
여기 적힌 4가지(시크릿 · IP · 환경변수 · 확인)만 사람이 화면에서 눌러 주면 수집이 시작된다.

- 대상: 스테이징(FOMS-DEV) 먼저 → 잘 되면 운영(FOMS)
- 걸리는 시간: 20~30분
- 준비물: 네이버 커머스API센터 로그인 계정, Railway 로그인 계정
- 관련 문서: 원장 `docs/plans/2026-08-13-naver-order-ingest-ledger.md`, 스펙 `docs/specs/2026-08-13-naver-order-ingest_SPEC.md`

---

## 왜 이 4가지가 필요한가 (1분 요약)

네이버는 "**등록된 IP 에서, 맞는 열쇠로**" 부르는 요청만 받아 준다.

- **열쇠** = 애플리케이션 ID + 시크릿 → Railway 환경변수에 넣어 준다.
- **IP** = 우리 서버가 밖으로 나갈 때 쓰는 주소 → Railway 에서 고정 IP 를 켜고, 그 IP 를 네이버에 등록한다.
- 네이버 IP 등록 칸은 **딱 3개**다. Railway 고정 IP 도 **3개**. 그래서 **사무실 IP 는 지우고 3개를 이걸로 채운다**(여유 0).
- 수집은 **WORKER 서비스에서만** 나간다. 웹 서버에서 나가면 IP 가 달라 네이버가 막는다.

---

## 1단계 — 커머스API센터에서 시크릿 다시 받기

> 왜: 2026-08-13 시험 중에 예전 시크릿이 기록에 노출됐다. 노출된 열쇠는 버리고 새로 받는다.

1. https://apicenter.commerce.naver.com 접속 → 로그인.
2. 위쪽 메뉴에서 **애플리케이션 관리** (이름이 "내 애플리케이션"일 수도 있다) 클릭.
3. 우리 앱(FOMS 주문 수집용)을 고른다.
4. **애플리케이션 ID**를 복사해서 메모장에 붙여 둔다. → 나중에 `NAVER_COMMERCE_CLIENT_ID`
5. **시크릿 재발급** 버튼을 누른다. 새 시크릿이 화면에 뜬다.
6. 새 시크릿을 복사해서 메모장에 붙여 둔다. → 나중에 `NAVER_COMMERCE_CLIENT_SECRET`
   - **주의 1**: 시크릿은 이 화면을 벗어나면 다시 못 본다. 지금 복사해 둔다.
   - **주의 2**: 시크릿은 반드시 `$2` 로 시작한다(예: `$2a$04$...`). 아니면 잘못 복사한 것이다.
   - **주의 3**: 이 값은 **저장소(코드)에 절대 적지 않는다.** Railway 환경변수에만 넣는다.
   - **주의 4**: PowerShell 창에 큰따옴표로 붙여넣으면 `$2a` 부분이 변수로 바뀌어 값이 깨진다.
     붙여넣기는 Railway 화면 입력칸에 직접 하거나, 터미널이면 작은따옴표(`'...'`)를 쓴다.
7. 같은 화면에서 **만료일**(유효기간)을 확인해 메모해 둔다. → 나중에 `NAVER_COMMERCE_APP_EXPIRES_ON`

---

## 2단계 — Railway 에서 WORKER 고정 IP 켜기

> 왜: 네이버에 등록할 IP 3개를 얻기 위해서. **web 이 아니라 worker 서비스**에 켜야 한다.

1. https://railway.app 접속 → 로그인.
2. 프로젝트를 고른다.
   - 연습(스테이징) = **FOMS-DEV**
   - 진짜(운영) = **FOMS**
   - **여기서 자주 실수한다.** 프로젝트 이름을 눈으로 한 번 더 확인한다.
3. 그 프로젝트 안에서 **worker** 서비스를 클릭한다(웹 서비스 아님).
4. **Settings** 탭 → **Networking** 항목 → **Static Outbound IP** 를 **켠다(Enable)**.
5. 켜면 IPv4 주소 **3개**가 표시된다. 3개 모두 메모장에 복사한다.
   - 예: `203.0.113.10`, `203.0.113.11`, `203.0.113.12`
6. 켠 뒤에는 서비스가 한 번 다시 뜬다(redeploy). 1~2분 기다린다.

---

## 3단계 — 그 IP 3개를 커머스API센터에 등록(교체)

> 왜: 네이버는 등록된 IP 에서 온 요청만 받는다. 칸이 3개뿐이라 **기존 사무실 IP 는 지운다**.

1. 커머스API센터 → 우리 앱 → **호출 IP 관리**(또는 "IP 주소 관리") 화면.
2. 지금 등록돼 있는 IP 를 **전부 삭제**한다(사무실 IP 포함).
3. 2단계에서 메모한 Railway IP 3개를 **하나씩 추가**한다.
4. 저장 후 화면을 새로고침해서 **3개가 정확히 그대로** 들어갔는지 눈으로 대조한다.
   - 숫자 하나만 틀려도 수집이 통째로 막힌다.

---

## 4단계 — Railway 환경변수 넣기

Railway → 해당 프로젝트 → **worker** 서비스 → **Variables** 탭 → 아래 값을 추가한다.

| 변수 이름 | 넣을 값 | 설명 |
|---|---|---|
| `NAVER_COMMERCE_CLIENT_ID` | 1단계에서 복사한 애플리케이션 ID | 열쇠 앞부분 |
| `NAVER_COMMERCE_CLIENT_SECRET` | 1단계에서 새로 받은 시크릿(`$2`로 시작) | 열쇠 뒷부분 |
| `FOMS_NAVER_SYNC_ENABLED` | `1` | 자동 수집 켜기(안 넣으면 꺼진 상태) |
| `FOMS_NAVER_SYNC_INTERVAL_SECONDS` | `300` | 5분마다 확인(생략 가능, 기본값이 300) |
| `NAVER_COMMERCE_APP_EXPIRES_ON` | 1단계에서 본 만료일 `YYYY-MM-DD` | 만료 7일 전부터 관리자에게 알림(생략 가능) |

- **worker 서비스에만** 넣는다. web 에 넣어도 수집은 web 에서 돌지 않는다.
- 저장하면 worker 가 다시 뜬다. 1~2분 기다린다.

---

## 5단계 — 잘 됐는지 확인하기

1. 브라우저에서 관리 화면을 연다.
   - 스테이징: `https://lahom-dev.up.railway.app/admin/naver-ingest`
   - 운영: `https://<운영주소>/admin/naver-ingest`
   - 관리자(ADMIN) 계정으로 로그인해야 보인다.
2. 오른쪽 위 **"지금 수집"** 버튼을 누른다.
3. 잠시 뒤 화면을 새로고침한다.

**성공 신호**

- "마지막 실행" 카드가 **성공**으로 바뀌고, 확인한 주문 건수가 뜬다.
- 결제완료된 새 주문이 있었다면 아래 이력 표에 줄이 생긴다.

**실패 신호와 뜻**

| 화면에 뜨는 말 | 뜻 | 할 일 |
|---|---|---|
| `NAVER_COMMERCE_CLIENT_ID / NAVER_COMMERCE_CLIENT_SECRET 가 설정되지 않았다` | 4단계 환경변수가 안 들어갔다 | worker 서비스 Variables 다시 확인 |
| 시크릿이 `$2` 로 시작하지 않는다는 오류 | 시크릿을 잘못 복사했다 | 1단계 재발급부터 다시 |
| 401 / 인증 실패 | 열쇠가 틀렸다 | ID·시크릿 다시 복사해 넣기 |
| 403 / IP 관련 오류 | 네이버에 등록된 IP 와 실제 나가는 IP 가 다르다 | 3단계 IP 3개 다시 대조 |
| `미배정 보류함 계정이 없다: naver_unassigned` | 그 환경 DB 에 시스템 계정이 없다 | 아래 "계정 만들기" 참고 |

## 계정 만들기 (스테이징은 이미 완료, 운영은 아직)

수집 주문은 사람이 아직 안 정해졌으므로 **보류함 계정**이 임시 주인이 된다.

- 스테이징(FOMS-DEV): **이미 만들어져 있다** — `naver_ingest_bot`(id 62), `naver_unassigned`(id 63).
- 운영(FOMS): **아직 없다.** 운영에 넣기로 결정하면 그때 아래 명령을 운영 DB 를 향해 1회 실행한다(여러 번 돌려도 안전).

```bash
python scripts/maintenance/create_naver_ingest_accounts.py
```

두 계정 다 사람이 로그인할 수 없게 난수 비밀번호로 잠겨 있다.

---

## 수집된 주문은 어디서 보나

- **수집 이력·원본 보기**: `/admin/naver-ingest`
- **사람이 확인하고 담당자 지정**: `/admin/naver-ingest/triage`
  - 왼쪽에 확인 대기 목록, 오른쪽에 네이버 원본과 FOMS 값 대조표.
  - 담당자를 고르면 보류함에서 그 사람에게 넘어간다.
- **주문 대시보드**: 담당자가 아직 안 정해진 수집 주문은 담당 칸에 **`담당 미지정`** 노란 뱃지가 뜬다.

---

## 잠깐 멈추고 싶을 때

Railway worker 서비스의 `FOMS_NAVER_SYNC_ENABLED` 를 `0` 으로 바꾸면 자동 수집이 멈춘다
(코드 배포 없이 껐다 켤 수 있다). 관리 화면의 "지금 수집" 버튼은 그래도 동작한다.
