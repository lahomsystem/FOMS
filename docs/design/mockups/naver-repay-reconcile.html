6. 이 설계가 지키는 규칙

되돌릴 수 있는 것 먼저 붙이기 → ERP 처리 → 네이버 취소. 불가역을 맨 끝에 둬서 중간에 멈춰도 손실이 최소다.
원자성은 없다, 대신 사실을 말한다 두 시스템에 걸친 트랜잭션은 불가능하다. 부분 완료를 화면이 추적하고 실패한 조각만 다시 보낸다.
자동 판정 금지 근거는 시스템이 모으고 확정은 사람이 한다(기존 원칙). 다만 불가능한 갈래는 잠근다.
삭제는 소프트 ERP 주문 폐기는 deleted_at 만 찍는다. 휴지통에서 복구된다. hard delete 없음.
네이버 호출은 WORKER 단독 web 은 큐에 넣기만 한다(IP 3슬롯 계약). 그래서 3단계는 비동기이고 폴링으로 상태를 받는다.
이력은 남는다 붙이기·금액 정정·주문 폐기·네이버 취소가 각각 주문 변경 이력 1건씩. 감사 로그는 별도로 전량.
