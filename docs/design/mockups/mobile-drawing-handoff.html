⚠️ 데이터 현실 반영 (주문 단위 v1) — 외부 구현 시 이대로

• 상태는 주문 1개(structured_data.drawing_status: 확정대기 TRANSFERRED / 수정요청됨 RETURNED / 완료 CONFIRMED 등). 장별 독립 상태·장별 확정은 데이터에 없음.
• 여러 장 = 도면 파일 여러 개(drawing_current_files, key로 식별). 차수=주문 전달 회차(drawing_transfer_history의 1차·2차…), 장별 차수 아님.
• 수정요청만 도면 번호 타깃 가능(target_drawing_keys→target_drawing_numbers). 전달·확정·상태는 주문 단위. 확정은 confirm-drawing-receipt(주문 1개) — "1번만 확정" 같은 건 v1에 없음.
• ＋도면 추가 전달 = Append(추가) / Replace(번호 선택 교체) / Replace All(전체 교체).

도면팀이 보면 같은 주문 상태로 리본이 "도면 올릴/수정할 차례", 액션 바가 "⬆ 도면 전달"로 자동 전환. 역할·주문상태만으로 화면이 바뀌어 둘 다 "내가 뭘 하면 되는지" 한눈에 압니다.

도면 많을 때(5~6장+): 스트립 vs 리스트 — 리스트(C)가 정답

• 1장: 목록 생략, 바로 상세(B). • 2장+: 도면 목록(C)에서 골라 진입.
  ① 가로 스트립은 4번째부터 화면 밖에 숨어 한눈에 안 보임.
  ② 리스트는 한 줄에 번호·이름·썸네일·최근 회차/수정요청 대상을 다 노출 → 어떤 도면 볼지 바로 판단.
  ③ 세로 스크롤 = 모바일 자연 패턴, 장 수 늘어도 그대로 확장.
  ④ 상세(B) 안에선 ‹ 1/6 › 페이저로 목록 안 거치고 옆 도면 이동(스트립의 '빠른 전환'만 흡수).
→ 스트립은 버리고 리스트 + 페이저로 통일. (상태는 주문 1개이므로 목록은 '골라보기' 용도 — 장별 상태 배지 없음)
