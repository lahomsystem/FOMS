③ 사장님이 정할 것 — 카드 다시 짜기 시안

회사 지식 승인 대기의 ③ 카드 한 장을 다시 그렸습니다. 기존 칸의 차례 · 글 · 보이는 양만 바꿨고, 새 칩 · 요약 상자 · 그림은 없습니다. 보기 사례는 「깊이 줄임 추가비」 — 회사 지식은 통 당 값, 직원은 한 고객에게 통 수를 곱한 합계를 말한 경우입니다. 금액은 ○ 로 가렸고 이름 · 글은 지어낸 것입니다.

사장님 방향(글자 그대로): 카드 화면 다시 짜기 — 바뀌는 곳만 보이기 · "그 손님에게만 맞는 말" 답 · 직원이 실제 한 말 보이기 · 기계 말 걷어내기. 덧붙여 확정: 답은 한 번에 저장 · 사장님이 고쳐 적은 글이 그대로 지식이 됨 · 일어나지 않는 말은 뺌.

2. 「직원 말이 맞아요 — 지식을 고쳐요」를 골라 글을 고치는 중

고칠 칸에는 바뀌는 문장만 들어 있습니다(직원 말 쪽 글로 미리 채움). 사장님이 적은 글이 그대로 지식이 되고, 나머지 문장은 손대지 않습니다. 위 바뀌는 곳 칸은 이름이 「저장하면 바뀌는 곳」으로 바뀌고, 적는 동안 다시 그려집니다 — 바뀌는 곳 표시는 카드에 하나뿐입니다.

4. 저장한 뒤

지금은 카드가 목록에서 사라지고, 화면 맨 위 알림 줄(「정했어요 — 바깥 글이 맞아요.」)과 그 아래 되돌리기 줄(「방금 정한 것 「…」 [되돌리기]」)이 따로 뜹니다. 바꾼 뒤에는 두 줄을 카드 자리 한 줄로 합칩니다. 다음 카드는 바로 아래 이어집니다. 되돌리기 시간은 지금 코드 값(이 화면 · 30분) 그대로 적었습니다.

6. 비평 번호별 — 이 시안이 어떻게 풀었나

풀음 · 일부 · 못 풂 세 가지로 적었습니다. 근거는 docs/plans/2026-11-26-brain-decide-card-review-findings.md.

  • P1풀음「바깥 글」이 화면에서 사라짐. 답은 「직원 말이 맞아요」, 초록 글은 「AI가 직원 말을 정리해 넣는 글」이라고 밝힘.
  • P2풀음기계 두 줄을 보이지 않게 하고, 두 구절은 질문 아래 사람 말 한 줄로. 저장된 표시 줄은 그대로 둠(학습 코드가 씀).
  • P3풀음문단 둘 → 바뀌는 곳 한 칸, 처음부터 빨강 · 초록. 안 바뀌는 문장은 접힘.
  • P4풀음답 「그 고객에게만 맞는 말이에요」를 더함(새 답 코드가 필요 — 7번).
  • P5풀음고칠 칸에 바뀌는 문장만. 나머지 문장은 사장님이 건드릴 수 없으니 몰래 바뀌지 않음.
  • P6풀음자세히 보기에 직원 원문 · 고객 수 · 날짜 · AI가 본 이유(서버가 실어 줘야 함).
  • P7풀음답마다 누르면 생기는 일 한 줄. 지금 코드가 하는 일만 적음.
  • P8못 풂엉뚱한 구절을 짚는 것은 AI 지시문 쪽 일. 다만 직원 원문이 보여 사장님이 틀린 짚음을 알아챌 수는 있음.
  • P9일부고른 단추 표시 · 저장 한 번 · 되돌리기를 카드 자리로. 되돌리기 30분(화면) ↔ 서버 24시간 차이는 그대로 — 시안은 화면 쪽 참값만 적음.
  • P10못 풂「나중에」는 여전히 이 탭에서만 기억. 글도 그대로 둠.
  • P11일부문장 단위로 접어 눈에 덜 띔. 마침표만 다른 것을 바뀜으로 안 치는 규칙은 구현 때 textDiff 에서.
  • P12풀음제목 = 회사 지식 이름(카드에 이미 있는 about.title).
  • S1못 풂고객 둘이면 바로 고치는 길이 사장님 답을 건너뛰는 것은 서버 일. 그래서 답 글에 「다시 안 물어요」를 쓰지 않음.
  • S2풀음「바깥 글은 고칠 일로」 뺌.
  • S3못 풂계산기를 가리키는 지식에 금액이 들어가는 길은 그리지 않음(이 사례는 사장님이 정한 통 당 금액이 글에 있는 지식). 계산기 지금 값 보이기는 7번에 적음.
  • S4풀음저장 한 번 — 서버 한 번 부름이 전제(7번). 실패 글 「아무것도 바뀌지 않았어요」도 이것이 있어야 참.
  • S5일부사장님이 고친 글이 그대로 지식이 됨. 그 글을 다음 밤 배우기에 넘기는 것은 서버 일(7번).
  • S6못 풂카드가 낡았을 때 알림은 그리지 않음. 보통 카드의 「지식이 바뀌었어요」 경고 칸을 같이 쓰면 됨(서버가 판을 견줘야 함).
  • S7풀음화면이 문장을 지우거나 옮기는 어림셈(outsideDraft)을 없애고, 바뀌는 문장만 칸에 넣음(서버가 고친 글을 실어 줘야 함).
  • S8일부되돌리기를 카드 자리로 옮기고 시간을 참값으로 적음. 결정 시간 0 문제 · 고침이 어느 카드에서 왔는지는 서버 일.
  • S9못 풂「나중에」가 서버에 안 남는 것 · 합쳐져 닫힌 카드를 알리는 곳 없음은 그대로.

7. 서버가 새로 해야 하는 것 (시안이 전제한 것)

  1. 답 한 번에 저장 — 새 동작 하나(예 answer_question: 카드 번호 · 답 코드 · 고친 글)를 한 묶음으로: 고침 제안 → 승인 → 카드 닫기. 고침 근거에 카드 번호를 남기고, 화면이 재던 결정 시간을 그대로 실음. 지금은 화면이 세 번 따로 부름(ds-inbox-question.js:129-168).
  2. 새 답 코드 「그 고객에게만 맞는 말」 — constants.py:186 ANSWER_CODES 에 더하고, 밤 배우기 판단 재료 말(handoff_learning_place.py:75)에 「한 고객에게만 맞는 말 — 회사 규칙 아님」으로 실음. 거절 이유에 이미 있는 one_customer(「한 손님 일」)를 답 코드로도 쓸지, 새 코드를 만들지 정해야 함. 보통 카드 거절 칩에서 빼는 목록(ds-inbox-card.js:18)도 같이.
  3. 고친 글을 카드에 함께 남김 — 밤 배우기가 이미 만드는 「직원 말에 맞게 고친 전체 글」(fixed_text)을 _differs_card 가 버리지 말고 카드에 실음. 화면은 이것과 지금 지식 글을 문장 단위로 견줘 바뀌는 문장만 칸에 넣음.
  4. 직원 원문 읽어 오기 — 근거 상담의 가린 직원 답 한두 줄 · 고객 수 · 상담 날짜 · AI가 다르다고 본 이유를 카드 화면 재료(change_view)에 실음(근거 자리 handoff_learning_gates.py:215-219,304).
  5. 두 구절을 따로 내줌 — 저장 글 첫 줄(CLASH_HEAD 「어긋남 — 」) · 둘째 줄(DIFFERS_LINE)은 그대로 두고, 화면 재료에서 두 구절을 따로 칸으로 꺼내 주고 본문에서는 두 줄을 뺌.
  6. 사장님 글을 다음 밤에 넘김 — 판단 줄에 답 이름뿐 아니라 사장님이 적은 글도 실음(S5). 「다시 안 물어요」류의 약속을 단추에 쓰려면 고객 둘 바로 고침 길도 사장님 답을 먼저 보게 해야 함(S1) — 그전까지 시안은 그 말을 쓰지 않음.
  7. (있으면 좋음) 카드의 target_version 과 지금 판이 다르면 「지식이 바뀌었어요」 경고(S6) · 계산기를 가리키는 지식이면 계산기 지금 값 보이기(S3).

확인 못 한 것

  • 사장님이 실제로 이 말을 쓰는지(「직원 말」 · 「그 고객에게만」)는 사장님께 확인하지 않았습니다.
  • 실제 화면에 붙여 보지 않았습니다. 시안은 실제 class 이름을 빌려 따로 그렸습니다.
