# 실측 대시보드 → 지도 전체 주문건 미반영 리뷰

**일자**: 2026-02-25  
**현상**: 실측 N건인데 지도 표기는 더 적음 (예: 22건 → 20건, 18건 → 13건)

---

## 1. 흐름 요약

| 단계 | 실측 대시보드 | 지도 (map_view → generate_map) |
|------|----------------|----------------------------------|
| 진입 | `/erp/measurement?date=YYYY-MM-DD` → 지도 버튼 클릭 | `redirect(/map_view?date=YYYY-MM-DD&status=ALL)` |
| 주문 집합 | `all_rows` (limit 500) → 날짜 필터 → `rows` (최대 300) | `api_generate_map?date=...&status=ALL` (limit 기본 200) |
| 지역/자가실측 | **포함** (필터 없음) | **제외** (`is_regional != True`, `status not in (SELF_MEASUREMENT, SELF_MEASURED)`) |
| 날짜 조건 | 실측일/예정일 등 OR 조건 후 **in-memory 정확일 필터** | DB에서 **동일 OR 조건** → `query.limit(200)` → in-memory 정확일 필터 → `[:limit]` |

---

## 2. 원인 및 설계 원칙

**원칙**: 자가실측·지방실측은 **항상 제외**. 진짜 실측이 필요한 것만 집계(실측 대시보드와 지도 동일 기준).

### 2.1 건수 차이의 실제 원인: 날짜 필터 시 DB 조회 한도(200)

- **파일**: `apps/api/erp_map.py` → `api_generate_map`  
- **로직**:  
  1. 날짜는 “실측일/접수일/시공일/완료일/AS일 + ERP Beta ±30일” 등 **넓은 OR 조건**으로 DB 조회  
  2. `query.order_by(Order.id.desc()).limit(limit)` 로 **상위 200건만** 가져옴 (기본 `limit=200`)  
  3. 가져온 200건을 **in-memory**로 “선택한 날짜와 정확히 일치”하는 건만 필터  
- **결과**:  
  - 넓은 OR에 걸리는 주문이 200건을 넘으면, “선택한 날짜” 건이 200건 안에 다 들어가지 않을 수 있음.  
  - 예: 넓은 조건으로 250건이 나오는데, 그중 “해당일 실측”은 18건 → 상위 200건 안에 실측 18건이 전부 없으면 13건만 포함될 수 있음 → **18건 vs 13건** 같은 차이 발생.

---

## 3. 수정 방향

1. **날짜 필터 사용 시 스캔 한도 상향**  
   - `date` 파라미터가 있을 때는 “후보 조회”를 `limit`이 아니라 `ERP_MAP_SCAN_MAX_LIMIT`(또는 800 등) 수준으로 늘린 뒤,  
   - in-memory로 “선택한 날짜”만 걸러서, 그다음에 표시용 `limit`(200 등) 적용.  
   - → 같은 날짜 실측 건이 200건 밖에 있어도 빠짐없이 후보에 포함되도록 함.

2. **실측 대시보드에도 자가실측·지방실측 제외**  
   - `base_query`에 `is_regional != True`, `status not in (SELF_MEASUREMENT, SELF_MEASURED)` 적용.  
   - → “실측 N건”과 “지도 N건”이 동일한 주문 집합 기준으로 일치.

## 4. 관련 코드 위치

- 실측 대시보드: `apps/erp_measurement_dashboard.py` (rows 구성, 지도 리다이렉트 235~237행)  
- 지도 API: `apps/api/erp_map.py`

  - `api_generate_map`: 231~412행 (동일 제외 246~251행, limit 286행, 날짜 후 필터 290~308행)  
- 지도 템플릿: `templates/map_view.html` (날짜/상태 초기값 832~840행, loadMap 943~954행, limit 미전달)

---

## 5. 결론

- **원칙**: 자가실측·지방실측은 당연히 제외. 진짜 실측 필요한 것만 집계.  
- **원인**: 날짜 필터인데 후보 조회를 200건으로 제한 → 해당일 실측 건이 200건 밖에 있으면 일부만 지도에 표시(18→13 등).  
- **조치**: (1) 날짜 있을 때 스캔 한도 상향(지도), (2) 실측 대시보드에도 동일 제외 조건 적용해 건수 기준 통일.
