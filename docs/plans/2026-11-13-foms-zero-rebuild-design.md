# FOMS 원점 재구성 설계서 — 팔란티어 방식 (판 1, 2026-11-13)

> 이 설계서는 지금 FOMS 코드가 하나도 없다고 보고 처음부터 다시 짓는 설계예요.
> 지금 코드에서 가져온 것은 "회사가 하는 일"(주문 단계 · 팀 · 회사 지식 종류)뿐이에요. 코드 구조 · 표 모양 · 화면은 보지 않았어요.
> 바탕 지도: 팔란티어 · FOMS 개념 지도 https://claude.ai/artifact/4RH3dftV4WFsoq7E8gohFX

## 0. 한 장 요약

- **최종 목표 둘**: (1) AI가 ERP를 운영한다. (2) AI가 손님 상담을 완벽하게 한다.
- **중심**: 온톨로지. 회사가 이름으로 부르는 것(주문 · 손님 · 실측 · 도면 …)을 **물건**으로, 물건 사이 관계를 **연결**로, 물건을 바꾸는 일을 **할 일**로 정의해요.
- **규칙 하나**: 사람도 AI도 **할 일로만** ERP를 바꿔요. 화면 단추 = 할 일. AI 제안 = 할 일. 모든 할 일은 기록이 남고 되돌릴 수 있어요.
- **화면**: 팔란티어가 공개한 화면 부품 **Blueprint 5**(Apache-2.0 라이선스)로 만들어요. 색 · 글자 · 크기 값이 팔란티어 제품과 같아요.
- **AI**: AI도 직원처럼 이름 · 맡은 일 · 쓸 수 있는 할 일 · 자율 수준 · 시험 점수를 가져요. AI는 DB를 직접 못 보고 온톨로지 도구로만 일해요.
- **짓는 순서**: 바탕(온톨로지 엔진 · 할 일 엔진 · 디자인 시스템) → 상담 · 주문 → 방문 · 일정 → 도면 · 생산 → 돈 → AI 운영 넓히기. 한 갈래씩 끝까지(자료 → 온톨로지 → 할 일 → 화면 → AI) 짓고 실제 사람이 써 봐요.

## 2. 팔란티어에서 가져오는 것 · 안 가져오는 것

**가져와요**
- 개념: 물건 종류(object type) · 속성(property) · 연결 종류(link type) · 할 일 종류(action type) · 계산(function) · 공통 모양(interface) · 물건 묶음(object set).
- 일하는 방법: 결정 중심(누가 무엇을 정하나부터), 부트캠프(한 갈래를 며칠에 끝까지), AI는 시험 먼저.
- 화면 부품: Blueprint 5 — 팔란티어가 직접 만들어 공개한 부품이라 그대로 써도 돼요.
- 공개 문서에 적힌 화면 배치 원칙: 위 줄 · 왼쪽 길잡이 · 가운데 내용 · 오른쪽 옆 창, 물건마다 카드 하나.

**안 가져와요**
- 팔란티어 코드 · 로고 · 제품 이름 · 문서 그림 · 비공개 화면을 그대로 베끼기. 라이선스가 없고 법 위험이 있어요. 팔란티어 소프트웨어를 뜯어 복제(리버스 엔지니어링)하지도 않아요.

## 3. 시스템 구성

### 3.1 일곱 층과 흐름

```
바깥 자료: 네이버 커머스 · 채널톡 · 알림톡 · 결제 · 사진 · 직원 입력
   │
[1 자료 붙이기]  받은 그대로 원본 표에 쌓기(지우지 않음) → 정리 → 물건으로
   │
[2 온톨로지]     물건 · 속성 · 연결 · 공통 모양 · 보호 표시
   │
[3 할 일 · 계산 · 자동 규칙]  바꾸기는 할 일로만, 조건이 맞으면 자동 규칙이 제안
   │                        │
[4 앱(사람 화면)]          [5 AI 직원]
   └──────── 할 일 실행 ────────┘
                 │
     온톨로지에 다시 씀 + 바깥으로 보냄(알림톡 · 네이버 처리) + 할 일 기록
                 │
     AI 시험 · 배울 거리(고친 글 · 거절 이유)
[6 플랫폼] 로그인 · 권한 · 보호 표시 · 기록 · 배포 · 지켜보기 — 모든 층을 감쌈
[7 일하는 방법] 결정 중심 · 부트캠프 · 능력 질문 · 시험 — 위에서 이끔
```

### 3.2 서비스 나눔

| 서비스 | 하는 일 | 비고 |
|---|---|---|
| web | 화면(React 단일 앱) — PC · 태블릿 · 폰 한 코드 | 손님 확인 링크도 같은 앱의 손님 길 |
| api | 온톨로지 서버: 물건 읽기 · 묶음 질의 · 할 일 실행 · 계산 · 검색 | 화면과 AI가 같은 api 를 씀 |
| worker | 바깥 보내기(outbox) · 자동 규칙 · 자료 길 · AI 작업 | 한 번만 보내기 보장(idempotency key) |
| cron | 정해진 때 일(아침 AI 운영 훑기 · 정산 받기) | worker 에 일을 넣기만 |
| DB | PostgreSQL 16 + pgvector(글 검색) | 물건 종류마다 표 하나 |
| 파일 | Cloudflare R2 | 사진 · 도면 · 문서 |
| 실시간 | 서버 보내기(SSE) | 화면 자동 갱신, 승인함 숫자 |

### 3.3 기술 고르기 (권장)

- **화면**: React 18 + TypeScript + Blueprint 5(`@blueprintjs/core` · `icons` · `table` · `select` · `datetime2`). 팔란티어 제품과 같은 부품이에요.
- **서버**: Python 3.12 + FastAPI + SQLAlchemy 2 + Pydantic 2. AI 도구 · 자료 처리에 강하고, 지금 일하는 사람과 AI가 가장 잘 아는 말이에요. (다른 길: 서버도 TypeScript — 결정 D-1)
- **온톨로지 정의 = 저장소 안 YAML 파일**(물건 종류 · 속성 · 연결 · 할 일 · 공통 모양 · 보호 표시). 이 한 곳에서 DB 표 · api · 화면용 TypeScript 타입 · Python 타입 · 시험을 자동으로 만들어요(팔란티어 OSDK 와 같은 생각).
- **AI 모델**: Claude — 어려운 판단 Opus 5.5, 상담 초안 Sonnet 5.5, 나누기 · 뽑기 Haiku 5.5.
- **배포**: Railway(web · api · worker · cron) + R2. 지금 계정 그대로 써요.

### 3.4 DB 모양 원칙

1. 물건 종류마다 표 하나. 속성 = 열. 큰 JSON 칸에 업무 자료를 숨기지 않아요(지금의 큰 칸 문제를 다시 만들지 않기).
2. 연결: 하나 대 여럿은 열(바깥 열쇠), 여럿 대 여럿은 연결 표.
3. 모든 표에 `id`(사람이 읽는 번호와 따로) · `version` · `created_at` · `updated_at` · `archived_at`.
4. 상태는 물건마다 열 하나(`state`). 두 축(상태와 단계)을 따로 두지 않아요.
5. 할 일 기록 표: 할 일 하나 = 한 줄(누가 · 사람/AI · 할 일 이름 · 넣은 값 · 바뀐 속성 전/후 · 승인한 사람 · 시각 · 바깥 보내기 결과).
6. 원본 표(raw)는 지우지 않아요. 물건마다 어느 원본에서 왔는지(계보) 남겨요.

## 4. 온톨로지 설계

### 4.1 원칙

1. 물건 = 회사에서 이름으로 부르는 것. 화면에 이름이 없는 것은 물건이 아니에요.
2. 상태 길은 물건마다 하나. 다음 상태로 가는 길은 할 일로만 있어요.
3. 반복되는 것은 물건으로(주문 안 품목 → 주문 품목 물건).
4. 연결은 이름이 두 개(나가는 이름 · 들어오는 이름) — 예: 주문 →'설치할 곳'→ 현장, 현장 →'이 곳의 주문'→ 주문.
5. 사실(정체)과 관찰을 나눠요. 사진을 AI가 읽은 결과는 '관찰'이고, 사람이 확인해야 '사실' 속성이 돼요.
6. 회사 지식(제품 · 옵션 · 규칙 · 정책)과 ERP 물건이 같은 온톨로지 안에서 연결돼요. 예: 주문 품목 →'제품 줄'→ 제품 줄(회사 지식) →'만들기 규칙'→ 만들기 규칙.

연결 종류 17개도 그대로 가져오고, ERP 물건과 잇는 연결을 더해요(4.4).

### 4.5 주문 상태 길 (하나만)

```
상담 → 견적 → 계약 → 실측 대기 → 실측 끝 → 도면 → 손님 확인 대기 → 확정
     → 생산 → 출고 대기 → 시공 대기 → 시공 끝 → 완료
옆길: 보류(어느 단계에서나 — 돌아올 단계를 기억) · 취소(돈 확인 뒤)
```
- 지금의 '설치예정 · 상차예정 · 지방실측' 같은 물류 상태는 주문 상태가 아니에요. 시공 · 배송 방문의 상태와 주문의 '지역' 속성으로 보여요.
- AS는 주문 상태가 아니라 AS 건 물건의 상태 길이에요. 완료된 주문에도 AS 건이 여럿 붙을 수 있어요.
- 주문 상태는 손으로 고르지 않아요. 할 일(예: '실측 결과 올리기')이 끝나면 따라서 바뀌어요.

### 4.6 값 모양 (value type)

| 값 모양 | 규칙 |
|---|---|
| 전화번호 | 숫자만 저장, 화면은 010-0000-0000 |
| 주소 | 도로명 · 상세 · 지역 계산 |
| 금액 | 원 단위 정수, 음수는 환불 · 지급 |
| 치수 | mm 정수 |
| 날짜 · 시각 | 한국 시간 기준(서버 시험도 한국 시간) |
| 시간대 | 오전 · 오후 · 시각 지정 |
| 사진 묶음 | R2 파일 열쇠 목록 + 찍은 시각 |

## 6. AI 설계

### 6.1 AI 직원 다섯

| AI 직원 | 맡은 일 | 쓰는 할 일 |
|---|---|---|
| 상담 AI | 손님 메시지 → 근거 있는 초안 + 할 일 제안 | 상담 답 보내기 · AS 접수 · 방문 옮기기 · 알림톡 보내기 |
| 운영 AI | 아침 8시와 매시 정각, 상태가 바뀔 때 막힌 주문 · 빠진 자료 · 겹친 일정 찾기 | 담당 맡기기 · 일 맡기기 · 알림톡 보내기 |
| 일정 AI | 실측 · 시공 · AS 방문 날짜 제안(팀 · 지역 · 인원 · 생산 끝날 날) | 실측 잡기 · 시공 잡기 · 방문 옮기기 |
| 지식 AI | 상담 · 사례에서 회사 지식 고치기 제안 | 회사 지식 고치기 제안 |
| 자료 AI | 사진 · 도면 · 메모에서 속성 읽기(관찰) | 실측 결과 올리기(초안) · AS 접수(초안) |

### 6.2 AI 도구 (모두 온톨로지를 거침)

- `objects.search(type, filter, follow_links)` — 물건 묶음 찾기
- `objects.get(id)` — 물건 읽기(보호 표시를 지킴: 🔒 손님 정보는 가린 채 주고, 필요하면 '풀어 보기'를 따로 요청해 기록에 남김)
- `functions.call(name, args)` — 계산
- `actions.propose(name, params, reason, evidence)` — 할 일 제안(자율 수준에 따라 승인함으로 가거나 실행)
- `knowledge.search(text)` — 회사 지식 글 + 연결 검색

AI는 SQL을 못 써요. 할 일 밖에서는 쓰기가 없어요. 모든 제안에 '이유 한 줄 + 근거 물건'이 붙어요.

### 6.3 상담 AI 흐름

1. 메시지 들어옴 → 손님 · 주문 찾기(전화 · 이름 · 주문 번호 · 상담 연결).
2. 질문 나누기: 일정 · 값 · 제품 · AS · 불만 · 기타.
3. 근거 모으기: 주문 상태 · 방문 일정 · 도면 상태 · 정책 · 제품 지식 · 지난 답 틀 · 말투.
4. 초안 + 근거 칩 + 위험 표시(돈 약속 · 날짜 약속 · 사과 · 보상).
5. 할 일 제안을 함께(예: 'AS 접수', '방문 옮기기').
6. 사람이 확인 → 보냄. 고친 차이는 '배울 거리'로 쌓여 지식 AI가 읽어요.
- 지켜야 할 것: 손님 정보 가림 · 근거 없는 약속 금지 · 모르면 "확인하고 다시 안내드릴게요" + 담당에게 맡긴 일.
- 말투는 실제 상담사 글을 재서 맞춰요(문법대로 고치지 않기).

### 6.4 운영 AI 흐름

정해진 때 + 상태가 바뀔 때 → 저장된 감시 묶음(막힌 주문 · 늦은 도면 · 손님 알림 안 간 방문 …) 훑기 → 할 일 제안(이유 · 근거 · 되돌리기) → 승인함 → 사람 승인 → 실행 → 결과 확인 → 승인 · 거절 · 고침 비율을 AI 작업실에 남김. 거절 이유는 회사 지식 '배운 점'으로 제안돼요.

### 6.5 AI 시험

- 시험 세트: 지난 상담(가린 글) + 정답 근거, 능력 질문 79개, 운영 장면(막힌 주문 30개).
- 모델 · 지시문 · 도구가 바뀌면 시험을 다시 돌리고 점수가 내려가면 배포를 막아요.
- AI 작업실에 AI 직원별 점수 · 비용 · 시간 · 최근 실패를 보여줘요.

## 7. 앱 (화면) 설계

### 7.1 화면 원칙

1. 배치: 위 줄(앱 이름 · 전체 검색 · 승인함 숫자 · 사람) + 왼쪽 길잡이 + 가운데 내용 + 오른쪽 옆 창(자세히 · AI).
2. 물건마다 카드 하나. 어디서 눌러도 같은 카드.
3. 바꾸는 단추 = 할 일 단추 → 할 일 창(넣을 값 · 막는 조건 · 바뀔 것 미리 보기).
4. AI는 옆 창에서 같이 일해요: 근거를 보여주고, 제안은 할 일 모양으로.
5. 글자: 바탕 14px, 12px 밑으로 안 내려요(사장님 PC 80% 배율). 글자 크기 조절은 한 곳(`--fs` 배율)에서만.
6. 상태 배지: 무채색 금지. 나란히 보이는 상태 색끼리 색 차(ΔE2000) 10 이상, 색약 흉내 뒤 6 이상(8.4에서 잼).
7. 새 기능은 폰 목록 줄 · 배지에서도 보여야 해요.
8. 화면 글: 쉬운 한글, 같은 말 한 번, 기계 말 금지.

## 11. 일하는 방법

1. **결정 중심**: 화면이 아니라 "누가 어떤 결정을 하나"부터 적어요. 결정마다 필요한 물건 · 연결 · 할 일을 적어요.
2. **부트캠프**: 한 갈래를 1~2주에 끝까지(자료 → 온톨로지 → 할 일 → 화면 → AI) 짓고, 그 팀 실제 사람이 1주 써 봐요.
3. **능력 질문**으로 온톨로지 완성을 재요. 질문이 답 못 하면 물건 · 연결이 빠진 거예요.
4. **AI는 시험 먼저**. 자율 수준은 점수로 올려요.
5. **쓰는 사람부터**: 화면마다 실제 쓰는 사람 하나(영업 · 도면 · 생산 · 시공 · CS · 사장님)로 검토해요.
