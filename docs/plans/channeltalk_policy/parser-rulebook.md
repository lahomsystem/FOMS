# Parser Rulebook (CT-E)

## 1. 개요
ChannelTalk에서 수신된 웹훅 페이로드(사용자 또는 매니저 채팅 입력)를 파싱하여 FOMS 내부 포맷으로 변환하는 규칙을 정의한다.

## 2. 파싱 기본 원칙
1. **표준 템플릿 우선 (Standard Template First)**: 자유 텍스트 추론(NLP/LLM) 방식보다는 사전에 약속된 키-밸류 구조나 템플릿 양식을 기준으로 파싱한다.
2. **필수 필드 강제**: 주문 또는 태스크 생성에 필수적인 필드가 누락된 경우 파싱 실패(`parse_failed`)로 간주한다.
3. **무음 실패 방지 (No Silent Failures)**: 파싱에 실패하면 실패 상태로 기록하고, Quick Reply(또는 봇 메시지)를 통해 발신자(또는 운영자)에게 명확한 실패 사유를 안내한다.
4. **개인정보 보호 (PII Masking)**: 로그 저장용으로 사용할 때는 고객의 개인정보(이름, 전화번호, 주소 등)를 마스킹 처리하여 저장한다. 원본(raw_payload)은 30일 후 폐기한다.

## 3. 예시: 접수 템플릿 규칙
**입력 포맷 예시:**
```text
[신규 주문 접수]
고객명: 홍길동
연락처: 010-1234-5678
주소: 서울시 강남구 테헤란로 123
수주제품: 가죽소파 3인용
```

**파싱 규칙:**
- 각 줄을 정규식 또는 Split 기반으로 분리하여 `고객명`, `연락처`, `주소`, `수주제품` 키를 찾는다.
- 필수 키: `고객명`, `연락처`, `주소`. 하나라도 없으면 실패 처리.
- 파싱된 결과는 `ChannelInboundEventLog.parsed_result`에 마스킹된 형태로 저장된다 (예: 홍**, 010-****-5678).

## 4. 실패 시 Quick Reply (안내 메시지)
파싱 실패 시 아래와 같은 고정 문안을 웹훅 응답(또는 후속 채널톡 API)으로 전송한다.
> "[시스템 안내] 메시지 형식이 올바르지 않아 주문/태스크 등록에 실패했습니다. 지정된 템플릿을 사용하여 다시 입력해주세요.\n(누락된 정보: {missing_fields})"
