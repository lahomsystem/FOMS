# 도면 마법사 V2 — 칸 자동 배치 화면 · V1/V2 고르기 (Spec v1, 2026-10-26)

> 상태: 구현(사용자 지시 "이 레이아웃으로 도면 wizard V2 만들고, V1, V2 도면팀이 선택할 수 있게").
> 레이아웃 정본: 디자인 캔버스 `도면 폼 시안 10종` 의 `K2-WizardAuto.dc.html`(사진 자동 + 그림 종류 자동 판단, 1440×900).
> 코어 변경 아님: DB·API·인증·배포·하네스를 바꾸지 않는다. 서버는 페이지 라우트가 쿠키로 템플릿 갈래만 고른다.

## 0. 한 줄
V2 는 V1 과 **같은 도면 데이터**(시트·그림·글자·폼)를 다른 화면으로 보여 준다. 종이 위쪽을 '칸'(사진·자재표·특이·큰 그림·상세·평면·미분류)으로 나눠
그림을 저절로 넣고, 아래 띠는 새 양식(01 정돈 표준형)으로 그린다. 저장·전달 대기함·전달·도면방 PUSH·버전·자동 채움·자재표 계산은 V1 엔진을 그대로 쓴다.

## 2. 데이터(서버 바꾸지 않음)
- 칸은 저장하지 않고 **객체에서 읽는다**: 그림 = `part.label`(V1 닫힌 목록), 자재표 = 첫 줄이 `[SR]` 같은 대괄호 머리글인 글자(V1 `isBomText` 규칙 그대로).
- 특이 사항 · 강조 문구 = 글자 객체이고 **id 앞머리**로 가린다: `n-`(특이 · 실선 = 제작) · `nc-`(특이 · 점선 = 현장/고객) · `st-`(강조 문구). V1 은 id 를 그대로 두므로 V1 에서 열어도 빨간 글자로 보이고(데이터가 숨지 않는다), V1 이 저장해도 역할이 남는다.
- 시트 폼에 문자열 두 칸(서버 `_validate_form` 은 문자열 칸을 받는다, V1 `serializeForm` 은 모르는 칸도 그대로 옮긴다):
  - `v2_layout` = `'band'`(위 띠형) | `'column'`(왼쪽 기둥형) — V2 가 칸으로 정리한 시트 표시. 칸 머리는 이 표시가 있을 때만 그린다. V1 [자동 배치]가 그림을 다시 놓으면 지운다.
    V2 종이에는 V1 의 위쪽 체크 칸·쪽 번호 칸이 없어서 그 자리에 그림·자재표가 놓인다 — V1 에서 이런 시트를 열면 시트마다 한 번 알린다(겹치면 [자동 배치] 또는 새 화면에서).
  - `v2_pick` = 사람이 고른 틀(''|'band'|'column') — 다시 배치해도 그 틀을 쓴다. `v2_photo` = 'done'(실측 사진 자동을 이미 한 시트).
  - `v2_kind` = 제품 종류를 사람이 고른 값('' = 그림을 보고 자동).
- 손으로 옮긴 그림 = 지금 자리 ≠ `part.arr`(자동 배치가 놓은 자리, V1 과 같은 뜻). 잠근 그림·돌린 그림은 V1 처럼 옮기지 않는다.
- 켜고 끄기 4개와 V1/V2 선택은 이 브라우저에만 기억한다(localStorage · 쿠키 `dws_ui`).

## 3. 종이(스테이지 좌표, 1478×1040)
- 테두리 (40,40)–(1440,1000) 3px — V1 과 같다. 아래 띠 높이 142(K2 108px × 1.316), 띠 위선 y=858.
- 칸 자리: x 53–1427, y 53–848. 칸 머리 높이 24(검정 딱지 · 이름 · 크기/색).
- 아래 띠(새 양식): 체크(도면팀 3 · 생산팀 5) | 2줄 정보(시공일자·고객명·연락처·주소·영업담당 / 제품명·현장규격·색상·손잡이·서랍·시공자수) | 기타·부자재 | 로고·장 N/M·No.주문·DREW. 값은 V1 폼 칸과 같은 이름(`data-dws-form-key`)이라 자동 채움·편집·글자 줄이기가 그대로 돈다.
- 칸 머리·특이 상자·강조 테두리·자재표 칸 선은 스테이지 안 DOM(`#dws-v2-slots`)이라 PNG 에 찍힌다. 배율 표시(108% 등)는 `.dws-ui` 라 PNG 에 안 찍힌다.

## 4. 자동 배치(V2) — `v2-slots.js`(묶기) · `v2-layout.js`(틀 계산)
- 칸: 사진(`사진`) · 자재(자재표 글자, 크기 고정) · 특이(`n-`/`nc-` 글자, 줄 바꿈 흐름) · 강조(`st-`, 오른쪽 위) · A 큰 그림(정면·입체 짝 묶음 — V1 `FomsPartLayout.groups` 그대로) · B 상세(서랍 단면·부품 상세) · 평면(평면·상판) · 미분류(`미분류`·`그림 아님`·종류 없음 — 맨 아래 낮은 줄(높이 170 까지) 또는 오른쪽 좁은 기둥(폭 200 까지) 중 큰 그림이 크게 나오는 쪽의 '기타 그림' 칸, 큰 그림과 배율을 나누지 않는다: 같이 두었더니 한 장만 미분류여도 큰 그림이 반으로 줄었다).
  - 주방(제품 종류)이면 큰 그림을 A 정면 · C 입체 두 칸으로 나눈다.
  - '확신이 낮으면 미분류로' 를 끄면 미분류 그림은 AI 짐작(`part.ai`) 칸으로 간다.
- 틀 두 가지를 모두 계산해 점수가 높은 쪽(사람이 고른 틀이 있으면 그것):
  - 위 띠형: 위 띠 = [사진][자재 + 특이][B][평면] (강조는 오른쪽 위), 아래 = 큰 그림 줄.
  - 왼쪽 기둥형: 왼쪽 기둥 = [사진][B][평면], 오른쪽 위 = [자재][특이], 오른쪽 아래 = 큰 그림 줄.
  - 띠 높이·기둥 폭을 여러 값으로 재 보고 고른다. 같은 칸 그림은 같은 배율('같은 칸은 같은 배율'을 끄면 칸 안 그림 높이를 맞춘다). 확대는 원본의 1.25배까지(V1 과 같음).
- 배율(%) = **지금 양식 대비**: 같은 그림을 V1 자동 배치(빈 새 시트 칸)로 놓았을 때 높이에 견준 값. 점수 = 가장 작은 그림 % + 큰 그림 %의 절반, 치수 글자가 8px 밑이면 크게 깎는다.
- 치수 글자가 8px 밑(V1 과 같은 기준)이거나 가장 작은 그림이 60% 밑이면 '시트 2장으로 나누기'를 권한다(처음 80% 로 두었더니 기준인 V1 자동 배치가 빈 종이에 그림을 가득 키운 크기라 그림 넷뿐인 시트에도 권했다 — 로컬 실화면)(큰 그림·상세를 넓이로 반씩 → 새 시트 → 두 시트 모두 다시 배치, 이 시트에서 Ctrl+Z 한 번이면 처음대로).
- 그림 위·안에 붙어 있던 글자·도형·펜(가운데가 그림 안)은 그 그림을 따라 옮긴다(치수 메모가 떨어지지 않게).
- 언제 도나: 자동 배치 모드에서 그림을 올렸을 때·종류가 바뀌었을 때·틀/켜고 끄기를 바꿨을 때·[다시 자동 배치]. 시트를 열기만 해서는 옮기지 않는다(`v2_layout` 없는 시트는 알림 띠로 '정리하기'를 권한다). 자유 배치 모드에서는 저절로 옮기지 않는다.
- 되돌리기: 사람이 한 일(올리기·종류 바꾸기)과 그 뒤 배치는 Ctrl+Z 한 번에 함께 돌아간다. [다시 자동 배치]·틀 고르기는 따로 한 번.

## 5. 실측 사진 자동
- 시트에 사진 그림이 없고 실측 사진이 있으면, 첫 자동 배치 때 한 장을 골라 넣는다(V1 실측 사진 넣기 API 그대로). 고르는 법: 지금 제품 사진 중 가로 사진 우선, 색·밝기가 가장 고르게 섞인 것(방 전체가 보이는 사진일수록 큼).
- 사람이 지운 뒤에는 다시 넣지 않는다(이 창에서 기억). 사진 칸 카드의 [다른 사진]으로 바꾼다.

## 6. V1/V2 고르기
- 라우트 `/erp/drawing-workbench/<id>/wizard`: `?ui=v1|v2` 가 있으면 그것, 없으면 쿠키 `dws_ui`, 없으면 V1(지금 쓰는 사람 화면은 그대로).
- V1 앱바에 [새 화면 V2], V2 ⋯ 메뉴에 [예전 화면 V1]. 누르면 고치던 것을 자동 저장(PUT)한 뒤 쿠키를 바꾸고 다시 연다.
- 계정마다 기억하려면 DB 칸이 필요하다 — 이번에는 하지 않는다(브라우저마다).

## 7. 시험
- 파이썬: 라우트 갈래(쿠키·쿼리·잘못된 값), V2 템플릿 요소·스크립트·핀, 인라인 style 없음.
- node: 칸 묶기(이름표·자재표·id 앞머리·미분류 켜고 끄기·주방 두 칸), 틀 계산(두 틀·같은 배율·확대 상한·고정 그림 제외·% 기준·글자 하한·나누기 권함), 배선(코어 API·V2 에서 V1 표 엔진·V1 자동 배치 안 돎).
- 로컬 dev 실화면(견본 그림) → 스테이징 실화면(CLAUDE-TEST 주문).

## 8. 안 하는 것
- 계정별 V1/V2 기억(DB), 칸 순서 끌어서 바꾸기, 자재표 계산 결과를 시트에 넣기(도면팀 확인 전 — 2026-10-23 설계서 §3.6).
