## 0. 한 줄

도면팀이 그림 종류를 고르거나 고치면, 그 그림의 **특징 숫자 768개**(브라우저 AI 가 이미 계산한 것, 그림 자체가 아님)를 종류와 함께 서버에 남긴다.
한 장을 고치면 같은 주문의 닮은 그림도 같이 고칠지 묻고, 다른 주문에서 올린 새 그림이 남겨 둔 그림과 **아주 비슷하면 사람이 고른 종류를 따른다**.
AI 본체(분류기 가중치)는 그 자리에서 바꾸지 않고, 모인 기록으로 지금처럼 검사를 거쳐 다시 가르친다.

## 1. 지금 사정

- **운영(production)에는 AI 분류가 아예 없다**(2026-10-26 `origin/production` 확인: `static/js/drawing/` 에 `part-*`·`v2-*`·`bom-*` 없음,
  `foms/api/drawing/wizard.py` 에 그림 이름표 검증 없음). 이전 마법사는 그림의 자리 · 크기만 저장한다 → 운영에서는 아직 배울 거리가 0이다.
  이 설계의 효과는 AI 마법사가 운영에 올라간 뒤부터다(운영 승격은 따로, 사용자 요청 때).
- 지금 배우는 길은 `tools/drawing_ai` 다시 가르치기 하나다: 손으로 · 한 달에 한 번 · 고친 기록 100건 이상 · 운영 읽기는 돌릴 때마다 허락.
  운영 그림을 내려받아 파이썬으로 특징을 다시 뽑는데, 브라우저와 그림 줄이기 방식이 달라 같은 그림의 확신이 0.1까지 다르다(2026-10-26 #4465 실측).
- 운영 마법사 사용량(10-23 실측): 9/11 ~ 10/23 낱장 그림 약 1,040장 → 하루 25장쯤. 분류기 h1 은 시험 값으로 94%를 스스로 정하므로
  사람이 고르거나 고치는 그림은 하루 몇 장(어림 2~5장)이다. **그래서 다른 주문 사이의 기억은 천천히 자란다.**
- 도면팀은 한 주문의 그림을 보통 한꺼번에 올린다. 분류가 다 끝난 뒤에 사람이 고치므로, 같은 주문 안에서는 '새 그림이 기억을 따르기'보다
  **'한 장을 고치면 닮은 그림도 같이 고치자고 묻기'(§3.3)** 가 바로 효과를 낸다.

## 2. 왜 '고칠 때마다 AI 다시 가르치기'가 아닌가

| 방식 | 판단 | 까닭 |
|---|---|---|
| 가) 고칠 때마다 분류기 가중치를 바로 고침 | 안 함 | 잘못 누른 한 번이 모두에게 바로 퍼진다. 시험 묶음 검사를 할 틈이 없다. 여러 사람이 동시에 고치면 엉킨다. 한 장씩 배우면 거의 안 변하거나 그 한 장에 휩쓸려 잘 맞히던 것을 잊는다. 어느 판으로 분류했는지(`part.head`) 기록이 흐려진다. |
| 나) 브라우저마다 따로 배우기 | 안 함 | 사람마다 다른 AI 가 되고, 브라우저를 바꾸면 사라진다. |
| 다) **비슷한 그림 기억 + 모아서 다시 가르치기** | 채택 | 다음 그림부터 바로 효과. 본체는 그대로라 기억을 꺼도 지금 실력. 이유를 보여 줄 수 있고(어느 그림을 따랐나), 잘못된 기억만 골라 끌 수 있다. |

## 3. 설계

### 3.1 새 표 `drawing_part_memory`

| 칸 | 꼴 | 뜻 |
|---|---|---|
| `id` | 정수 PK | |
| `order_id` | 정수 FK `orders.id` (ON DELETE CASCADE), 색인 | 주문을 지우면 함께 지운다 |
| `asset_key` | 글자 512 | 마법사 그림 저장소 키(`orders/<order_id>/drawing_wizard/assets/…`). `(order_id, asset_key)` 유일 |
| `feat` | 바이트, 비어도 됨 | 특징 768개(CLS 384 + 패치 평균 384, L2 정규화)를 float16 으로 = 1,536바이트. 기억 전에 올린 그림은 비어 있을 수 있다 |
| `feat_v` | 글자 16, 비어도 됨 | 특징 판(모델 커밋 + 전처리). 판이 다르면 섞지 않는다 |
| `ai` · `conf` · `head` | 글자 16 · 실수 · 글자 16 | 분류 때 AI 첫 짐작(다시 가르치기 통계용, `part` 와 같은 규칙) |
| `label` · `src` | 글자 16 · `ai`/`user` | 지금 이름표와 출처 |
| `kind` | 글자 16, 비어도 됨 | 제품 종류(closet · kitchen · fridge · other) — 제품별 판정용 |
| `created_by` · `updated_by` | users.id | 누가 남겼나 |
| `created_at` · `updated_at` | 시각, `updated_at` 색인 | |
| `active` | 참/거짓, 기본 참 | 잘못된 기억 끄기 |

- 크기: 줄당 약 1.7KB. 1년 1만 장이어도 17MB 안팎. 저장 경로(마법사 PUT)와 주문 `structured_data` 는 건드리지 않는다(JSONB 를 키우지 않는다).
- 마이그레이션: 표 · 색인 만들기만(데이터 바꾸기 없음), `downgrade()` 는 표 지우기. 운영 승격 때 alembic head 를 그날 운영 계보에 맞춘다.

### 3.2 언제 남기나 (브라우저 · M1)

1. **분류 직후**: `part-ai.js` `classify` 가 결과에 특징 `feat`(Float32Array)과 특징 판 `fv` 를 더해 돌려준다(시트에는 저장하지 않는다).
   새 모듈 `part-memory.js` 가 1초 동안 모아 한 번에 보낸다 — `{key, f, fv, ai, conf, head, label, src, kind}`.
2. **이름표가 바뀔 때**: 사람이 고름(`labels` 사건 `by:'user'`) · 되돌리기 · 다시 하기 · 자동 저장 성공 때마다
   '이 주문 그림들의 이름표 목록'을 만들어 지난번 보낸 것과 견주고, 바뀐 줄만 보낸다 — `{key, label, src}`.
   같은 그림이 여러 시트에 있으면 사람 이름표가 이기고, 그다음은 나중 것.
3. **특징이 없는 그림**(기억 전에 올린 그림)에 사람이 이름표를 달면: 서버가 응답에 `missing` 으로 알려 준다.
   모델이 이 브라우저에 이미 있으면 특징만 다시 뽑아 보낸다(이름표는 바꾸지 않는다). 한 창에서 한 번만 시도한다.
4. 보내기는 한 줄로 차례차례(앞의 것이 끝나야 다음) — 늦게 도착한 분류 결과가 사람 이름표를 덮지 않는다.
   실패하면 조용히 버리고 다음 동기화 때 다시 보낸다. 분류 · 배치 · 저장 · 전달은 기다리지 않는다.

### 3.3 같은 주문에서 같이 고치기 (M2-a · 사람이 확인)

- 사람이 그림 한 장의 종류를 고치면(AI 이름표 → 사람 이름표), 같은 주문의 다른 그림 중 **AI 이름표인 그림**(사람이 고른 것은 빼기)을
  닮은 순서로 찾는다. 문턱(`min_sim`)을 넘은 그림은 **바로 같은 종류로 바꾸고**(판 표시 `.m`) "비슷한 그림 2장도 같이 바꿨어요 — 정면·도어 · 되돌리기 Ctrl+Z"를 띄운다.
  되돌리기 한 번이면 같이 바꾼 것만 돌아간다(사람이 고른 한 장은 그대로). 같은 시트 안에서만 바꾼다(보이지 않는 시트는 건드리지 않는다).
- 내부/도어만 바꾼 경우는 더 높은 문턱(`min_sim_door`)을 쓰고, 고친 그림의 짝(주방 짝 규칙에서 같은 보기 두 장 중 다른 한 장)은 뺀다 —
  짝은 반대 종류일 가능성이 크다.
- 특징은 이 창에서 분류한 그림이면 브라우저에 이미 있어 브라우저 안에서 잰다. 다시 연 주문처럼 브라우저에 없으면 서버에 남은 특징으로 잰다(`match` 의 `key`).
- 같이 바꾼 그림의 출처는 `ai` 로 둔다 — 사람이 하나하나 본 것이 아니므로 다른 그림이 따를 기억(사람 이름표)이 되지 않는다.
  같이 바꾼 뒤 되돌린 비율을 세어 문턱을 다듬는다(V2 는 사람이 고른 것처럼 고정을 풀고 다시 배치한다).

### 3.4 다른 주문의 기억 따르기 (M2-b · 처음부터 켬, 보수적 문턱)

- 순서: 분류 → 기억 찾기(`…/part-memory/match`, 1.5초 안에 답이 없으면 건너뜀) → 이름표 확정 → 주방 짝 규칙 → 배치.
- 서버 판정 — 같은 특징 판 · 켜진 줄 · 사람 이름표(`src:'user'`, 미분류 아님) 중 코사인 닮음이 큰 순서로:
  - 가장 닮은 것이 문턱(`min_sim`) 아래면 따르지 않는다.
  - 문턱을 넘은 기억들이 서로 다른 종류면 '갈림' — 따르지 않고 이유만 보여 준다.
  - **내부/도어만 다른 경우는 더 높은 문턱**(`min_sim_door`): 같은 가구의 내부 그림과 도어 그림은 서로 아주 닮는다.
    못 넘으면 보기(정면 · 입체)만 기억을 따르고 내부/도어는 지금처럼 AI · 짝 규칙에 맡긴다.
  - 자기 자신(같은 키)은 뺀다. 같은 주문의 기억도 쓴다(한 주문 안에 같은 모듈 그림이 자주 되풀이된다).
  - AI 가 자신 있던 짐작(확신 `strict_conf` 0.8 이상)을 뒤집을 때도 `min_sim_door` 를 넘어야 한다 — 기억은 주로 AI 가 헷갈린 그림을 고친다.
  - 문턱 가값: `min_sim` 0.95 · `min_sim_door` 0.985 — 사용자 결정으로 처음부터 켜고, 측정(§3.6)으로 다듬는다.
- 기억을 따른 이름표: `label` = 기억 종류, `src:'ai'`, `ai` · `conf` 는 AI 원래 짐작 그대로, `head` = `<판>.m`(예 `h1.m`).
  서버 `part` 칸은 늘리지 않는다(`head` 규칙 `^[A-Za-z0-9._-]{1,16}$` 안이다).
- 주방 짝 규칙은 `.m` 이름표를 바꾸지 않는다(사람이 고른 근거가 빗금 어림보다 강하다). V2 칸 짐작(`v2_ai`)은 이름표가 정해졌으니 쓰지 않는다.
- 보여 주기: V1 이름표 칩에 '기억' 표시(풀이 "사람이 고른 비슷한 그림을 따랐어요"), V2 오른쪽 '컴퓨터가 본 것'에
  "비슷한 그림을 사람이 고른 대로 · 닮음 97%"(닮음 숫자는 그 창에서만, 다시 열면 숫자 없이).
- 사람이 다시 고르면 언제나 사람 것이 이긴다. 그 고침도 기억에 들어간다.

### 3.5 다시 가르치기와 잇기 (M3)

- `tools/drawing_ai/retrain_data.py` 모으기가 그림 대신 이 표의 특징을 읽는다(특징이 없는 그림만 예전처럼 내려받아 뽑는다).
  → 운영 그림을 내려받지 않아도 되고, 서버 쪽 onnxruntime 도 필요 없고(numpy 만), 브라우저 · 파이썬 특징 차이가 사라진다(브라우저가 만든 숫자로 배우고 브라우저가 쓴다).
- 정답 · 무게 · 시험 묶음 · 판 바꾸기 조건은 2026-10-23 설계서 §3.7 그대로(사람 1 · 손대지 않고 전달한 AI 0.5). `.m` 이름표는 0.5 묶음에서 뺀다(기억에서 베낀 것이라 겹친다).
- 새 판으로 바꾸기는 지금처럼 코드 변경(사람 확인). 자동으로 판을 바꾸는 것은 이번 범위 밖(§7-5).

### 3.6 측정 (문턱 다듬기)

- 새 도구 `tools/drawing_ai/memory_report.py`(numpy, DB 읽기 전용): 최종 이름표가 있는 그림마다(사람 이름표 + 손대지 않고 전달한 AI 이름표),
  **그 그림보다 먼저 있던 사람 기억만으로** 찾아본다(시간 순 한 장 빼기).
  - 덮는 비율: 문턱을 넘은 기억이 있던 그림의 비율.
  - 맞힘: 그중 기억 종류 = 최종 종류인 비율. 목표 98% 이상(지금 AI 자동 이름표 정확도와 같은 줄).
  - 따로 보기: 내부/도어 · 같은 주문/다른 주문 · AI 가 틀렸거나 미분류였던 그림을 기억이 몇 장 살렸나.
  - 문턱별 표(0.90 ~ 0.995)를 보고 `min_sim` · `min_sim_door` 를 고른다.
  - 같은 그림에 사람마다 다른 종류를 고른 경우를 모아 보여 준다 — 도면팀과 기준을 맞출 때 쓴다(사람 평가용이 아니다).
- 운영 DB 를 읽으므로 돌릴 때마다 사용자 허락. 켜기 제안 기준: 문턱을 넘은 그림 50장 이상 · 맞힘 98% 이상.
  사람 이름표가 하루 몇 장이라 이 기준을 채우는 데 몇 주에서 몇 달 걸릴 수 있다(기간을 정해 두지 않는다).

### 3.7 서버 API

1. `POST /api/orders/<order_id>/drawing-wizard/part-memory` — 남기기(M1)
   - 권한: 마법사 저장과 같다(`_can_save_wizard` — 관리자 · 도면 작업실 참여자). 정책 `DRAWING_ASSIGNED`. CSRF 는 마법사 다른 쓰기와 같다.
   - 몸: `{items: [...]}` 최대 30줄 · 96KB.
   - 검증(하나라도 틀리면 그 요청 전체 400):
     `key` 접두 `orders/<order_id>/drawing_wizard/assets/` · `f` 는 base64 2,048자 → 1,536바이트 · 모든 값 유한 · 길이(L2) 0.9 ~ 1.1 ·
     `fv` 규칙 `^[a-z0-9.-]{1,16}$` · `label` · `ai` 는 `_PART_LABELS` · `src` 는 `ai`/`user` · `conf` 0~1 · `head` 는 `_PART_HEAD_RE` ·
     `kind` 는 네 값 · 주문당 줄 상한 2,000.
   - 같은 `(order_id, asset_key)` 는 덮어쓴다: 특징은 같은 판이 이미 있으면 그대로, 없거나 판이 다르면 새 값. 이름표 · 출처 · AI 짐작은 새 값.
   - 응답 `{success, data: {saved, missing: [key…]}}`.
   - 감사: 잦은 자동 쓰기라 SecurityLog 를 남기지 않고 줄마다 `created_by` · `updated_by` 를 남긴다.
     감사 allowlist(EXEMPT) 사유: "AI 학습용 특징 · 이름표 사본 — 이름표 원본은 마법사 저장(감사됨)에 있다."
2. `POST /api/orders/<order_id>/drawing-wizard/part-memory/match` — 찾기(M2-a · M2-b)
   - 권한 · 정책 같음. 꺼져 있으면 `{success: true, data: {enabled: false}}`.
   - 몸 `{items: [{id, f, fv} | {id, key}]}` 최대 30. `key` 는 서버에 남은 특징으로 찾는다.
     `scope: 'order'` 면 같은 주문의 AI 이름표 그림 중에서 닮은 그림 키를 돌려준다(M2-a), 없으면 다른 주문 사람 기억에서 찾는다(M2-b).
   - 응답 `{items: {id: {label, sim, n, conflict, scope: 'order'|'other'} | null}}`.
   - 계산: 서버 프로세스가 사람 이름표 줄의 특징을 메모리에 들고 있다가 바뀐 줄만(`updated_at`) 다시 읽고 numpy 로 코사인을 잰다.
     줄이 5만을 넘으면 pgvector 로 옮긴다(운영 DB 에 이미 있다 — `designer_pgvector` 리비전).
3. `POST /api/orders/drawing-wizard/part-memory/disable` — 잘못된 기억 끄기(M2-b). 관리자 · 도면팀(§7-4), SecurityLog 감사.
- 켜고 끄기 값: SystemSetting `drawing_part_memory` `{store, suggest, follow, min_sim, min_sim_door}`.
  저장이 없으면 코드 기본값(store 켬 · suggest = §7-2 결정 · follow 끔).
  마법사 화면에 `data-*` 로 내려 준다.

### 3.9 시험

- 서버(SQLite): 거부 규칙 각각 · 권한 403 · 덮어쓰기(같은 판 특징 유지 · 판 다르면 바꿈) · `missing` · 줄 상한 ·
  찾기 판정(문턱 · 갈림 · 내부/도어 문턱 · 자기 제외 · 판 다름 · 꺼짐 · 같은 주문 AI 이름표만) · 캐시가 바뀐 줄을 반영.
- PG 레인: 마이그레이션 체인(모델 = 리비전).
- 화면(node 계약 시험): float16 왕복 · base64 길이 · 이름표 목록 견주기(사람 > 나중 · 되돌리기 반영) · 차례 보내기 ·
  실패해도 분류 · 배치가 안 막힘 · `.m` 이름표와 짝 규칙 건너뜀 · 같이 고치기 후보(사람 이름표 · 짝 빼기 · 내부/도어 문턱) · [바꾸기] 되돌리기 한 번.
- 도구: 합성 자료로 측정 표(덮는 비율 · 맞힘 · 문턱별).
- 실화면: 로컬 dev → 스테이징 시험 주문 #4464. M1: 그림을 올리고 고친 뒤 표에 특징 · 이름표가 들어갔는지, 되돌리기가 반영되는지.
  M2-a: 닮은 그림 여러 장을 올리고 한 장을 고치면 [바꾸기] 묻기가 뜨는지, 누르면 같이 바뀌고 Ctrl+Z 한 번에 돌아오는지.
  M2-b(스테이징만 켬): 같은 그림을 다른 주문에 올리면 사람 이름표를 따르는지, 이유가 보이는지. 서버를 꺼도 마법사가 정상인지.

## 4. 단계

| 단계 | 내용 | 도면팀 화면 |
|---|---|---|
| (먼저) | AI 마법사 운영 반영 — 따로, 사용자 요청 때 | 그림 종류 칩 · 자동 배치 |
| M1 | 남기기만 + 측정 도구 | 바뀜 없음 |
| M2-a | 같은 시트 같이 고치기(바로 바꾸고 알림, 되돌리기 한 번) — 처음부터 켬 | 한 장 고치면 "비슷한 그림 N장도 같이 바꿨어요" |
| M2-b | 새 그림이 사람 기억 따르기 — 처음부터 켬(보수적 문턱), 측정으로 다듬기 | 새 그림이 'AI 기억' 표시와 함께 사람 종류를 따름 |
| M3 | 다시 가르치기가 이 표를 읽기(고친 기록 100건 이상 때) | 판이 바뀌면 AI 가 더 잘 맞힘 |

## 5. 위험과 막는 법

- **잘못 고른 기억이 퍼짐**: 같은 주문 같이 고치기는 늘 사람이 확인한다. 다른 주문 기억 따르기는 처음엔 꺼 두고 측정 뒤 켠다 ·
  문턱 · 갈림 · 내부/도어 문턱 · 사람이 늘 이김 · 기억 끄기 · 이유 표시.
- **기억이 천천히 쌓임**: 사람이 고르는 그림이 하루 몇 장이라 다른 주문 기억은 몇 달에 걸쳐 자란다. 바로 보이는 효과는 같은 주문 같이 고치기다.
- **같은 가구의 내부/도어 그림이 닮음**: 문턱을 따로 두고 측정도 따로 한다. 안 맞으면 기억은 보기(정면 · 입체 …)만 정한다.
- **고객 자료**: 그림은 보내지 않고 숫자만 우리 DB 에 둔다. 외부 서비스로 보내지 않는다. 주문을 지우면 함께 지운다.
- **서버 부하**: 남기기는 1초 모아 한 번 · 찾기는 메모리 캐시 · 마법사 저장(PUT) 경로는 건드리지 않는다.
- **모델이 바뀌면**: 특징 판(`feat_v`)이 다르면 섞지 않는다. 새 모델이면 기억이 다시 모인다(필요하면 다시 뽑기 도구를 따로).
- **기억 호출 실패**: 언제나 조용히 지나가고 분류 · 배치 · 저장을 막지 않는다(failopen 인벤토리에 사유).

## 6. 안 하는 것

- 분류기 가중치를 실시간으로 고치기 · 브라우저마다 따로 배우기.
- 사람 확인 없이 운영 분류기 판을 자동으로 바꾸기.
- 그림 자체를 새로 저장하거나 밖으로 보내기.
