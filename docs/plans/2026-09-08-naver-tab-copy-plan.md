# 네이버 수집탭 문구 정리 계획 (2026-09-08)

## 1. 왜

담당자 지적: **"네이버 수집탭에 전반적으로 너무 말이 길고 어색한 문장이 많다."**

오늘 두 문장을 이렇게 줄였다. 이것이 기준선이다.

| 전 | 후 |
|---|---|
| 이 주문에는 아직 살아 있는 결제가 있습니다 — 상품주문 7건 중 1건만 취소됐습니다. 전부 취소된 뒤에 접습니다. | **부분 취소 건 — 상품주문 7건 중 1건만 취소됐습니다** |
| 이 주문은 발송처리가 끝났습니다 — 취소가 필요하면 반품 접수를 쓰세요. 승인·환불은 모달에서 승인까지 한 번에 를 켜거나, 판매자센터에서 합니다. | **이 주문은 발송처리가 끝났습니다.** |

읽는 법: **남은 것은 숫자와 판정. 사라진 것은 앞머리·훈수·다른 버튼 사용법.**

지금 남은 군살은 오탈자가 아니다. 최근 이 화면은 사실을 더 정직하게 말하려다 문장이 길어졌다(유령 문장 사실화·실측 맥락·휴지통 표기·옛 결제 승인). 그때 붙인 설명과 훈수가 대상이다.

---

## 2. 이 화면을 쓰는 사람

**네이버 주문 대행 담당자.** 스토어에 들어온 결제를 ERP 주문으로 옮기고, 네이버 쪽 버튼(발주확인·발송처리·취소·반품)을 우리 화면에서 대신 눌러 준다. 하루는 "이 집을 어떻게 처리할지 고르고, 네이버로 나가는 되돌릴 수 없는 호출을 정확히 한 번 보내는 것"이다. 단위는 낱개가 아니라 **집(묶음)** 이라, 머리 스트립의 `처리 N주문`과 `상품주문 N건`을 매일 구분해 읽는다. 브라우저를 80%로 축소해 목록을 최대한 많이 띄워 놓고 쓰며, 같은 문장을 하루에 수십 번 다시 읽는다 — **첫 독해 비용보다 재독 비용이 지배한다.** 한 화면을 STAFF·ADMIN·회계팀이 함께 보므로, 문장이 말할 것은 "관리자만 아는 배경"이 아니라 **지금 이 사람이 누를 수 있는지 없는지**다. 취소·반품 사유는 고객에게 그대로 나가고, 담당자는 화면을 보며 통화 중일 수 있다. 문장은 판단 재료여야 한다. 교육 자료·변명·사용 설명서가 되면 안 읽힌다.

## 3. 문장 규칙

### 줄이는 것 (R1)

| 갈래 | 내용 |
|---|---|
| R1-a 앞머리 설명 | 결론 앞에 붙은 배경. 판정을 먼저 놓는다. |
| R1-b 맺음말 훈수 | "~한 뒤에 하세요", "잠시 뒤 다시 확인하세요". 그 버튼이 같은 화면에 있으면 말하지 않는다. |
| R1-c 버튼이 이미 말하는 것 | 버튼 라벨·꼬리표·모달 제목과 같은 뜻의 문장. |
| R1-d 같은 사실의 재진술 | 한 화면에서 두 번 말하는 사실. 자리마다 보는 사람이 다르면 재진술이 아니다. |
| R1-e 시스템 자기 변명 | "화면이 알 수 없습니다"의 **이유 설명**. 사실은 남기고 사유 서술만 줄인다. |

### 절대 안 줄이는 것 (R2)

| 갈래 | 내용 |
|---|---|
| R2-a 돈이 걸린 경고 | 환불 확정·취소 확정·"되돌릴 수 없습니다"·"고객에게 그대로 보입니다". 한 글자도 안 흐린다. |
| R2-b 불가역 동작의 범위 | 몇 건이 나가고 몇 건이 안 나가는가. 새 결제인가 옛 결제인가. 한 번에 저장되는가. |
| R2-c "모른다"는 사실 | 추정·단정으로 바꾸지 않는다. 짧게는 해도 확신을 올리면 안 된다. |
| R2-d 숫자와 단위 | 집(주문) ↔ 상품주문 구분. 두 축을 한 문장에 섞지 않는다. |
| R2-e 왜 잠겼는가 | `disabled` 사유. **title 에만 있으면 안 된다** — 터치 기기는 못 읽는다. |
| R2-f 남이 한 일 / 진행 중 | 누가 시작했는지, 지금 돌고 있는지. 중복 실행을 막는 사실이다. |

### 길이 (R3)

- 한 줄에 한 사실.
- 둘째 문장은 근거를 대야 산다. "없으면 담당자가 무엇을 잘못하는가"를 한 줄로 못 적으면 삭제.
- 줄표(—) 뒤 절은 사실이면 살고 훈수면 죽는다.
- 판정·라벨은 명사구로 끊는다. 경고(R2-a)는 완결 문장을 유지한다.
- 금지: 한자, 영문 enum 노출, 같은 화면에서 같은 수 두 번.
