## 1. 문제 A — 시트 사이 그림 id 겹침

### 1.1 지금
- 서버 `_validate_wizard_state`(foms/api/drawing/wizard.py)는 시트마다 `_validate_sheet` 만 돌린다. 시트 사이에 같은 객체 `id` 가 있어도 그대로 저장한다.
- 브라우저의 복제·붙여넣기·버전 복원은 늘 새 id 를 만든다(10-25 확인). 겹침은 **버그 길에서만** 생긴다. 10-25 실화면 QA 에서 찾은 길 하나(나누기 뒤 지운 새 시트를 '되돌리기'로 살리기)는 브라우저 쪽에서 막았다(`restoreDeletedSheet`).
- 겹치면 생기는 일: 같은 그림이 두 시트에 보이고, 한쪽을 지우거나 옮기면 다른 쪽과 헷갈린다. 다시 가르치기 자료(`tools/drawing_ai/retrain_data.py`)는 그림 저장 키(`key`)로 겹침을 없애므로 학습 숫자는 두 번 세지 않는다.

### 1.2 제안
1. **먼저 잰다(읽기만).** 스테이징 전체와(자유) 운영(사용자 허락 1회, 읽기·측정만)에서 `structured_data.drawing_wizard.sheets[*].objects[*].id` 가 시트 사이에 겹치는 주문 수·객체 수를 센다. 개인 정보는 남기지 않고 숫자만 보고한다.
2. **브라우저가 불러올 때 고친다(서버 변경 없음).** `normalizeState` 뒤에 시트를 앞에서부터 보며, 앞 시트에 이미 있는 id 를 뒤 시트에서 만나면 새 id 로 바꾼다(그림은 그대로 두 장 다 남김 — 무엇을 지울지는 사람이 정한다). 바꿨으면 한 번만 알림: '같은 그림이 두 시트에 있어 뒤쪽 시트의 그림을 따로 떼었어요 — 필요 없으면 지워 주세요'. 저장할 때도 같은 검사를 한 번 더 돈다.
3. **서버는 기록부터.** `_validate_wizard_state` 에 시트 사이 id 겹침 검사를 더하되, 처음 판은 **거절하지 않고** 감사 기록(SecurityLog 가 아니라 앱 로그 경고 + 숫자 지표)만 남긴다. 2주 동안 운영에서 0건이면 거절(400, '같은 그림이 두 시트에 있습니다 — 새로고침 뒤 다시 저장해 주세요')로 바꾸는 작은 PR 을 따로 낸다.
   - 바로 거절하지 않는 까닭: 이미 겹친 자료가 있는 주문은 다음 저장부터 막혀 일을 못 한다. 브라우저 고침(2)이 먼저 퍼져야 한다.

### 1.3 시험
- 브라우저: 겹친 시트 둘을 불러오면 뒤 시트 id 만 바뀌고 그림 수·자리는 그대로, 알림 1번, 저장 본문에 겹침 0(node 러너).
- 서버: 겹친 상태 PUT → 1판은 200 + 경고 로그 1줄(caplog), 2판은 400. 겹침 없는 상태는 그대로 200.

## 2. 문제 B — 전달본 '예전 것' 정확히 가리기

### 2.1 지금
- 전달 대기함 항목: `structured_data.drawing_wizard.pending[sheet_id] = {key, filename, at, sheet_name}`(`api_post_drawing_wizard_sheet_png`).
- 브라우저는 '넣은 뒤 고쳤나'를 그림 지문(`FomsSaveStatus.sheetSig`)으로 가른다. 이 창에서 넣었으면 넣을 때 지문을, 다시 연 창이면 **불러올 때의 지문**을 기준으로 쓴다(10-25 고침). 그래서 '넣고 → 더 고치고 → 자동 저장 → 창 닫음 → 다시 엶' 이면 불러온 상태가 이미 고친 뒤라, 첫 편집 전까지 초록 '전달 대기함'으로 보인다(실제로는 예전 것).

### 2.2 제안
- [저장](`sheet-png` POST) 때 브라우저가 form 칸 `sig` 를 함께 보낸다: `'v1:' + sheetSig(sheet)`(판 표시를 붙여, 지문 계산을 바꾸면 v2 로 올려 예전 것과 섞이지 않게).
- 서버는 형식만 본다(`^v\d{1,2}:[0-9a-z]{1,24}$`, 넘으면 버림 — 거절하지 않음) → `pending[sheet_id]['sig']` 로 남긴다. `_pending_list` 가 `sig` 를 함께 돌려준다.
- 브라우저: 목록의 `sig` 가 있고 판이 같으면 그것을 기준으로 '전달 대기함'/'전달본 예전 것'을 정한다. 없거나 판이 다르면 지금처럼(불러올 때 지문).
- 작업실 일괄 전달(`stage_pending_snapshot`)은 항목을 옮길 때 `sig` 를 그대로 둬도 되고 버려도 된다(전달 뒤에는 쓰지 않음) — 버린다.

### 2.3 호환·되돌리기
- 예전 항목(`sig` 없음)과 예전 브라우저(안 보냄)는 지금 동작 그대로. 칸 하나가 늘 뿐 JSONB 크기 영향은 항목마다 30바이트 안.
- 되돌리기: 브라우저가 `sig` 를 안 쓰게 되돌리면 끝(서버 칸은 남아도 무해).

### 2.4 시험
- 서버: `sig` 를 보낸 POST → pending 항목과 GET 목록에 같은 값, 형식이 틀리면 칸 없이 저장(200), 안 보내도 200.
- 브라우저: 다시 연 창에서 목록 `sig` ≠ 지금 지문이면 '전달본 예전 것', 같으면 '전달 대기함', 판이 다르면 예전 규칙(node 러너, 날짜는 '오늘'로 만든다 — 10-26 날짜 시험 사고).
