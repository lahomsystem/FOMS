# 회사 지식 온톨로지 — 깊은 비평 종합 (2026-11-26)

사장님 11-26: "통 수 지식 뿐만이 아니라, 학습지식, 저장 된 지식 전체를 온톨로지 화 해서 연결 하는게 최종 목표야 > 지금 구현 된 프로세스가 목표에 부합 하는지 deep critique 해 봐 > 가능 한 모든 자원 동원".

일꾼 열이 따로 읽었다. 1차 일곱(틀 · 들어오는 길 · 쓰는 길 · 운영 자료 감사 · 사람 손 · 재는 길 · 바깥 사례), 2차 셋(진단 반대 심문 · 처방 반대 심문 · 목표 과정 안). **일꾼 보고는 주장이다** — 아래 '확인' 표시는 총괄이 코드 · 자료를 직접 열어 본 것만이다. 고친 것은 아직 없다.

전체 보고서 열 장과 운영 지식 자료는 회사 지식 글이 들어 있어 저장소 밖에 둔다(총괄 PC `c:\tmp\foms-onto-critique\` — `0-받은요약.md` 에 받은 요약 전부와 확인 기록). 이 파일에는 판단과 코드 자리만 적는다.

## 1. 한 줄 판정

지금 과정은 **글 지식을 쌓는 과정이지 잇는 과정이 아니다.** 목표에 맞지 않는 곳이 세 군데이고, 셋이 같이 풀려야 한다.

1. **들어오는 길이 잇기를 만들지 않는다.** 잇기 319개 중 316개는 11-13 사람이 돌린 계획 길이 만들었다. 밤 배우기가 살아 있는 항목에 건 잇기는 0개.
2. **틀이 '사실'의 잇기를 막는다.** 밤 배우기는 대부분 '사실'로 적는데 사실에서 제품 · 옵션 · 가격 규칙 · 용어로 가는 허용 짝이 없다.
3. **이어 둬도 읽는 쪽이 거의 없다.** 잇기를 읽는 AI 길은 물어보기와 (지금 꺼진) 상담 초안뿐이다. 카드를 만드는 판정 길 · 셈 · 보내기 전 검사는 잇기를 읽지 않는다.

덧붙임(처방 반대 심문): 잇기 그 자체는 값이 아니다. 일곱 보고서에서 '잇기가 없어서 생긴 실제 손해'로 확실한 것은 0건, 반쯤 걸친 것 1건(발단 카드)이다. 목표는 잇기 수가 아니라 결과(새 두 벌 수 · 가짜 엇갈림 카드 비율 · 값이 바뀐 뒤 놓친 베낀 글 수 · 셈 질문 정답률)로 재야 한다.

## 4. 뒤집히거나 깎인 것 (종합에서 쓰지 않는다)

- '잇기를 따라가는 쪽이 아예 없다' → 물어보기는 따라간다.
- '밤 배우기에 합치는 걸음이 없다' → 있다. 없는 것은 붙이기.
- '못 잇는 비율 8 ~ 9할' → 전체 약 6할.
- '겹침 66%' → 같은 내용 두 벌은 25%.
- '11-13 뒤 새 지식 300여 개' → 161개.
- '넘김 19건은 빈 지식 문제' → 가를 수 없다(판정자는 헷갈리면 '없음').
- 개념 열쇠(같은 개념을 묶는 새 키) → 처방 심문이 버림. 같은 내용은 '같음 잇기'가 아니라 합치기로.
- 그래프로 찾기(GraphRAG 류) · 그래프 DB → 우리 크기에는 값이 없다(바깥 사례). 잇기는 지식을 지키는 데(두 벌 · 어긋남 · 값 바뀜 알리기) 쓴다.

차례 0 ~ 3 이 과정 안의 '작게'(10 ~ 13일 · 밤 돈 거의 0), 4 ~ 6 까지가 '가운데'(23 ~ 31일), 7 까지가 '제대로'(43 ~ 58일)다. 날 수는 설계자 일꾼의 어림이다.

사람 승인 없이 넣으면 안 되는 잇기(처방 심문): 금액 정본(`value_from`) · 베낀 글(`copy_in`) · 유효 끝을 찍는 것(`supersedes`) · '안 돼요 / 꼭 같이'(`excludes` · `requires`) · 합치기 · 종류 바꾸기 · 브랜드를 넘는 것 · 가격 규칙 · 사장님 결정 · 기준 답에 닿는 것 · 셈과 검사가 읽을 것.

## 6. 사장님께 여쭐 것

1. 어느 길로 — 작게 / 가운데 / 제대로 / 가운데까지 하고 결과 보고 정하기.
2. AI 가 찾은 연결을 넣는 법 — 모두 체크 / 뻔한 것은 바로 / 처음 2주 체크 뒤 다시 정하기.
3. 여닫이 통 수가 설치 폭으로 늘 하나로 정해지는지, 표 값을 어떻게 받을지.
4. 밤 배우기 돈 — 아끼는 장치 먼저 / 연결 일만 따로 더 / 상한 올리기.
5. (설계 글 때) 같은 내용 두 벌 합치기 범위 · 하우드 ↔ 라홈 · 한글 표에서 '온톨로지'는 사장님 말 그대로 둠.

## 7. 확인 못 한 것

- 운영 관리 칸의 지금 값(초안 스위치 · 바꿔 묻기 · 견적 계산 넣기).
- 발단 카드가 실제로 어느 판정 길에서 나왔는지 · 그 밤 후보에 발단 항목이 들었는지.
- 쓰임 표 둘의 실제 수.
- 밤 배우기 목록을 캐시로 굳혔을 때 실제 적중률.
- 틀 넓힘으로 풀리는 몫(설계자 어림 7할 ~ 8할 반) — 설계 글 때 `link_allowed` 를 새 표로 다시 돌려 센다.
- 계산기 실제 금액과 글 속 금액의 대조.
