AI 에이전트를 위한 Spec Driven Development 요약
1. 문제 정의: 바이브코딩의 한계 (0:00-0:59)
현상: AI(ChatGPT, Claude 등)를 즉흥적으로 사용하여 초기에는 만족하지만, 수정 요청 시 의도와 멀어지거나 비효율적인 결과가 발생.
용어: 이 즉흥적인 방식을 바이브코딩(Vibe Coding) (0:30)이라고 지칭.
문제점:
동일한 요청이라도 표현에 따라 다른 결과 초래.
수정 요청이 반복될수록 초기 의도에서 벗어남.
이는 단순히 불편함을 넘어선 근본적인 한계.
해결책의 필요성: 아마존, 깃허브 등 글로벌 기업들도 이 문제에 공감하여 새로운 방식 모색 시작.
2. 해결책: Spec Driven Development (SDD) (0:59-2:14)
정의: AI에게 작업을 지시하기 전에 '완벽한 주문서'를 먼저 작성하는 방식 (1:02).
핵심 원리: 명확하고 구체적인 요구사항이 모호한 지시보다 항상 우수한 결과를 도출.
주문서 작성 3가지 원칙:
무엇을 원하는가 (What): 최종 결과물 및 기능적 요구사항을 구체적으로 명시 (1:41).
예: "사용자가 이메일과 비밀번호로 로그인할 수 있어야 한다. 로그인 실패 시 에러 메시지 표시. 3회 실패 시 계정 잠금 처리."
어떻게 만들 것인가 (How): 전체 구조, 순서, 방향성을 제시 (1:53).
예: "데이터 인수 순서에 따라 처리 로직을 구현."
무엇을 하나씩 해야 하는가 (Steps): 작업 단계를 체크리스트 형태로 분할 (1:59).
예: "1단계: 사용자 인증 모듈 개발. 2단계: 에러 처리 로직 구현. 3단계: 계정 잠금 기능 추가."
3. SDD 도구 및 제안: 하니스 워크플로우 (2:14-3:46)
기존 도구의 한계:
Kiro (아마존): 특정 서비스에 종속적, 유연성 부족 (2:24).
Spec-Kit (깃허브): 복잡한 사용법, 낮은 성능 체감 (2:29).
BMAD (오픈소스): 학습 시간 소요, 역할 놀이 같다는 느낌 (2:33).
공통 문제: 프로젝트 및 작업 방식에 대한 커스터마이징의 어려움 (2:38).
제안된 해결책: 하니스(Harness) 기반 워크플로우 직접 구축 (2:54).
개념: AI가 자유롭게 작업하되, 정해진 방향에서 벗어나지 않도록 잡아주는 '안전 장치' 구조 (2:57-3:10).
구성 요소:
프로젝트 맥락 파일: 프로젝트 목표, 제약 조건, 기결정 사항 등 AI가 항상 인지해야 할 정보를 포함 (3:11).
작업 요청 템플릿: AI에게 작업을 요청할 때 사용하는 일관된 형식 (3:18).
결과 검증 체크리스트: AI 결과물 확인을 위한 기준 목록, 신속한 검증 가능 (3:27).
장점: 특정 AI 도구(ChatGPT, Claude 등)에 구애받지 않으며 (3:37), 사용자의 작업 방식에 최적화된 설계 가능 (3:43).
4. SDD 작동 원리: 3가지 핵심 이유 (3:46-4:49)
AI의 '기억 상실' 문제 해결:
AI 약점: 대화 세션이 바뀌면 이전 컨텍스트를 망각 (3:57).
SDD 해결: 주문서 문서가 AI의 '기억'을 대체. AI는 문서를 통해 맥락을 파악하므로, 반복적인 설명 불필요 (4:04).
역할 분담 및 집중:
비효율: AI가 '무엇을 만들지'와 '어떻게 만들지'를 동시에 고려하는 것은 비효율적 (4:19).
SDD 해결:
사용자가 먼저 '무엇을 만들지' 주문서 작성 (4:24).
AI는 '어떻게 만들지'에만 집중 (4:27).
효과: 각 역할에 대한 집중도를 높여 효율성 극대화.
반복 작업의 안정성 확보:
문제: 반복적인 수정 요청 시 초기 의도와 멀어지는 경향 (4:35).
SDD 해결: 주문서가 '북극성' 역할. AI가 벗어나려 할 때 주문서가 올바른 방향으로 재조정 (4:41).
효과: 일관성 있고 안정적인 결과물 유지.
5. 실전 적용: 지금 바로 시작하는 방법 (4:49-5:32)
대상: 개발자 외 AI를 활용하는 모든 사용자 (기획자, 마케터 등) (5:25).
간단한 시작 방법: ChatGPT나 Claude에 요청하기 전에 다음 세 가지를 메모장에 먼저 정리:
최종 결과물이 정확히 무엇인가? (4:57)
어떤 조건이나 예외 상황이 존재하는가? (4:59)
어떤 순서(단계)로 작업을 진행하면 좋을까? (5:01)
결과: 이 간단한 정리만으로도 AI 결과물의 품질이 크게 향상됨 (5:04).
핵심 요약: AI에게 지시하기 전에 '명확하게 적는 것' 이 가장 중요 (5:32-5:35). SDD는 복잡하고 중요한 프로젝트에서 특히 효과적 (5:18-5:22).
