# 🚨 긴급 알림 및 브리핑 보드 연동 시스템 구축 계획

## 1. 개요 및 목적
현재 FOMS의 알림 시스템은 종 모양(🔔) 아이콘의 단순 숫자 증가와 리스트 추가에 머물러 있어, **긴급한 공지나 1:1 멘션** 발생 시 즉각적인 업무 인지가 어렵습니다. 
이를 해결하기 위해, 새로 구축된 **개인 브리핑 보드 열기 버튼(Chevron)**과 **보드 내 위젯**에 **요란하고 확실한 시각・청각적 이펙트**를 추가하여 사용자가 즉각적으로 반응할 수 있는 '강제 인지 UX'를 도입합니다.

## 2. 신규 알림 발송 채널 구축 (백엔드)

### A. 관리자 전용 '긴급 공지' 발송 기능
*   **어디에?**: 사용자 관리 등 관리자 메뉴 영역에 `[🔔 공지/알림 발송]` 전용 화면 추가.
*   **어떻게?**: 타겟(전체/특정 팀/특정인) 지정 및 **"긴급 여부(Urgent Checkbox)"**를 포함하여 메시지 발송. `Notification` 테이블에 `is_urgent=True` 및 `notification_type='URGENT_ANNOUNCEMENT'` 기록.
*   **발송 처리**: `Socket.IO`를 통해 접속 중인 대상자들에게 `erp_notification` 이벤트(payload: `urgent: true`) 실시간 전파.

### B. 주문 상세 1:1 '긴급 멘션(@)' 기능
*   **어디에?**: /erp/dashboard, 제작, 시공 등 각 주문 상세의 타임라인/메모 작성란.
*   **어떻게?**: `@사용자이름` 태그를 인식하거나 전용 '동료 즉시 호출(긴급)' 버튼 배치.
*   **발송 처리**: `Notification` 생성 후 대상자에게 `Socket.IO` 긴급 이벤트 전파. 클릭 시 대상 주문 상세 화면으로 딥링크.

## 3. 강제 인지 UX 구현 (프론트엔드 - layout.html)
`layout.html`에 웹 소켓 수신부를 보강하여, 긴급 이벤트(`urgent: true`) 수신 시 다음 3단계의 강제 인지 효과를 실행합니다.

### A. 중앙 브리핑 보드 버튼의 "요란스러운" 시각적 변화
`<button class="btn personal-briefing-chevron-btn" id="personal-briefing-toggle">`
*   **에러 펄스(Pulse) 애니메이션**: 붉은색 테두리 또는 붉은 글로우(Glow) 효과가 빠른 타이밍으로 반복 점멸.
*   **아이콘 스와핑**: 기존의 `fa-chevron-down` 모양이 긴급 아이콘인 `fa-exclamation-triangle` (빨간색)로 잠시 바뀌거나 좌우로 크게 흔들리는 쉐이크(Shake) 애니메이션 적용.
*   **뱃지 표출**: 쉐브론 버튼 곁에 빨간색 점(Dot) 혹은 "NEW 긴급" 라벨 툴팁이 팝업.

### B. 청각적 피드백 (Alert Sound)
*   긴급 알림 수신 시, 브라우저 `Audio` 객체를 활용하여 짧고 명확한 경고음(예: 띠링! 혹은 삐빅!) 1회 재생.
*   (단, 브라우저 정책 상 사용자의 최초 인터랙션이 발생한 이후에만 재생되므로 예외 처리 추가)

### C. 개인 브리핑 보드 내부 (Offcanvas) UX 강화
사용자가 놀라서 버튼을 클릭하여 브리핑 보드를 열었을 때:
*   **상단 강제 배너**: 오프캔버스 최상단 영역에 붉은색의 `[긴급] 관리자 공지: ...` 또는 `[긴급 멘션] 이수영 님이 #1245 주문에서 호출했습니다.` 배너가 가장 먼저 보이도록 추가.
*   **해당 위젯 강조**: '공지/알림' 카드의 테두리가 붉은색으로 깜빡이거나 배경을 연한 붉은색(`#fff5f5`)으로 전환하여, 어디를 클릭해야 할지 즉시 안내.

## 4. 데이터 플로우 및 개발 범위 요약

1.  **DB & Model**: `Notification` 테이블에 긴급 여부를 알 수 있는 플래그(`is_urgent` boolean 컬럼 또는 `notification_type` 세분화) 추가.
2.  **API**: `/api/notifications/send` (가칭) 신규 구축. Socket.IO `emit` 로직에 `is_urgent` 속성 부여.
3.  **UI (발송)**: 관리자용 공지 발송 화면, 주문상세용 멘션(호출) 버튼 추가.
4.  **UI (수신 - layout.html)**:
    *   CSS Keyframes 추가 (`@keyframes urgentPulse`, `@keyframes shake`).
    *   JS Socket.IO 수신 핸들러 업데이트 (긴급일 경우 오디오 재생 및 버튼 DOM 클래스 토글).
    *   `api_summary` (개인 보드 API)에 긴급 알림 건수/내역만 최상단으로 별도 추출하는 로직 추가.

## 5. 실행 순서
*   **Step 1**: 프론트엔드 수신 UI 선행 적용 (layout.html에서 소켓 수신 시 버튼 요란하게 흔들리기 & 오디오 재생 & 보드 안 빨간 표시).
*   **Step 2**: 백엔드 API (긴급 여부 속성 모델 추가 및 발송 API).
*   **Step 3**: 관리자 공지 발송 화면 및 기능 연동.
*   **Step 4**: 각 업무 영역 딥링크 연동 및 테스트.
