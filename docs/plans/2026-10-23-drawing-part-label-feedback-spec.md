## 2. 바뀐 순서

1. **① 스케치업** — 그대로. (선택 사항) 파일 이름에 모듈 폭·구성을 넣는 규칙을 정하면 ③을 미리 채울 수 있음(§3.4).
2. **② 불러오기 → 자동 정리** — 여러 장을 올리면:
   - AI가 그림마다 종류를 붙임(정면·내부/정면·도어/입체·내부/입체·도어/평면·상판/서랍 단면/부품 상세/사진/그림 아님). 확신이 낮으면 '미분류'.
   - 종류에 맞춰 자리를 자동으로 잡음(§3.2).
   - 사람은 틀린 이름표와 자리만 고침.
3. **③ 자재표 → 계산 칸 입력 → 자동 계산 → 확인 후 넣기** — 전체 크기와 모듈 구성만 넣으면 [SR][DOOR][옷봉][마이다] 줄을 계산해 보여 줌. 사람이 보고 '넣기'를 눌러야 글자로 들어감(§3.3).
4. **④ 저장·전달** — 저장할 때 사람이 고친 기록이 함께 남음. 그 기록으로 그림 분류 AI를 다시 가르치고(§3.5), 계산 규칙이 어디서 틀리는지 모음.

## 3. 설계

### 3.1 그림 종류 자동 분류 (②)
- **실력**(실험 §8, 마법사 그림 1,040장, 주문 단위로 나눠 시험):
  - 전체 95.6%
  - 제품별: 붙박이장 98.8% · 냉장고장 97% · 그 밖 장 92% · 주방 85%. 주방은 짝 규칙을 함께 쓰면 90%.
- **어디서 돌리나**: 브라우저에서 onnxruntime-web 으로 돌림. 서버에 onnxruntime 을 올리면 FOMS 고정 numpy==1.26.4 와 충돌함. 그림은 브라우저 밖으로 나가지 않고, 외부 AI 서비스도 쓰지 않음.
- **모델 구성**:
  - DINOv2-small int8(24MB, Apache-2.0)은 처음 한 번 받고 캐시함.
  - 마지막 판단 부분(분류기 머리, 수십 KB JSON)은 판 번호를 붙여 따로 둠.
- **확신 문턱**: 0.5보다 낮으면 '미분류'로 둠. 실험에서는 이 문턱으로 75%를 자동으로 붙였고, 붙인 것의 98%가 맞음.
- **주방 짝 규칙**: 같은 시트에서 같은 보기(정면/입체)로 짐작한 그림이 딱 둘이면, 빗금이 많은 쪽을 내부로 봄. 주방 시트에만 씀. 다른 제품에 쓰면 정확도가 오히려 내려감.
- **이름표 저장**: 그림 객체에 선택 필드 `part` 를 더함.
  - 모양: `{"label": "입체·도어", "src": "ai"|"user"|"confirmed", "ai": "입체·내부", "conf": 0.62, "head": "h1"}`
  - label 은 닫힌 목록 9칸 + 미분류.
  - 검증은 `wizard.py:368` 에 더함.
  - 옛 시트는 이 필드가 없어도 그대로 통과함.

### 3.2 자동 배치 (②)
- **배치 칸**: 머리(y 70) 아래, 아래 표(`TBL_Y0`=899) 위. 자재표 글자 상자(머리글 줄 y 120부터 아래로 자람)는 피함.
- **놓는 순서**: 캔버스 시안 J01~J11 에서 맞춰 본 틀을 씀.
  - 큰 그림 줄: 정면·내부 바로 옆에 같은 모듈의 정면·도어 → 입체
  - 평면·상판은 그 아래
  - 서랍 단면·부품 상세는 작은 그림끼리 한 칸에
  - 사진은 한쪽에 모음
- **크기**: 같은 시트의 모듈 그림은 같은 비율로 줄이거나 키움. 그래서 1000 폭 모듈과 500 폭 모듈이 반 크기로 보임. 다 안 들어가면 그림을 더 작게 줄이지 않고 '다음 시트로 나누기'를 제안함.
- **위치**:
  - 지금 쌓아 두는 방식(24px 어긋나게)을 이 배치로 바꿈. `addImagesFromFiles` 가 모두 올라간 뒤 한 번에 배치.
  - 실행 취소 한 번이면 배치 전으로 돌아감(`recordUndo`).
- **기록**: 자동 배치 뒤 사람이 옮긴 그림은 옮긴 거리를 함께 남김. 처음엔 통계로만 쓰고, 다음 판에서 배치 규칙을 고치는 근거로 씀.

**견본 대조**: 이 식으로 계산한 결과입니다(모듈 구성은 자재표를 보고 짐작해 넣음).
- 11번 몰딩 여닫이(피닉스바): 7줄 중 6줄 같음. SR 위 110 의 수량만 다름(계산 2, 견본 3).
- 12번 로라 몰딩 여닫이: 5줄 중 5줄 같음.
- 대조·검사 스크립트: 세션 스크래치 `scripts/bom_calc.py`(계산), `bom_fit.py`(차이 세기), `bom_rules.py`(맞음·여유·틀림 세기). 정식 코드로 옮길 때 테스트로 바꿉니다.

**넣는 법**:
- 계산 결과를 미리보기로 보여 주고, 사람이 '넣기'를 누르면 머리글([SR] 등) 글자 객체의 아랫줄에 들어감.
- 이미 사람이 친 줄이 있으면 지우지 않음. '바꿀까요?'로 물음.
- 자동으로 넣은 줄은 저장 전까지 색으로 구분함.

**저장**:
- 시트에 `calc` 를 둠: 입력값 + 넣은 글자(auto_text) + 계산 규칙 판.
- 나중에 사람이 그 줄을 고치면, 저장할 때 '계산 → 최종' 차이가 남음.
- 이 차이 목록이 도면팀과 계산 규칙을 맞추는 근거가 됨. 예: "옆 SR 을 사람이 매번 +10 함".
- 검증은 `wizard.py:553`(시트)에 더함. 크기 상한을 둠.

**상수 보관**:
- 계열별 상수는 코드에 박지 않음. 관리자가 고칠 수 있는 설정으로 둠.
- 지금 프리셋 설정이 SystemSetting + 판 번호 잠금으로 저장되는 방식을 따름(`PRESETS_ENDPOINT` `wizard.js:3734`).

### 3.4 모듈 구성 미리 채우기 (③ 앞당기기, 선택)
- **가: 파일 이름 규칙** — 스케치업에서 저장할 때 `1000_한통_서랍3_옷봉1.png` 처럼 저장하면, 올릴 때 이름을 읽어 모듈 목록을 채움.
  - 붙여넣기로 올린 그림은 이름이 `paste-<시각>.png` 로 바뀌어서 이 방법을 못 씀(`uploadAsset` `wizard.js:2858`).
- **나: 치수 글자 읽기** — 모듈 그림 위쪽의 폭 치수 글자를 한국어 OCR(RapidOCR, 실험에서 자재표 크기 줄 99.5%)로 읽음. 무거워서 4단계로 미룸.

### 3.5 사람이 고친 것을 다시 배우기 (④)
- **그림 이름표**:
  - 사람이 바꾼 것은 `src: user`, 무게 1.
  - 손대지 않고 전달한 AI 이름표는 `src: confirmed`, 무게 0.5.
  - 이 기록을 모아 분류기 머리를 다시 가르침.
  - `tools/drawing_ai/retrain_head.py`(새 파일)는 운영 DB 읽기 전용 + R2 GetObject 만 씀.
- **판을 바꾸는 조건**:
  - 고정 시험 묶음(사람이 확인한 그림 중 주문 단위로 떼어 둔 20%)에서 전체·제품별 정확도가 지금 판보다 낮아지지 않아야 함.
  - 주방은 1%p 이상 올라야 함.
  - 처음엔 손으로 한 달에 한 번 돌림. 고친 기록이 100건 넘을 때만 돌리고, 운영 읽기는 그때마다 허락받음.
- **헷갈림 표**: 예를 들어 "입체·도어 → 입체·내부 n건"처럼 함께 보여 줌. 다음에 무엇을 고칠지 정하는 근거가 됨.
- **계산 규칙**: AI 학습이 아님. §3.3 의 '계산 → 최종' 차이 목록을 달마다 도면팀과 보고 상수·식을 고침.

### 3.6 2단계 상세 — 자재표 계산 칸(그림자 판) (2026-10-23 구현)
- **화면**: 앱바 [자재표 계산] 단추를 누르면 오른쪽에 칸이 열린다(340px, 좁은 화면은 그림 위에 겹쳐 열림). 시트마다 입력을 따로 둔다. 저장 권한이 없으면 보기만 한다.
  - 기본: 제품 계열(몰딩 여닫이·무몰딩 여닫이·슬라이딩·냉장고장·그 밖), 손잡이(피닉스바·그 밖), 전체 폭·깊이·천장 높이(제품 규격 `W×D×H` 에서 미리 채움), 무몰딩 문 높이 방식, 서랍 칸 높이, 문 높이 직접, 드러난 옆면(EP), 옆벽 SR 좌·우.
  - 모듈: 폭·문 짝(0~2)·서랍 단수(0~4)·옷봉 수(0~2). 모듈 합과 남는 폭(옆벽 SR 로 채울 폭)을 보여 준다.
  - 계산 결과: 줄마다 어떻게 계산했는지 함께 보여 준다(예: '(1000 − 34) ÷ 2 내림 · 높이: 표준 문 중 …').
  - 시트 자재표와 맞춰 보기: 시트 글자 상자에서 [SR]·[DOOR] 같은 머리글 아래 줄을 읽어 줄마다 같음·여유(+n)·짧음·수량 다름·시트에 없음·시트에만 있음으로 표시한다. 머리글 없이 친 크기 줄은 세어서 '머리글과 한 상자에 써 달라'고 알린다.
- **그림자 판에서는 넣기·복사 단추를 두지 않는다**: 사람이 따로 친 자재표가 계산과 섞이지 않아야 맞춰 본 기록이 규칙을 검증하는 자료가 된다. 도면팀 규칙을 받으면 '넣기'를 열고 그때부터 `calc.mode = "insert"` 로 남긴다.
- **저장(시트 `calc`)**: `{in: 입력값, out: 마지막 계산 글자, rules: 규칙 판, mode: "shadow"}`.
  - 입력을 처음 바꿀 때 생긴다. 칸을 열어 보기만 해서는 시트가 바뀌지 않는다.
  - 서버 검증 `_validate_calc`: 닫힌 칸·선택값·숫자 범위, 모듈 24개, 계산 글자 2,000자, 전체 4KB. 브라우저는 저장 직전 같은 꼴로 정리한다(넘치면 계산 글자를 버림 — 입력값으로 다시 만들 수 있음).
  - 되돌리기(Ctrl+Z)는 그림 편집만 되돌리고 계산 칸 입력은 그대로 둔다.
- **규칙 숫자**: SystemSetting `drawing_wizard_bom_rules`, GET/POST `/api/orders/drawing-wizard/bom-rules`.
  - 고치기는 도면팀·관리자(`DRAWING_TEAM` 정책, 프리셋과 같음). version 잠금(누락 428·충돌 409), 감사 기록에 바뀐 칸의 전·후 값.
  - 판 이름: 저장이 없으면 `d1`(코드 기본값 1판), 저장하면 `s<번호>`. 칸 맨 아래 '계산 규칙 숫자'에서 고치고 '기본값으로' 되돌린다.
  - 저장된 값 중 형식이 틀린 칸은 기본값으로 읽는다(마법사가 깨지지 않게).
- **알게 된 것**: 프리셋 메뉴로 [DOOR] 를 넣으면 머리글이 선택된 채 열려 타자가 머리글을 덮는다(원래 동작). 새 시트에 미리 깔린 자리표를 누르면 아랫줄에서 쓰기 시작하므로 머리글이 남는다. 맞춰 보기는 자리표 방식을 전제로 하고, 머리글이 사라진 줄은 세어서 알린다.
- **사용자 결정(2026-10-23)**: 규칙 고치기는 도면팀·관리자 그대로(관리자만으로 좁히지 않음). 바꾼 기록은 관리자 감사 화면에 '도면 마법사 자재표 계산 규칙 변경'으로 남는다.
- **남은 것**: '넣기'(규칙 확인 뒤), 주방·냉장고장 문 높이·옆벽 SR·보조목 규칙(도면팀), 맞춰 본 기록 모아 보기(3단계 스크립트와 함께).

## 4. 단계 (각 단계 끝에 도면팀 실사용 확인)

| 단계 | 내용 | 코어 변경 |
|---|---|---|
| 1 | 그림 종류 자동 분류 + 이름표 칩(눌러서 고침) + 자동 배치 + 고친 기록 저장 | `part` 필드 검증(API) |
| 2 | 자재표 계산 칸. 도면팀 규칙을 받기 전에는 '그림자 판'으로 결과를 옆에 보여 주기만 하고 넣지 않음. 규칙을 받으면 '넣기' 열기 | `calc` 필드 검증·상수 설정(API·SystemSetting) |
| 3 | 다시 가르치기 스크립트 + 판 바꾸기 문턱 + 헷갈림 표 | 운영 읽기 스크립트(도구) |
| 4 | 모듈 구성 미리 채우기(파일 이름 규칙, 그다음 치수 글자 읽기) | 없음(브라우저) |

## 5. 위험과 막는 법
- **자재표 숫자가 틀리면 재단 손실**: 계산은 언제나 '제안 → 사람 확인 → 넣기'로만 들어감. 그림자 판에서 도면팀 계산기 값과 맞춰 본 뒤에 연다. 자동으로 넣은 줄은 기록이 남음.
- **모델 24MB 첫 받기**: 마법사를 처음 열 때만 받음. 받는 동안에는 지금처럼 손으로 하게 하고, 화면을 막지 않음.
- **잘못된 '확인' 정답**: 전달된 AI 이름표 중 사람이 못 보고 넘긴 실수가 섞일 수 있음. 그래서 무게를 0.5로 두고, 판을 바꾸기 전에 고정 시험 묶음으로 막음.
- **JSONB 크기**: `part` 는 그림당 약 80바이트, `calc` 는 시트당 수 KB 미만.
- **코드 규칙**: 인라인 스타일 금지(`static/css/foundation/erp-pro.css`). wizard.js 는 5,769줄이라 분류·배치·계산은 새 파일로 나눔(`static/js/drawing/part_ai.js`, `bom_calc.js` 등, 새 JS 300줄 래칫 지킴). 성능 가드(`scripts/ops/pre_push_smoke.ps1`)를 통과해야 함.

## 6. 도면팀에게 받을 것 (계산 규칙)
§3.3 표의 식은 지난 도면에서 '가장 많이 쓴 값'을 찾은 것입니다. 진짜 규칙인지는 도면팀 확인이 필요합니다.
1. 확인만 받으면 되는 것:
   - 문 틈: 피닉스바면 34·30, 그 밖이면 8·4
   - 옷봉: 모듈 − 35
   - 마이다 폭: 모듈 − 5
   - 피닉스바 개수: 문 ÷ 2 올림
   - SR 위: (위 틈 − 30)을 10 단위로 올림, 무몰딩은 60
   - 측판 EP: 깊이 + 10
   - 문 높이: 몰딩 100 단위 표준, 무몰딩 천장 − 45
2. 새로 받아야 하는 것:
   - 옆벽 SR 과 '좌벽 스라 맞춤' 나누는 법
   - SR 수량
   - 보조목 수
   - 서랍 칸 높이와 단수별 마이다 높이(외부 서랍·속서랍)
   - 주방·냉장고장 문 높이(상부·하부·플랩)
   - 원도어·플랩·사선 문 같은 예외
   - EP 41 띠 수량
3. 여유를 주는 기준: 언제 몇 mm 를 더 주는지(예: 천장이 고르지 않을 때 SR). 계산기에 '여유 더하기' 칸을 둘지 정함.
4. 위 규칙이 맞는지 볼 지난 주문 5~10건. 입력값(모듈 구성)과 최종 자재표를 같이 받음.

## 7. 정할 것 (사용자)
1. 1단계(자동 분류·배치)부터 할지, 2단계 계산 칸 그림자 판을 함께 할지.
2. 파일 이름 규칙(§3.4 가)을 도면팀에 부탁할지.
3. 다시 가르치기를 손으로 돌릴지, 매달 자동으로 돌릴지. 자동이면 운영 읽기를 계속 허락해 두어야 함.
